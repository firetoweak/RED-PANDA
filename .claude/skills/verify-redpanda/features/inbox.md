# Bot 待处理事项

没有独立的待处理导航或汇总页。有事项时，在所属 Bot 的侧栏头像旁显示提醒；点击 Bot 进入对话处理。命令授权与控制提案由 `PendingActions.tsx` 显示，交流超限、暂停未处理消息和无人查看例行任务询问由 `SessionAttention.tsx` 显示。`GET /api/inbox` 仍是名册提醒与会话通知的数据源，不是页面路由。

## Sub-features

- `empty`：没有事项时不额外显示通知区；侧栏不出现 `待处理` 按钮。
- `authorization`：会话待处理条显示工具名与参数摘要，`查看 <工具名> 的参数` 展开完整 JSON，`允许` / `拒绝` 走原命令授权接口。
- `control`：会话待处理条显示摘要和风险，`取消` / `确认` 走原控制接口。
- `limit`：在所属会话显示交流上限报告；人在这个会话再发消息后消失。
- `paused`：所属会话提示暂停且有未处理消息，`继续` 沿用会话重试接口。
- `absence`：在所属会话询问例行任务是否 `继续` / `停下`；超时暂停后显示 `恢复`。决定沿用 `POST /api/inbox/absence`，只恢复这次被暂停的例行任务。

## How to get to it (user POV)

- 找到头像旁带提醒的 Bot，点击它进入 `/sessions/<id>`，在输入框上方处理。没有事项的 Bot 不因其他 Bot 的事项显示提醒。

## Driving it with the browser

- **空状态与归属**：无事项时查看侧栏；有事项后切换两个 Bot。
  - (a) 对照 `GET /api/inbox` 的 `session_id`。
  - (b) 侧栏无 `工作台` / `待处理` 按钮；仅对应 Bot 的状态点提示 `需要你处理`；当前会话只显示自己的事项。
  - (c) 切换不改变事项，不重新创建 Bot。
  - (d) 连接断开时，已有通知中的决定按钮禁用。
- **命令授权**：关闭自动放行，让 Bot 写个人目录中的 `review.txt`。
  - (a) `GET /api/inbox` 含授权项，批准前文件不存在。
  - (b) 对应 Bot 的头像旁有提醒；进入对话展开参数并允许后，待处理条与侧栏提醒消失。
  - (c) 同一授权只在会话待处理条出现一次；不另开汇总页。
  - (d) 拒绝不写文件；重复授权仍由后端返回冲突。完整判据见 [工具授权](tool-authorization.md)。
- **其他通知**：按原业务条件准备暂停消息、交流超限或无人查看询问，再打开对应 Bot。
  - (a) `GET /api/inbox` 中的报告、暂停状态或询问与会话内容一致。
  - (b) 暂停消息可以继续；例行任务询问可以继续或停下，已暂停的可以恢复。
  - (c) 这些通知不重复展示授权与控制提案；决定只作用于该 Bot。
  - (d) 请求失败时显示失败信息，事项保留以便重试。

## Gotchas

- 还没有用户消息的 Bot，只要已有事项，也应获得名册提醒。
- 旧版 `/inbox` 页面与数字汇总徽标已移除，历史汇总页验证不代表当前入口通过。
- 历史（旧版入口）：2026-10-20 `origin/main@32860f6`，Windows Chrome/ConPTY、隔离 home，真实 `write_file` 授权项、数字徽标、参数展开与批准后空收件箱通过；已暂停 Ada 收到私信后出现暂停项，点继续后处理。交流上限与无人查看门槛未覆盖。
- 2026-10-20 入口精简增量：隔离 Web、真实 DeepSeek 模型，验证侧栏无独立导航、品牌返回首页、关闭自动放行后 `write_file` 进入待授权、Bot 提醒与会话条同步、展开参数并允许后文件写入与提醒清除。无人查看门槛、通信超限、暂停消息继续与窄屏未 live 重验；例行任务决定的会话归属、断线禁用和原接口调用由组件回归覆盖。证据保存在本地 `.tools/frontend-review/evidence/sidebar/`。
