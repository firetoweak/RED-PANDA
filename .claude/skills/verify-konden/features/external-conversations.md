# 外部会话

原生聊天经 MCP 登记独立身份，与长期 Bot 持续双向交流，并在 Web 中可见；当前入口要求客户端提供有效的 Codex 原生聊天标识，自动接续由人按会话启用。当前优先适配并验证同机 Codex，其他客户端暂未纳入接入验证。消息不要求仓库、版本或验证结论。来源：外部会话服务、MCP 入口与 `web/src/features/external/`；任务场景见用户指南 `docs/外部协作.md`。

## Sub-features

- `register`：`get_context` 从原生标识自动登记当前聊天，登记后即在侧栏出现，允许尚无消息；新聊天自动分开，原聊天和重连保持同一身份，收发工具不接收 identity。默认显示本机 Codex 标题，原生改名后刷新列表和会话页应更新；显式 name 别名优先，无法取得标题时保留简短标识。长标题不撑开名册，悬停可查看全名。
- `duplex`：外部用 `send_message` 向同事发送正文，Bot 用 `send_external_message` 按外部 identity 发言；可引用此前消息，也可独立继续话题。Bot 用 `list_external_sessions` 查询已登记对象。
- `inbox`：`read_messages` 按外部会话和游标读取 Bot 与用户的三方共享发言，标明 Bot、来源、接收方和是否请求响应；有界等待、分页与重启后续读不改变消息归属。
- `web`：侧栏“外部会话”支持搜索与过滤；进入后选择一位 Bot，固定由该 Codex 聊天、Bot 和用户参与。人的输入用 `@Codex`、`@Bot 名字` 点名，`@all` 或同时点名两位表示双方，不点名默认给 Bot；支持候选补全，底部实时显示接收方，引用预览不参与点名。三方来源、接收方与引用可见；不同 Bot 的记录和草稿分开，不提供全部 Bot 的混合输入视图。Bot 时间线的外部往来只显示方向、头像与名称小标签，点击进入对应 Bot 的三方对话查看正文；外部页面可进入相关 Bot 的会话。输入区复用群聊的紧凑布局与按内容展开方式，右侧提供当前 Bot 的模型选择和上下文用量，与私聊共用控件及状态来源；切换 Bot 后随之更新，模型选择确认前禁止发送。
- `delete`：单条外部会话的「⋯」及右键菜单提供「删除外部会话」。取消不写入；确认后从侧栏移除、当前会话回首页，并停止该会话收发、等候读取和自动接续；其他会话及共用配置不受影响。Bot 已提交往来保留，原生聊天主动重新接入后按原身份恢复联系，自动接续需重新启用。
- `access`：「Codex 接入」支持配置命名、重命名，并提供可分别复制的 URL、Authorization 请求头值，完整步骤在用户指南；TOML 放在「高级：手动配置 TOML」。「返回连接列表」或关闭设置后隐藏凭据，列表「查看配置」可再次读取；撤销使该配置下全部会话停止收发。已有会话、往返与引用继续可读，页面不声称客户端持续在线。
- `codex-continuation`：人在外部会话的「Codex 自动接续」确认自动定位的聊天与本机程序；保存后新消息发送固定提醒，失败或未确认时可重试，停用与撤销停止后续提醒。入队不代表已经处理。

## How to get to it (user POV)

从“设置 → Codex 接入 → 新建连接配置”进入，确认此时尚未创建；填写名称，再点击「确认生成」。取消不产生配置。核对 URL 与 Authorization 的独立复制，确认 TOML 默认收起。「返回连接列表」清空本次展示的凭据；再次「查看配置」应读取同一份配置。按用户指南在 Codex 应用中添加服务器；无法驱动原生设置时，明确记录该步骤未验证，不以 CLI 或协议客户端代替。高级路径可将 TOML 合并到隔离 `CODEX_HOME` 下的 `config.toml`，用本机 Codex CLI 检查配置确实可读，再通过 MCP 完成身份登记。可从连接列表重新查看凭据，不将凭据放入截图或证据。Codex 聊天自动登记后，从侧栏“外部会话”点名称进入；需要 Bot 回复时，先创建 Bot 并配置模型，无需代码项目。

## Driving it with the browser

先按主技能启动独立 home、端口并通过 Doctor。配置、登记与历史查看不需要模型；真实 Bot 收发和主动联系需要 live_model_ready。

生成配置必须由 Web 页面操作。外部身份登记和发言走 MCP 真实入口，HTTP GET 只核对界面结果。

1. 登记两个原生聊天：使用不同的原生聊天标识，自动得到不同会话；原聊天重连不填写身份。两项应在发送消息前实时出现在侧栏，点开显示已接入的空状态；刷新不重复登记。
2. 无版本普通往返：从一个身份向 Bot 讨论需求，Bot 显式回传，再独立补充一条不带回复引用的消息。外部按同一游标续读得到两条，Web 内容与方向一致。
3. 分流与主动联系：第二个身份联系同一 Bot，回复不能出现在第一个身份的收件箱。人在 Bot 私聊中让它查询外部会话并主动联系第一个身份，即使没有新外部请求也能送达。多 Bot 收件与跨对象引用边界在低成本契约层验证。
4. 三方输入与阅读：从 Bot 时间线的外部名称进入对应身份及 Bot 的三方视图。用输入框的 `@` 或底部「点名接收方」补全 Bot、Codex 或 `@all`，确认候选的 Enter 只补全，不发送；不点名默认给 Bot，删除点名后底部提示随之更新。发送后核对 `GET /api/external-sessions/<identity>` 中的来源、接收方、引用与编号；只选 Bot 时不提醒 Codex，只选 Codex 时不启动 Bot。Agent 引用人的消息默认回给人，明确交给另一方时才请求其处理。切换 Bot 后记录、草稿分开；失败保留正文、引用与原编号供重试。桌面明暗主题与 390px 名册、消息、输入框及引用均可读，没有横向溢出；新消息不抢走正在补读的位置。重复提交、交付中断后的幂等恢复及跨 Bot 引用在契约层验证，真实 Bot 回复需要模型。
5. 停止并重启记录的 Host，使用原生聊天与原游标续读：历史、消息号、引用和位置保持，侧栏不新增重复项。
6. Web 设置撤销配置：正在等待的读取应结束，新访问为 401；外部页面实时显示接入已撤销，原消息仍在。保存同一状态的截图、快照与只读 API body。
7. 同机 Codex 接续：在外部会话页展开「Codex 自动接续」，确认自动识别的聊天并保存；界面没有聊天 ID 输入，验证无效程序路径的错误提示，再让 Bot 发消息。核对消息先可读取、状态随后显示入队，并在原 Codex 聊天确认新一轮启动。保持两个外部身份的绑定独立。模拟命令失败时从页面「重试提醒」，核对原消息不重复；停用后新消息继续可读但不再提醒。截图与只读会话 body 留存提醒状态，原生聊天启动记录单独保留。
8. 单条清理：从侧栏「⋯」和右键打开删除确认，核对名称与影响范围；取消后会话仍在。确认删除当前会话后返回首页，列表移除该项，另一会话和接入配置保留；刷新后仍不出现，已撤销的条目也可删除。通过 MCP 确认旧会话不能收发，再从原生聊天主动重新接入，按原身份重新出现。Bot 已有往来不应被删除；等候读取及在途提醒的边界由契约用例保护。

## Gotchas

原生标识随 MCP 调用提供；缺失或无效时拒绝登记和收发，不以模型输入覆盖目标。共用凭据下的身份用于分流，不构成权限隔离。普通 assistant 结尾给人看，外部消息需要显式发送；送达不表示对方已处理。Codex 自动接续由人按会话启用，原生聊天自动定位，当前只支持同机已加载聊天；不承诺打开应用或恢复未加载聊天。
