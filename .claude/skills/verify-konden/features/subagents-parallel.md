# 并行子 Agent：共享工作区与独立执行

父使用 delegate 在同一决策中派出独立任务；子各有上下文和执行过程，共享父工作区。文件分工、目录、分支与顺序由父决定，系统不建立副本或合并成果。

## Sub-features

- 并行派出与逐个自然回复。
- 共享文件和互相可见的未提交内容。
- 选择性回收、父停止及后台命令收口。
- 独立过程观察与执行恢复。

## How to get to it (user POV)

按 verify-konden 启动独立实例，Doctor 通过且 live_model_ready=true。从父对话自然要求把两个互不依赖的调查或文件任务分别交给子助手；不要求挂代码项目。父应明确各自修改范围。

## Driving it with the browser

- 并行派出：Journal 中同一 Step 有两个 delegate，子执行时间重叠；各自普通回复到父，过程不自动复制进父上下文。
- 共享文件：让两个子修改不同文件，父目录立即可见，不出现专用子工作树、比较合入工具或自动 Git 提交。父未提交材料也能由子读取。不要用同时修改同一文件验证系统不存在的冲突解决保证。
- 选择性回收：父结束一个仍有后台命令的子，核对该命令停止，另一个继续执行；共享成果保留，重复回收不重新执行。
- 父停止：页面停止结束未关闭协作并收口其命令，随后普通新输入仍可处理。
- 恢复：重启不重跑已开始的命令，确定结果按原身份接纳；未知结果如实报告，已回收的子不被旧完成通知唤醒。
- 状态：后台命令仍在执行时，list_subagents 报告 running；模型暂时空闲不代表任务完成。打开或关闭观察页不改变执行。

## Gotchas

- 2026-10-26 按共享工作区设计更新，未重跑多子并行页面流程。单子共享文件、命令授权、父响应与回收见 subagents；进程内继续保护并行独立回复，真实进程保护共享执行和资源回收。
- 不承诺同一文件的并发写安全；验证报告必须区分父的协作安排与系统保证。
