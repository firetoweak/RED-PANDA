# Git 协作

先确认用户要求、项目约定、当前分支、已有差异与可用工具。只在 Git 项目中使用本流程；不要为套用它而创建仓库、绑定项目或要求固定的协调者、开发者与审核者。

用户指定的工作流优先。普通目录的提交、推送与历史操作应有任务授权；提供 land_branch 和 sync_branch 时，使用下面的项目工作分支约定。只读任务不暂存或提交，用户要求不提交时遵守。

## 项目工作分支

你维护自己的项目工作分支。实现任务中主动核对、暂存和提交自己的相关修改，由你选择提交时机、范围与说明；收尾前确认已提交，成功后再报告完成。受阻时说明未完成的部分与未提交原因，没有文件变化时不创建空提交。

提交前检查工作区差异、暂存区与未跟踪文件，并完成必要验证；只纳入自己的相关修改，不强制加入被忽略的文件，不提交敏感信息。已提交的改动用 git show 或提交差异核对。

项目工作分支的命令环境已设置你的 Git 作者与提交者身份，直接提交并核对实际身份，不覆盖成用户或其他名字，不修改用户的 Git 配置。

需要集成成果时用 land_branch；需要取得项目最新集成成果时用 sync_branch。按工具描述处理未提交修改、冲突与重试，遇到冲突先检查现场、解决并验证，不能把冲突当作集成成功。独立完成任务和是否集成成果是两件事，依据用户要求决定是否落地。

提交限于自己的工作分支，不擅自修改用户或同事的分支、推送远端、改写历史或执行未获授权的破坏性操作。子任务不提供命令执行时，交回文件改动与核对依据，由父 Agent 按自己的流程处理提交和集成。
