# 会话文件变更审阅

输入框上方显示当前会话仍保留的净变更；点击摘要打开右侧 `会话变更`，选择文件查看旧、新行号和文本差异。来源：`web/src/features/conversation/FileChangesPanel.tsx`、`Conversation.tsx`、`web/src/api/fileChanges.ts`、`redpandaApi.ts`、`redpanda/assistant/conversations.py`、`redpanda/sandbox/files/review.py`、`redpanda/channels/web/app.py`。

## Sub-features

- `summary`：`N 个文件已更改`、新增/删除行数；只加总能够精确统计的文件，有不能精确统计的文件时显示 `部分统计`。
- `file-list`：文件的相对路径、`新增`/`删除`/`修改` 状态、文件行数或 `部分` 标记。
- `line-diff`：选择文件后展示旧、新行号、增删正文和上下文；旧行号无法确定时显示 `?`，会话外与混合来源分别标记。
- `pagination`：正文按页查询，`上一页`/`下一页` 切换，分页不改变完整差异的统计。
- `refresh`：文件操作落地后自动刷新、重新连接后刷新；`刷新文件变更` 与抽屉内 `刷新` 支持手动更新。
- `net-scope`：重复编辑不累加，恢复原值后移出列表；分支包含继承历史的原操作范围；其他会话的独立修改不计入本会话。

## How to get to it (user POV)

- 打开已有会话，在输入框上方找到 `N 个文件已更改`，点击后进入 `会话变更`，再点文件路径。
- 无变更时仍有 `0 个文件已更改` 入口，抽屉显示 `当前没有保留的会话变更。`。
- 先按 `../SKILL.md` 检查隔离实例。通过编码回合准备变更时，`live_model_ready` 与 `sandbox.ready` 都必须为 true；任一不满足就记录未能准备真实成果，不用直接 POST 或伪造会话冒充页面证明。

## Driving it with the browser

前置：隔离工作区中没有 `review.txt`、`other.txt`。使用真实会话 A；涉及工具写入时明确授权。证据保存到 `$EVIDENCE_DIR/session-file-changes/`，不同状态用独立子目录保留截图、快照、只读响应和文件副本，不能互相覆盖。

- **摘要、列表与正文**：在 `消息` 中发送：`请用 write_file 新建 review.txt，UTF-8 内容为 first 和 second 两行，每行末尾都有换行；不要修改其他文件。完成后停止。` 等文件操作完成。
  - (a) 磁盘 `review.txt` 为 `first\nsecond\n`；`GET /api/sessions/<A>/changes` 仅一个文件，`status=added`、`added=2`、`removed=0`、`partial=false`。
  - (b) 页面无需手动刷新显示 `1 个文件已更改`、`+2`；点击摘要和 `review.txt`，出现 `会话变更`、`新增`、新行号 1/2 及对应正文。只读 `GET .../changes?path=review.txt&revision=<摘要中该文件的 revision>&offset=0` 与页面一致。
  - (c) 读列表、点文件和翻页不改磁盘文件，也不新增模型决策或工具调用。
  - (d) 若显示 `文件变更暂不可用` 或差异读取警告，先 Doctor；确认实例正常后按错误提示刷新，不将警告当成零变更。
- **会话隔离与净效果**：同工作区打开会话 B，让模型只创建 `other.txt`；回到 A。然后让 A 删除自己创建的 `review.txt`。
  - (a) A 不统计 `other.txt`，B 不把 A 的独立修改算作自身成果；A 删除后 `files=[]`，`added=removed=0`，`review.txt` 不存在。
  - (b) A 的摘要最终为零，抽屉显示空状态。
  - (c) `other.txt` 保持 B 的实际内容。模型工具 `get_changes` 默认也采用会话范围，可交叉核对来源；显式工作区范围的查询不能代替此判据，工具调用也不能代替页面操作证据。
  - (d) 不以“最后一次工具改过文件”证明净变更；同一会话反复修改、最终恢复原值也应归零。
- **分页与旧结果失效**：让 A 创建 `review.txt`，包含编号 1 至 230，每行一个编号并带换行。点文件后用 `下一页`、`上一页`。
  - (a) 摘要始终新增 230 行；各页读取相同 `revision`，按 `next_offset` 续读覆盖全部正文。当前每页最多 200 个展示行，包含 hunk 标题与上下文，不能将页大小当作新增行数。
  - (b) 页面页码与正文变化，最后一页 `下一页` 禁用。
  - (c) 分页与摘要统计分离；文件更新后使用新 revision 并回到第一页。
  - (d) 保存旧 revision，让 A 再修改文件，随后对旧 revision 发只读差异请求 → 409；页面提示 `文件变化已更新或暂时无法读取。`，刷新列表后可继续。不存在或已无当前会话效果的文件 → 404；`path=../outside.txt` → 422，不读工作区外文件。
- **外部修改与部分统计**：对 A 创建的文件，通过编辑器修改一行并保留其他助手内容，再点 `刷新文件变更`。
  - (a) 摘要含 `partial=true`；相关文件 `origin=mixed`、`added=null`、`removed=null`，不把会话外内容算作精确成果。
  - (b) 页面出现 `部分统计`、文件的 `部分` 标记和来源说明；无法判断的来源不标成助手。
  - (c) 查询不撤销编辑器修改，不改文件。
  - (d) 二进制、非完整 UTF-8 或原文证据不完整同样不得提供伪精确行数；不把 `null` 显示成文件新增/删除零行。
- **自动同步**：按 [realtime-events.md](./realtime-events.md) 的变更同步步骤，用两个标签页观察同一会话；保留工具完成后、无需手动刷新的摘要与 diff 证据。分支继承范围按 [edit-and-branch.md](./edit-and-branch.md) 的真实入口创建后核对，不能把继承成果错误地清零。

## Gotchas

- 此面板与模型工具 `get_changes` 默认均按当前会话查询（含分支继承）；工具显式 `scope=workspace` 才查询工作区所有会话的助手操作。工具允许已触碰文件显示 `external` 或 `unchanged` 以核对被覆盖、已恢复的内容，面板列表只保留仍有当前会话成果的文件。
- 净变更来自当前文件与实际操作证据，不等同于 Git HEAD 差异，也不累加工具调用次数。
- 二进制、混合来源与原文不完整的文件仍可在列表中出现；摘要只加总其他可精确统计文件的行数，并标 `部分统计`。
- 外部编辑没有自动监听，需手动刷新；文件操作失败也可能留下实际文件效果，仍需检查。
- 本入口只读，不提供接受、撤销或回退按钮；回退仍走 [file-rewind.md](./file-rewind.md)。
