# 上下文投影

投影、保护窗、Artifact 与预算。窗口切换见 [Compact](Compact.md)；SYS／工具呈现见[前缀稳定性](上下文窗口与前缀稳定性.md)；图片见[多模态附件](多模态附件.md)。

## Decision Context

> Decision Context 是 Step 开始时对"模型所见世界"的冻结快照。

它同时冻结：观察位置以内且可见的 Event、稳定 System Prompt 与已提交的能力目录事实、Tool / Skill schemas、Model Context 投影结果。

稳定 Prompt 与静态 schemas 在决策入口的首个异步等待前复制；目录消息和动态 schemas 从观察位置以内已提交的 catalog / load 事实投影。Journal 即使在读取期间继续追加，也按该位置截断。

由此得到两条硬边界：Toolset 已在进程内加载但成功 Outcome 尚未进入冻结 Decision State 时，对该 Step 不可见；Registry 的新 revision 尚未成为本 Session 的 catalog update 时，不能直接改写当前模型视图。

Step 执行期间到达的新 Event 或已提交的目录变化只影响后续 Step，不回写或刷新当前 Decision Context。

每条用户消息的接纳时间从对应 Event 投影为紧邻其前的系统来源事实；用户原文保持原样。这个时间表示 Journal 接纳消息的时刻，不冒充用户设备上的发送时间。

模型返回后，Assistant 保存一份 Replay Manifest Artifact，记录冻结依据、实际请求、模型、Projector 版本、原始响应和 usage。Runtime 只接收决策与其引用，不理解 Manifest 内容，也不能依据它改写模型决策。

```text
冻结可见 Event
  → 协议消息
  → 超大 tool Outcome 外置 Artifact
  → 保护窗：上一句 UserMessage 之后必留原文
  → 窗外、批次完整、已消费、成功 → Level 1 stub
  → InputBudget；超预算 fail fast
```

## 保护窗

上一句真实 `UserMessage` 之后的 Step / Outcome 不做年龄脱水，再从尾部按预算补足一段。

不脱水的判据是机械的：普通大小的失败结果、未消费结果和不完整批次都保留原文。工具失败不因 Runtime 执行闭环完成而被当成成功脱水——"这个失败还有没有用"是模型的判断，不是投影器的。

任何 Outcome 仍受强制体积外置限制，那是持久化边界，不是脱水策略。

## Artifact

Artifact 按 Session 隔离。模型侧工具结果统一为 `{ok, code, data, error, hint}`，不暴露 Runtime 的执行外壳；Journal 仍保存完整 Outcome。

单条结果超过阈值则外置：完整正文仍是同一套工具结果协议，Journal 只收小 stub，模型用 `read_artifact` 分页读取。结果刚产生时保留少量 preview；移出保护窗且整批结果成功、已消费后复用同一 Artifact 并清空 preview。

Session 目录下还有第二类外置物——工具带回的图片字节。它同样因 Journal 体积上限而必须外置，但按内容哈希寻址、整件取回、不可分页，与文本 Artifact 共用目录而不共用 API，见[多模态附件](多模态附件.md)。

## 预算

投影结果按配置的模型上下文上限与输入预算比例计量。调度器在决策前检查 compact 软阈值；容量不足时暂停下一次模型调用，继续接纳输入，等待后台压缩与安全切换。投影器自身对超预算抛错，不静默截断。

接续上下文与本会话消息一起计入预算。图片不做文本分词，按件计入并另有一份图片预算。

## 不做

- 把投影缓存当成第二事实源
- Runtime 内核做脱水
- 在模型调用前读取 Journal 尾部来"刷新"当前 Step
- 适配器自行解冻 Runtime 事实值，或为未知类型添加序列化兜底
