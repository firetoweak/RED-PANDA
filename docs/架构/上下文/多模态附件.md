# 多模态附件

图片与用户上传的普通文件都保存在 Session 中，字节不进 Journal，事实只持有引用。图片按引用还原为模型内容块；普通文件向模型提供具名材料路径，由模型选择读取与解析方式。Runtime 不认识格式，也不判断附件的含义。

## 为什么必须外置

Journal 对所有事实值有一个百 KB 级的硬字节上限，构造事件时逐字节扣减预算。一张 1280×720 截图 base64 之后是兆级，**写不进 Journal，会在事件构造时直接抛错**。

所以外置不是体积优化，是唯一可行路径。这与超长文本结果被同一上限逼出 Artifact 外置是同一个成因。

## 两类外置物，API 语义相反

| | 文本 Artifact | 图片附件 |
|---|---|---|
| 成因 | 单条结果超过字符阈值 | 二进制天然不可进 Journal |
| 标识 | 每次外置新建 | 内容地址（sha256） |
| 读取 | 按字符 offset 分页 | 整件取回，不可分页 |
| 工具 | `read_artifact` | `read_image` |

两者都在 Session 目录下，事实引用的原件丢失都算持久化损坏。但文本可以连续降级，图片只有"在"与"不在"两态。**不得把附件并入 Artifact Store，也不得为二者预建统一 blob 抽象。**

投影期脱水造出的那批 Artifact 是第三回事：它是投影缓存，用随机 id，重放会重新生成，不进 Journal。附件与之无关。

## 图片存储

按内容哈希寻址：相同字节得到相同 id，只存一份。截图循环里页面未变即复用，崩溃重试产生相同字节也不会重复落盘。

写入是"暂存文件 + 原子替换"。内容寻址靠文件存在与否判重，若直接写规范路径，崩在写一半会留下截断对象并被永久当成有效。这是单个对象的标准原子写，不是多文件事务。

**不使用 sidecar 元数据文件**，mime 与尺寸跟随引用对象进入事实，磁盘上只有裸字节。硬链接去重、逐级目录 fsync 之类的耐久性工程不做——本项目一个用户，不为不存在的问题建工程。

附件缺失是持久化损坏，读取时原样暴露，不降级成"没图"。保留策略与垃圾回收本版不做；孤儿对象（字节已落盘而 Outcome 未提交）是垃圾，不是错误。

## 图片准入

模型图片协议只接受支持的栅格格式；其他格式可以作为普通文件上传，但不伪装成模型图片块。

理由是 provider 的图片协议只认有限几种格式。普通文件不走这条协议，不因缺少内置解析器而被拒绝；接受上传也不代表模型已经读懂内容。

落盘前完整解码栅格，声明 mime 与实际格式不符则拒绝。超过归一化上限的图做确定性重编码后再存，**磁盘上是归一化后的字节**，引用里同时记录原始事实与归一化事实。把输入压到有界，比为无界输入精确建模成本更低，也顺带消除了 provider 尺寸限制导致的请求失败。

## 用户文件原件、材料与工作副本

普通文件保留名称与独立身份。同名文件不互相覆盖。挂入成功不等于发送：只有进入用户消息事实的引用，才进入模型可读的材料视图。移除或未发送的挂入不能提前成为模型材料。分析文件默认挂本机路径，不为自包含再抄一份；拖入或粘贴的非图片才流式落入会话原件。

原件是会话证据；材料目录是供现有工具读取的派生视图；工作区是模型写入与修改文件的地方。模型依据用户目标自行选择文本读取、命令或已有专用能力；需要修改时，先显式复制到工作区，再编辑并验证工作副本。系统不自动导入、不做格式解析或摘要，也不替模型判断何时复制。

材料根只读地加入执行环境视图，不暴露整个产品数据根。只读是文件工具的访问契约，本机命令仍在日常进程环境执行，不宣称操作系统隔离。浏览器上传保存的是字节快照，不能借此写回用户机器上的来源文件。

会话恢复与分支继承原件，材料视图按已提交引用重新生成。压缩可以移出消息窗口，但不删除已发送材料；交接仍应保留附件身份和材料来源，摘要文字不代表已经读取文件。工作区回退不会改动会话原件。

## 引用与顺序约束

模型侧工具结果协议由 `{ok, code, data, error, hint}` 扩展出**可选第六键 `images`**，值为引用列表，同时 `data` 内对应的原始图片块替换为同一引用对象。

`images` 放在顶层而不是塞进 `data`，因为它是投影指令而非工具载荷：投影器要在不理解任何具体工具的前提下找到它，并且它必须在正文被外置成 Artifact 之后继续存活。

**抽图 → 引用替换 → 文本外置 → 构造 Outcome。** 顺序反了，外置逻辑会把带 base64 的结果当作普通长文本计入字符阈值，把兆级 base64 写进一个文本 Artifact：既没解决问题，又污染了文本抽屉。

另：对文本做密钥脱敏时**必须跳过二进制块**，字符串替换会破坏原始字节。

## 投影

图片块不能放进 `tool` 消息——Chat Completions 的 tool 消息只接受文本。因此图片跟在**完整工具响应组之后**，作为单独一条 `user` 消息注入，并在文本里标明"这是工具观察，不是用户指令"。tool 消息本身保持既有文本协议不变。

用户粘贴图片仍是一条普通用户消息。Channel 先把字节写入当前 Session 抽屉，正文带可见 token，稳定 id 写入事件已有的附件引用字段。投影器按 id 从抽屉嗅探 mime 与尺寸，还原为与工具图相同的内容块。消息因此始终非空；`yes` / `no` 授权只看纯文本，带着 token 的正文不会被当成确认。

分析文件不走这条图片协议。它们是文件系统对象：Channel 只登记身份（本机路径挂入，或把拖入字节流式落到会话原件），不按总大小拒绝，也不把整件读进服务进程。材料根是只读视图，同盘硬链接、跨盘再流式复制；模型用路径加分页读取，文件体积不是 `read_file` 的拒绝条件。路径消失按附件缺失处理，原样暴露。

## 数量与驱逐

上下文输入用量直接采用模型返回的 usage，不对图片引用或 base64 分词，也不再设置每张图片的 token 估算值。

工具图片有独立的数量边界，超出时从最旧的开始脱水为文字引用，并提示可用 `read_image` 回读。这是限制携带资源的机械规则，不代表新图使旧图语义失效；模型认为旧图仍需要时自行回读。

## 回读与请求边界

`read_image(id)` 只接受**本 Session 事实中出现过的** id，整件取回，不提供分页。规则与 `read_artifact` 同类：按本 Session 引用取回，不新开执行循环。

压缩 handoff 只保留 id 与来源，来源由持有引用的事件类型直接读出，不另存。摘要文字不等于看过原件，业务模型要再看走回读。

上层消息协议自始至终保持本地引用。Client 只在构造 provider 请求时读字节、转协议，**同一请求内相同 id 只编码一次**，不回写 Journal，不持久化 base64。同一张图留在可见窗口期间每轮都会重新编码上传，这是 token 之外的第二笔成本；内容寻址让"本轮与上轮是同一张图"退化为一次 id 比较，为后续复用上传留出空间。

## 不做

- **不改 Runtime payload / codec**：不加事件类型、不升版本、不碰空消息不变量，只把已有的附件引用入口接出去。
- **原件不自动进入 Workspace**：Workspace 是变更证据的对象，只由模型显式写入需要处理的副本与结果。
- **不做保留与 GC**：孤儿与历史对象暂时积累。
- **不设计音频模型协议**：音频可以作为普通文件提供，不自动转录或生成音频内容块。
- **不做 SubAgent 继承**：子 Session 是独立 identity，按本 Session 取回意味着看不到父 Session 的图。是否照文本 Artifact 的继承机制处理，待真实需要出现时单独决定。
- **不按分析文件总大小设产品上限**：图片协议与单次工具分页仍有界；普通文件的存在不受 20 MiB 一类整件门槛约束。
