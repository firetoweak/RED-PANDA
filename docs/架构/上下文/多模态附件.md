# 多模态附件

图片与普通文件属于 Session 材料，事实保存引用，不把大块字节写进 Journal。图片进入模型图片协议，普通文件提供具名路径，由模型按任务选择读取和解析方式；Runtime 不理解文件格式或内容。

## 原件与引用

事实必须有界，二进制图片和超长文本都要外置。但文本可以分页，图片须整件取回，因此不为两者建立统一 blob 接口。事实引用的原件缺失是持久化损坏，不能降级成没有图片或空内容。

图片按内容寻址，相同字节复用同一对象；完整写入后才对外可见，不能把崩溃留下的半件当成有效原件。投影缓存与原件不同，缓存丢失可重建，历史原件不自动回收。

## 图片准入与呈现

模型图片只接受已支持的栅格格式。输入须完整解码并核对声明格式，过大图片确定性归一化，引用保留来源与归一化说明；其他格式仍可作为普通文件提供，不伪装成模型图片。

先提取图片并替换引用，再处理文本外置，避免把二进制误放进文本原件。文本处理不能改写二进制字节。

工具图片在完整工具响应组之后呈现，明确标注工具观察来源，不能提升为用户新指令。用户粘贴图片是用户消息的一部分，不能因正文类似批准词就被误判为授权。

工具图片有独立数量边界，最早图片可缩成可回读引用，这不代表内容已失效；模型按需再读。图片引用或摘要说明不表示实际看过图像。

## 普通文件与工作副本

文件保留名称和独立身份，同名不覆盖。挂入成功仍是草稿，只有已发送消息引用的文件才进入模型材料视图；未发送或移除的文件不能提前成为模型材料。

分析文件默认挂本机来源，上传字节流式保存，不为整件文件设总大小门槛，也不整件读入服务内存。材料只读暴露，模型按路径分页、运行命令或加载专用能力；来源路径消失则明确报错。接受文件不代表已解析或读懂。

原件、材料视图与工作区职责分开。需要修改时，模型显式复制到工作区再编辑和验证；系统不自动导入、解析或摘要。工作副本的修改与撤销不改变会话原件，上传快照也不能写回用户机器上的来源文件。

恢复按已提交引用重建材料视图，压缩不删除已发送材料，交接保留附件身份与来源。只暴露材料根，不暴露整个产品数据根；文件工具的只读约束不等于本机命令具有操作系统隔离。

## 回读与请求边界

回读只接受本 Session 事实中出现过的引用，不能凭其他会话的标识取材料。子 Session 不自动继承父的图片与文件引用。图片整件读取，文本按范围读取，沿用已有工具，不另开执行循环。

内部消息始终保留本地引用，只在构造 Provider 请求时编码图片，同一请求复用相同引用的编码，不回写事实或持久保存协议编码。可见窗口中的图片仍可能逐轮上传，这笔成本不由内容去重自动消除。

不自动回收历史原件，不为普通文件预建格式解析器或音频模型协议，也不以单次读取和图片边界替代普通文件的按需读取。
