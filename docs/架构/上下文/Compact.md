# Compact：后台交接与上下文窗口

同 Session 内的上下文窗口切换契约。投影脱水见[上下文](上下文投影.md)；提醒见 [LoopGuard](LoopGuard.md)；SYS／工具呈现见[前缀稳定性](上下文窗口与前缀稳定性.md)。为什么这样设计见 [Self-Handoff 实施设计](Self-Handoff实施设计.md)。

## 执行模型

```text
B 在安全位置 P 冻结当前模型输入
  ├─ B 继续业务，新增事实进入同一 Journal
  └─ 独立 H Worker：原 SYS / TOOLS / 消息 + 交接要求
       → 可多轮回读冻结来源
       → 非空文本且无工具调用 → 接纳 handoff

B 到安全位置 Q
  → 提交交接事实
  → 提交窗口切换事实
  → 下一次决策读取新窗口
```

B 的 Session identity、工具激活、委派和决策游标持续存在。H 有独立 Journal 与决策游标，不竞争 B 的 Step，也不继承其待执行 Command。H 使用相同的模型工具定义，但执行侧只允许回读 P 以内的冻结消息及其 Artifact；其他工具调用明确失败，不修改工作区、不发送用户回复。

B 可以是用户会话，也可以是尚未交回的子 Session。子 Session 沿用同一套实际用量触发、后台交接和窗口发布；H 继承的是该子在 P 处实际看见的输入，回读范围只属于该子。压缩不改变父子关系，也不把子过程带进父 Journal。

最终交接文本经一个不向模型暴露的内部 Command 接纳，不改变冻结工具列表。**`WAITING` 不是成功判据**——它也可能是在等工具结果；只有没有工具调用的非空文本才触发接纳。

## 窗口和来源

窗口发布位于直接工具及等待授权收口后的决策边界，不要求普通 SubAgent 全部回收——它们仍属于同一 Session。

新窗口必须保留 handoff、当前能力目录、`(P,Q]` 期间全部原样新增消息及之后的新事实。P 以前的内容由 handoff 承接，原文保存在来源材料中供回读。

P 与 Q 都位于直接命令收口后的安全边界，新增消息沿 Event sequence 与 Step identity 选择，不能拆开 tool call 与 tool result。不再附带按本地 token 估算挑选的旧历史尾部。

Assistant 从 Journal 重建 active window。Runtime 始终归约完整 Journal：窗口隐藏的旧事件不被删除，也不会重新执行。

来源材料保存实际冻结请求、带事件序号的模型消息与允许读取的 Artifact。历史浏览覆盖授权范围内的完整原始消息，包含已被压缩移出当前窗口的部分；当前模型阅读窗口不限制历史回查。历史回读用事件序号，不把它冒充 Step 编号；读到的是该事件对应的模型消息投影，不是原始 Event 本体。handoff 保存原有证据强度，遇到疑点才回查，不做统一接班后验。

回读范围由执行侧确定，模型不选择来源会话。业务模型读取当前 Session 的完整逻辑历史，包括分支继承的前缀，不能读到来源在分叉之后追加的事实；后台交接模型只读取冻结来源。任意次分支派生与窗口压缩都不改变已继承消息的定位与原件回读，原件存放位置由现有继承关系解析。交接材料中的来源身份只用于溯源，不作为后续调用的路由。

历史浏览按事件范围与关键词字面匹配定位，返回有界原文片段和原文回读位置，保持历史顺序，不做语义排序或重要性筛选。片段不代表读过全文，外置原文仍须按引用读取。交接应保留完整文件位置、关键证据的真实序号、推测与未确认条件，不把相关性提升为已验证的因果结论。

一次查询固定历史截止位置，续页沿用同一切面。业务回读先截取截至该位置的执行事实再生成消息投影，后到的工具结果不能改变旧页中的 Step 表示；后台交接始终使用同一冻结来源。当前窗口切换、分支来源继续追加以及查询自身产生的新记录都不使续页漂移。查询切面由事件位置表达，不另存一套持久查询状态。

## 触发与恢复

触发只读取当前窗口最近一次已提交模型响应的实际输入用量，包含缓存命中；达到绝对阈值便启动后台交接。没有当前窗口用量时不估算。窗口切换后，旧窗口的用量失效，等待新窗口实际响应后再次判断。

用量及窗口身份随 Step 提交，恢复不依赖 Worker 内存。触发检查后若 Journal 变化，Runtime 的通用推进前提使下一 Step 重新经过边界；Runtime 不接收 Compact 阈值或用量语义。

阈值只用于启动交接，不是模型调用或窗口发布的硬上限。后台整理期间 B 持续运行，新窗口也不经过本地 token 容量检查。新输入和工具结果可能使实际请求超过 Provider 容量，这是调用边界需要原样报告的已知错误。

失败保留原始诊断，不自动重试、不发布半成品。B 保留旧窗口并继续运行；压缩失败本身不暂停业务会话。压缩状态推给 Channel 展示，失败不冒充用户会话的模型失败。

子 Session 的交接失败同样不阻塞其业务执行；后续模型调用若实际失败，沿既有子会话失败通道交回父 Agent。子正常 `report`、静止交回或被 `reclaim` 后，未发布的后台交接作废，reader 停止；`subagent.return` 之后不得再发布窗口。已发布的窗口仍是该子 Journal 的历史事实。

发布顺序是：先保存交接 Artifact 和发布准备，再向 B 幂等追加交接与窗口事实，最后标记任务已发布。进程中断后继续同一次发布，不重新生成已接纳的 handoff；过期来源窗口不能覆盖当前窗口。

Host 侧的后台任务库只保存任务、结果和发布准备，不保存业务会话路由。开发阶段只维护当前表结构，不做版本检查与自动迁移；旧结构数据需停止任务后一次性备份重建。
