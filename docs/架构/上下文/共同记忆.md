# 共同记忆

长期 Bot 除了产品提供的共同系统规约，还需要一份能共同查阅、修订的团队笔记，保留协作形成的约定和重要结论。它属于同一产品数据空间中的整个 Bot 团队，不依附某个 Bot、群聊或代码项目，也不随工作树落地进入仓库。个人笔记与系统提炼仍是[后续方向](../未开始/记忆.md)。

## 保持短小，由团队维护

正文硬限制五百字，标点、空白和换行也计数，可以为空。这个限制用来迫使维护者取舍，不是需要填满的容量。只保留长期协作需要的共同约定或重要结论，不收集任务进度、临时端口、一次性报错和个人笔记。修改时整理全文，删除过时项、合并重复项；超限拒绝，不截断原文。

所有长期 Bot 都能查阅、修改，写入沿用工具授权；人也能在 Web 设置中查看和直接修订，双方维护同一份正文。系统不从聊天自动提炼，不判断一条内容是否值得记住，不自动合并不同意见。共同记忆是团队维护的记录，不是用户的新指令；Bot 修改它不能扩大用户授权。依赖事实的结论应保留核验依据，实时资源状态仍通过实际工具查询。

## 共同编辑与来源

修改以维护者已经读到的版本为基础；其间别人改过，就返回当前正文，交给维护者重新阅读和调整，不覆盖未读的新内容。Web 保留人的草稿并展示最新正文，核对后才能继续保存；关闭或切换设置也保留未保存草稿。正文、版本、修改者和本次写入来源一起持久保存，同一次操作再次确认不重复修改。Bot 修改指回自己的执行记录，人的直接修改标明用户来源，不伪装成 Bot 执行；不要求模型填写内部会话坐标。

共同正文由一处产品存储拥有，各 Bot 的会话只记录自己实际读到的版本和操作结果。记录旧版本是为了保留观察与修改依据，不能反过来覆盖当前共同正文。

## 在判断前明确呈现

Bot 第一次决策前，以及之后共同记忆有变化时，当前全文先作为不请求决策的事实进入它自己的会话；不修改稳定系统提示，不改写已经冻结的判断。变化不会单独唤醒空闲同事，他们下次工作时取得当前内容。

上下文压缩后，已经观察到的最近一份共同正文在新窗口明确重述，不靠交接摘要转述。压缩期间的新观察仍按原有事实顺序接入，后续新版本取代旧版本。系统规约说明这是什么、怎样查改以及写入标准，正文随事实呈现。

Runtime 沿用普通工具和事实机制，不理解记忆内容。第一版不扩展成检索库、任务状态表、资源分配表或自动提炼系统。
