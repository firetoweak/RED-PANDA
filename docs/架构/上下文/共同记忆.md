# 共同记忆

共同记忆保存适用于整个 Bot 团队的工作约束，遵守同一准入标准：短、常用、常改、场景无关。只适用于单个 Bot 的约束放在[个人记忆](个人记忆.md)。两者按适用范围区分，个人例外须有用户明确依据，用户当前要求优先，记忆不能扩大操作授权。

可复用、相对稳定且通常带场景的结论、技能和文档属于知识沉淀，应归档后按需检索。任务进度由计划承载，过去做过的事情通过[历史检索](Compact.md)回查，均不进入常驻记忆。

## 保持短小，由人和 Bot 维护

正文有很小的硬上限，可以为空。容量用来迫使维护者取舍，不是需要填满的目标。修改时整理全文，删除过时约束、合并重复约束；用户明确修订时替换旧约束，不累计互相矛盾的要求。超限拒绝，不截断原文。

所有长期 Bot 都能查阅、修改共同记忆，写入沿用工具授权；人也能在 Web 设置中直接修订。内容是否值得记住、冲突意味着什么，由维护者判断，Runtime 不做语义判断。系统没有额外的主动提炼、定时检查或后台整理任务，[主动维护](../未开始/记忆.md)另行设计。

## 共同编辑与来源

修改以维护者已经读到的版本为基础；其间别人改过，就返回当前正文，交给维护者重新阅读和调整，不覆盖未读的新内容。Web 保留人的草稿并展示最新正文，核对后才能继续保存；关闭或切换设置保留未保存草稿。正文、版本、修改者和写入来源一起保存，同一次操作重试不重复修改。Bot 操作能回查执行记录，人的直接修改标明用户来源。

共同正文由一处产品数据拥有，不依附 Bot、群聊或代码项目，也不进入项目仓库。各会话的旧观察与修改结果不能反过来覆盖当前正文。

## 与历史分开加载

每次判断单独读取共同与个人记忆，将当前正文放在稳定历史之后。记忆加载不追加为会话历史消息，不修改稳定系统提示；一次模型请求中的正文保持不变。更新不会唤醒空闲 Bot，他们下次工作时读取新内容。

上下文压缩只整理历史，不携带或概括记忆正文。新窗口仍通过同一独立入口加载当前记忆，避免反复摘要造成改写，也避免记忆更新改变已有历史前缀。显式读写工具仍保留操作记录，实际模型请求可用于核对该次判断读到的内容。
