# 共同记忆

共同记忆保存适用于整个 Bot 团队的工作约束，遵守同一准入标准：短、常用、常改、场景无关。只适用于单个 Bot 的约束放在[个人记忆](个人记忆.md)。两者按适用范围区分，个人例外须有用户明确依据，用户当前要求优先，记忆不能扩大操作授权。

可复用、相对稳定且通常带场景的结论、技能和文档属于知识沉淀，应归档后按需检索。任务进度由计划承载，过去做过的事情通过[历史检索](Compact.md)回查，均不进入常驻记忆。

## 保持短小，由人和 Bot 维护

正文有很小的硬上限，可以为空。容量用来迫使维护者取舍，不是需要填满的目标。修改时整理全文，删除过时约束、合并重复约束；用户明确修订时替换旧约束，不累计互相矛盾的要求。超限拒绝，不截断原文。

所有长期 Bot 都能查阅、修改共同记忆，写入沿用工具授权；人也能在 Web 设置中直接修订。内容是否值得记住、冲突意味着什么，由维护者判断，Runtime 不做语义判断。系统没有额外的主动提炼、定时检查或后台整理任务，[主动维护](../未开始/记忆.md)另行设计。

## 共同编辑与来源

修改以维护者已经读到的版本为基础；其间别人改过，就返回当前正文，交给维护者重新阅读和调整，不覆盖未读的新内容。Web 保留人的草稿并展示最新正文，核对后才能继续保存；关闭或切换设置保留未保存草稿。正文、版本、修改者和写入来源一起保存，同一次操作重试不重复修改。Bot 操作能回查执行记录，人的直接修改标明用户来源。

共同正文由一处产品数据拥有，不依附 Bot、群聊或代码项目，也不进入项目仓库。

## 当前记忆、观察事实与上下文呈现

当前记忆的唯一事实源是对应的产品记忆存储。页面和读写工具访问同一份正文；只有显式修改才能改变它。共同与个人记忆各自拥有正文，不从会话、交接摘要或上下文快照归约当前值。

Journal 只拥有“这个 Bot 当时观察到了什么”的执行事实。首次判断前及之后版本变化时，先提交包含完整原文的观察，再允许模型据此判断。未变化时不重复追加，观察不请求决策，记忆更新本身也不唤醒空闲 Bot。工具结果证明那次操作的结果，不替代下一次读取当前记忆。

观察提交表示会话已经取得该版本，不单独证明模型已经使用它；某次实际调用读到了什么，仍以该次冻结请求核对。请求记录只保存输入依据，同样不能拥有或恢复当前正文。

两者回答不同的问题，不互相同步：产品中已经是新版、空闲 Bot 最后只观察到旧版是正常状态。它下次工作时取得新观察；旧观察不能覆盖、修复或恢复产品中的当前正文，也不能因为已有观察就跳过读取当前记忆。观察是必须保留的历史事实，不是可随意丢弃的当前值缓存。

上下文只从已提交观察确定性地呈现正文，不直接读取记忆存储。与[工作计划](工作计划.md)相同的是“首次呈现、变化追加、历史位置固定”；不同的是计划当前值来自成功工具结果，记忆当前值由产品存储拥有。无需另设一份当前正文或独立的呈现账本。

每份新观察以完整正文替代此前同类记忆，清空也明确呈现。旧版失去当前效力，但保留在原有位置；回复排在它实际已读的事实之后，后续请求继续追加，不拿最新正文回填旧位置。已经冻结的判断继续使用当时的观察，后来的修改从后续判断可见。观察不作为用户发言展示，也不修改稳定系统提示或工具定义。

## 压缩与恢复

交接摘要不负责复制、改写或恢复记忆正文。新窗口原文重述交接起点最近的共同与个人观察，再按原顺序保留压缩期间的新事实，使后来的完整版本替代旧版；更早的版本留在原始历史中。新判断前仍从产品存储取得尚未观察的新变化。

重述与历史回放只能由已提交观察重建，不能反写当前记忆。窗口切换会建立新的前缀；同一窗口内，未变化的记忆不重复呈现，更新只追加新正文。工具能力变化和普通上下文脱水仍遵守各自规则，不承诺跨窗口或任意投影变化后的缓存命中。
