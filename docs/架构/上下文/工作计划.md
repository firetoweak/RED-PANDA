# 工作计划与长任务

长任务沿用普通 Session 的 Step 推进，不另建执行器。Journal 保证事实连续，Compact 管理模型阅读窗口，LoopGuard 提供机械观察；计划和完成核验属于模型行为，由 Assistant 提供窄能力和上下文投影。

## 按需外化进度

非简单、多阶段或长时间任务由模型主动建立工作计划，简单任务无需制定计划。Runtime 不判断任务复杂度，也不要求每个 Session 都有计划。

计划表达模型对当前任务的理解、事项进度及必要说明，保持简短，不作为工作日志。做下一项前考虑上一项是否完成；理解变化、调整顺序或发现为达成当前目标必须补做的工作时，由模型更新完整计划。用户调整目标或开始新任务时，模型更新、替换或明确结束当前计划。

用户要求始终是任务理解和授权的依据。计划不能覆盖用户事实、扩大授权或把模型声明升级成客观证明。

## 唯一事实源

成功提交的普通计划工具结果是计划的事实源。尚未执行的请求、失败结果和 UI 预览不改变当前计划。每次更新形成完整新版本，结束当前计划也是追加事实，旧版本和对话历史保持原样。

Assistant 从同一组 Journal 事实投影模型上下文与 Channel 的当前计划，不在 Host 或前端另存权威计划。Runtime 不解释计划内容，不依据事项状态调度、强制续步或结束 Session。

## 动态尾部与历史前缀

每次业务模型调用从本次冻结位置以内的已提交事实读取当前计划，以独立区域附在上下文尾部，注明它是模型维护的记录，不是用户新指令或完成证明。从未成功更新计划时不附空占位；明确结束计划后仍提供已清除的状态快照，使模型无需从历史缺失推断当前状态。计划内容不进入固定 SYS 或工具定义。

实际呈现的计划文本随该 Step 原子提交；恢复历史时使用当时的原文，不拿最新计划回写旧块。保存的文本只证明当时给模型看了什么，不成为当前计划的第二事实源。更新和清除不能删除已经呈现的历史块。脱水与 Compact 窗口切换遵守各自契约，不改变原始 Journal。

Compact 后的当前计划及清除状态仍从完整 Journal 投影，不依赖 handoff 是否完整传承它。旧交接内容不能覆盖最新快照，计划快照也不能覆盖用户要求。冻结交接请求原样继承来源输入；交接 reader 不执行业务计划更新，也不把来源会话的计划当成自己的计划状态。

## 用户呈现

未完成的当前计划在输入区域上方按需展示，默认收起，展开后显示完整事项与说明。事项全部被模型标记完成后，计划跟随更新它的那轮回复末尾展示，随历史滚动；替换或清除当前计划后仍可查看完成记录。同一轮只展示最近一次完成记录。没有有效计划时输入区域不留占位。每轮模型阅读快照不重复显示为聊天气泡。

事项数量只统计模型记录的事项状态，不表示整个目标的完成百分比。模型记录的进行中事项不等于 Worker 正在执行，Session 活动仍由既有运行事实与瞬时活动展示。

## 完成核验

收尾前由模型对照最新任务要求和当前计划，用已有工具证据核对关键成果，缺少关键证据时继续验证。证据仍有效时不重复获取；未完成或未验证的部分如实说明，并据此更新计划。宣布完成必须说明验证依据，不要求所有类型的任务都采用同一种测试。

事项全部完成和停止调用工具都不能单独证明用户目标已满足。证据是否满足目标仍由模型判断，普通执行自然回到等待外部事实，不封闭 Session。

## 明确不做

- 不引入独立 Judge、声明式完成协议或核验阶段状态机。
- 不向 Runtime 增加 Goal、Criteria 或计划语义，不从 Host 内存注入可变判定标准。
- 不用缺少新事实的定时唤醒保证任务可靠性；实际观察需求沿现有自动化入口处理。
- 不增加任务层级、事项依赖图、前端直接编辑计划的第二更新路径。
