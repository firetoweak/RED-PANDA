# 工作计划

计划外化模型对长任务的理解与进度，不另建执行器。模型按需要建立、更新或结束，简单任务不强制有计划；Runtime 不判断任务复杂度，也不依据事项状态调度。

## 计划与证据

计划保持简短，不作工作日志。目标变化、顺序调整或发现必需的补充工作时，由模型更新完整版本；用户要求始终优先，计划不能覆盖目标或扩大授权。

只有成功提交的计划工具结果改变当前计划，失败、未执行请求和 UI 预览不算。更新、替换与清除都追加事实，旧版本留在历史；模型和页面从同一事实来源读取，不另存权威副本。

## 上下文中的呈现

每次业务判断从冻结位置以内取得当前计划，首次、变化或清除时在尾部呈现，未变化不重复追加；计划不进入固定系统提示或工具定义。实际呈现随该次决策提交，不能拿最新版本回填旧位置。

压缩后从完整事实重述当前计划及清除状态，不依赖摘要传承；交接材料不能覆盖最新计划。后台交接只读取来源计划，不把它当自己的状态或执行业务更新。

## 人的查看与完成核验

未完成计划按需显示，完成记录随更新它的回复保留在历史。替换或清除当前版本不抹掉旧记录，模型每次读到的快照不重复画成聊天气泡。

事项数量不是目标完成百分比，模型标记进行中也不表示 Worker 正在执行。收尾应对照最新要求，用实际工具证据核对关键成果；已有证据仍有效就不重复获取，缺少证据则继续验证或明确未验证范围。

全部勾选和停止调用工具都不能单独证明目标满足。完成判断归模型或人，不形成 Session 终态，也不引入独立 Judge、核验阶段或声明式完成协议。

不建设任务层级、事项依赖图或前端直接编辑的第二更新路径，不向 Runtime 增加计划语义；真正需要后续观察时使用[自动化](../运行/自动化.md)，无新事实的唤醒不能保证可靠执行。
