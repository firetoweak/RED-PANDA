# 记忆

共同记忆与个人记忆承载短、常用、常改、场景无关的工作约束。两者使用同一准入原则与呈现规则，只按适用范围区分。当前任务用[工作计划](工作计划.md)承接，经历通过[历史检索](上下文压缩.md#历史回查)回忆，稳定知识和方法归档后按需读取。

## 适用范围与维护

共同记忆面向整个团队，不依附 Bot、群或代码项目。个人记忆跟随单个 Bot 的长期身份，改名、项目变化与上下文压缩都不改变归属；它只补充共同约束，个人例外须有用户明确依据，不因范围更具体就自动覆盖共同约束。

人可编辑共同正文与各 Bot 的个人正文；Bot 可共同维护团队约束，只能读写自己的个人记忆，写入沿用工具授权。当前用户要求优先，记忆不能扩大操作授权，也不替代身份或历史记录。

正文可以为空，采用较小硬上限并整体修订。容量迫使维护者取舍，不是需要填满的目标；过时约束应删除，重复内容应合并，明确纠正应替换旧要求，超限拒绝而不截断。临时要求不进入持续约束。是否值得记住由维护者判断，系统不自动提炼或后台整理，[主动维护](../未开始/记忆.md)仍待设计。

## 共同编辑与来源

修改必须基于维护者已经读到的版本。期间有人或 Bot 改过，就返回最新正文，交给维护者核对后修订，不能覆盖未读的新内容。Web 保留人的草稿并展示最新版本，关闭或切换设置不丢弃当前页面内的未保存修改；切换 Bot 不沿用另一位的个人草稿。

正文与修订来源一起保存，同一次操作重试不重复修改。Bot 操作可回查执行记录，人的直接修改标明用户来源。

## 当前记忆、观察事实与上下文呈现

产品记忆存储拥有当前正文，页面与读写工具访问同一份内容；只有显式修改可以改变它。Journal 拥有“这个 Bot 当时观察到什么”的历史事实，两者不互相同步，也不从摘要或请求快照恢复当前正文。

每次判断前读取当前记忆，首次或变化后先提交包含完整原文的观察，再让模型据此判断；未变化时不重复追加。更新本身不唤醒空闲 Bot，工具写入成功也不能替代下一次读取当前正文。产品已是新版、空闲 Bot 尚未观察到是正常状态。

上下文只投影已提交观察，不直接读取产品中的最新正文。变化和清空都以完整新正文追加，旧版保留在原位置但失去当前效力；不能把新版回填历史开头。回复排在本次实际读到的事实之后，在途判断继续使用已经冻结的观察。观察的提交不单独证明模型已经使用它，实际依据以冻结请求为准。

## 压缩与恢复

摘要不复制、概括或恢复记忆正文。新窗口原文重述交接起点最近的观察，再按原顺序保留压缩期间的更新，避免把后来正文提前放回过去。新判断仍读取尚未观察的变化。

重述与重放都不能反写当前记忆。同一窗口内仅追加变化，窗口切换建立新的前缀；不承诺跨窗口或任意投影变化后的缓存命中。
