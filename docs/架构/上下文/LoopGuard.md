# LoopGuard：旁路机械观察

根据已提交执行事实机械识别重复行为，只提供提醒。可选语义增强与中断权限见 [Jev 决策增强](../运行/Jev决策增强.md)。

## 职责与边界

LoopGuard 归属 Assistant 的独立旁路，不进入主模型决策、Step 提交或 Runtime 推进流程。它不判定无进展、不拒绝工具调用、不强制收尾、不终止 Session，也不把策略命中转换成异常。

模型依据近期操作与结果决定继续原方法、调整方法、完成任务或报告阻塞；继续原方法不违反契约。未知异常原样暴露，不用机械提醒掩盖失败。

普通 Session、SubAgent 和后台交接各自检测自己的 Journal，不混用父子会话的执行范围。单次模型调用或工具一直不返回，不由机械重复检查解决。

## 严格匹配

首批只观察连续相同操作，不做参数语义推断或模糊匹配。相同操作要求工具身份及规范化后的完整参数相同：

- 忽略对象键顺序，递归规范化嵌套对象；保留数组顺序。
- 字符串原样保留，不修改空白、大小写或路径。
- 缺失字段与显式空值区分，保留数值、字符串、布尔和数值表示的类型区别。

检测策略只读执行记录，返回命中证据或不命中，不直接发消息、调用模型或修改 Session。不建设策略插件、动态加载或策略 DSL。

## 提醒覆盖

复用 Journal 的执行位置和操作身份。一个 Step 中的多个调用是不同操作，不用事件序号相减充当操作次数。

已经投递的系统提醒界定其所依据的执行范围。旧记录可帮助识别连续重复，但下一次提醒必须积累足够的新命中操作；未实际投递的检查结果不消耗提醒覆盖。多个机械策略共用提醒覆盖，不对同一段历史分别重复提醒。

覆盖从实际系统提醒与执行事实重建，不将检测计数、命中策略或检查结果绑定到 Step 元数据。分支只继承自己的冻结事实；Compact 不删除执行历史，也不重置覆盖。

## 投递与降级

旁路只通过通用系统消息入口投递固定提醒，明确系统来源，不冒充用户新指令。主模型在后续调用读取提醒，当前调用和工具继续执行。消息进入历史后按当时原文恢复，不在每轮重新生成。

未启用、未配置或无法取得有效 Jev 判决时，机械判定独立工作且只提醒。启用 Jev 的同一次检查只执行一个最终判决，不先发送机械提醒再应用增强判决。机械命中次数不授予中断权限。
