# LoopGuard

LoopGuard 从 Session 自己的执行事实机械发现重复行为，提醒模型审视进展。它不判定没有进展，不拒绝调用、强制结束或把命中变成异常；继续、调整、完成或报告阻塞由模型判断。

## 检测边界

同一行动理由内，连续相同工具与完全相同参数可触发提醒。相同是严格结构比较，不做语义归一、模糊匹配或路径改写；每次外部唤醒做一次同样检查属于正常事件驱动工作，不算跨唤醒重复。

请求决策的外部事实重开连续计数，包含人的输入、同事请求、定时、子回复与控制操作终局。仅供观察的变化不能重置。普通会话、子协作与后台交接各检查自己的执行，不混用来源历史。

策略只返回事实证据，不直接发消息、调用模型或改变会话；没有新需求前不建设策略插件或规则语言。单次工具一直不返回也不是这个检测器的问题。

## 提醒与覆盖

提醒可引用旧行为作为背景，但再次触发须有足够新行为，不能重复使用上次已经覆盖的证据。多个策略共享覆盖边界，避免轮流提醒同一段历史。

命中不立即消耗覆盖。提醒文本、依据和覆盖范围随成功决策一起提交；调用或提交失败不前移边界。文本明确这是系统观察到的重复，不冒充用户新要求，也不声称任务已经失败。

提醒只追加，不改系统提示、工具定义或旧前缀。恢复从原事实重建，不用新版策略重算旧提醒；[压缩](上下文压缩.md)只换模型阅读范围，不重置检测记录。

## 与资源限制分开

不设 Agent 任务总调用数或总时长来替代进展判断。模型请求、连接、下载等具体操作可有自己的资源限制；工作区命令前台到点转后台，不因此限制总运行时间。

未知异常仍原样暴露，不以提醒掩盖失败、发布半成品或自动重试。
