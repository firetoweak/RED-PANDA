# LoopGuard：Session 级进展审视提醒

根据执行事实机械触发进展审视提醒。窗口切换读 [Compact](Compact.md)。

## 职责与边界

LoopGuard 归属 Session。它**不判定无进展**，不拒绝工具调用、不强制收尾、不终止 Session，也不把策略命中转换成异常。模型依据证据决定继续原方法、调整方法、完成任务或报告阻塞；继续原方法不违反契约。

它是 Assistant 层能力，适用于普通 Session、SubAgent 和 compact Session。Runtime Core 只负责事实、冻结边界与原子提交，不理解检测策略或进展语义。

各 Session 检测自己的 Journal，不混用父子会话的覆盖位置。compact 的来源上下文不是 H 自身的执行记录。

本轮不设计 ActivityWatchdog，不预留相关接口。单次模型调用或工具一直不返回，不由 LoopGuard 解决。

## 策略与严格匹配

检测策略只读执行记录，返回命中证据或不命中，不直接发消息、调用模型或修改 Session。用独立策略函数和统一证据输出，不建设插件注册、动态加载或策略 DSL。

首批只实现连续相同 action。后续可增加短周期振荡、重复错误、重复结果和工具族高频，不提前实现。

相同 action 定义为相同工具身份，以及规范化后完全相同的 arguments：

- 忽略对象键顺序，递归规范化嵌套对象；保留数组顺序。
- 字符串原样保留，不 trim、不转小写、不改写路径。
- 缺失字段与显式 null 区分，不自动补默认参数。
- 保留数值与字符串、布尔与数值的类型区别。

**不做参数语义推断或模糊匹配。** 判断"这两次调用其实是一回事"是语义判断，属于模型的地界；fingerprint 只服务于严格动作比较。错误归类、结果比较和工具族划分由各自策略定义，不扩张统一 fingerprint 的含义。

## 检测窗口与提醒覆盖

复用 Journal 事件位置，不另建执行序列。动作证据引用已提交调用及其具体 Command 身份，一个 Step 中的多个调用仍是不同的行为；异常数量按行为计数，不用事件序号相减。

LoopGuard 统一维护提醒覆盖位置 C，各策略不维护独立覆盖游标。每次检测使用本次决策的冻结快照，截至位置 P：

1. 检测窗口允许跨过 C，旧记录可帮助识别连续重复或振荡。
2. 再次触发必须在 C 之后积累足够的新异常行为；旧行为不能再次计入触发门槛。
3. 合并各策略当前命中的证据，一次提醒覆盖到 P。其他策略不能随后使用 P 及以前的旧行为再次触发。
4. 仅检测命中不推进覆盖位置；提醒随 Step 成功提交后，覆盖位置才更新为 P。

门槛为 3 次时：A₁、A₂、A₃ 后提醒；A₄、A₅ 不重新触发；A₆ 后再次提醒。第二次可引用此前重复作为背景，但只用 A₄～A₆ 满足新增门槛。

策略必须返回异常行为的位置及身份，而非只有布尔值——否则算不出新增覆盖区间。

## 决策输入与持久化

命中时把一个独立标记块增量追加到模型上下文末尾，不修改 SYS、工具定义或已有请求前缀。提醒的措辞必须说明这是系统观察到的行为重复、不代表已经判定无进展，**不冒充用户新指令**。

已有提醒作为历史事实处理，不在每轮重新生成、改写或重复追加。

携带提醒的 Step 成功提交时，同一原子提交中记录实际文本、命中策略标识与版本、证据引用及覆盖位置。模型调用失败或 Step 未提交，不消耗提醒覆盖。Runtime 只冻结、序列化这份不透明元数据，不解释提醒语义。

## 恢复与压缩

Journal 是唯一事实源。检测窗口与计数可重建，不另存一份权威状态。

- resume：重放完整 Journal，恢复最后已提交提醒的覆盖位置。
- 从某个 Step 重建：只采用截至该提交边界的执行和提醒事实，不带入之后的覆盖位置。
- compact：上下文投影变化不删除执行事实，也不重置 LoopGuard。
- 策略更新：旧提醒按原事实恢复，不用新版策略重算或改写；新版策略用于后续检测，仍遵守已有覆盖位置。

## 与超时的分工

LoopGuard 取代了 compact 原有的调用次数上限与任务总时长预算——那两条是在替模型判断"该收尾了"。

保留的是资源边界，不是进展判断：压缩触发阈值、读取权限与交接接纳规则，以及模型 HTTP、命令执行、搜索、MCP、下载、数据库锁等局部超时。租约属于执行权协调，不属于任务总超时。

未知异常仍原样暴露，不用 LoopGuard 掩盖失败；不因提醒发布半成品或自动重试失败任务。
