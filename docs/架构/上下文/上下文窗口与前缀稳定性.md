# 上下文窗口与前缀稳定性

SYS／工具呈现约束：固定规则、目录按消息追加、工具按名称排序。能力端口见[工具与能力](../能力/工具与能力.md)，窗口切换见 [Compact](Compact.md)。

## 固定规则与动态事实

SYS 保存稳定的行为规则，不根据运行状态增删说明。

SYS 末尾的环境段只放会话内不变的事实：系统与会话绑定的工作区。日期这类会漂移的信息不进 SYS。

SubAgent 用固定条件规则表达："还有委派没回来时，手上的结论是不完整的。"不按 pending 状态添加或移除 SYS 提醒——那会让 SYS 每收到一条结论就变一次，整段前缀缓存跟着失效。委派、返回与收回继续通过追加事实表达，模型依据事实判断还有谁未返回。

工具定义只表达用途、参数、调用约束。目录不追加"已加载"标记，不拼入"最近失败"等运行状态。

关键动态信息作为有明确来源和用途的上下文消息追加，例如：

```text
<tool_catalog_update>
新增：mcp:github，用于查询 GitHub 仓库和 PR。
停用：mcp:calendar。
</tool_catalog_update>
```

标签是内容标识，不提升消息权限；角色表达上必须明确它是系统提供的事实而非用户发言。

初始目录与后续变更必须以 Session Journal 中带 catalog revision 的事实形成可恢复、顺序明确的模型视图。全局 Registry 只拥有产品当前可用资源，不能直接改写某条 Session 已经看见的目录。不把最新目录每轮插回历史开头，也不重复追加未变化的状态。

## 工具顺序

最终暴露给模型的 `tools` 统一按工具名称排序。同一组工具的输出顺序不得取决于加载先后、并发完成或注册顺序。新增工具可以插入排序位置，已有工具之间的相对顺序保持不变。

排序只消除无意义波动，不承诺动态 Schema 变化后继续命中完整前缀缓存。工具真实新增、删除或参数变化时正常更新 Schema，接受必要的缓存失效——保持渐进式加载，不为缓存预先暴露所有扩展工具。

## Skill 目录

Skill 是指令包。`load_skill` 与资源读取工具的描述保持稳定，不把当前技能目录拼进工具描述。初始目录、后续更新和按需读取的正文都通过消息提供，目录更新不回写之前的消息。

当前项目的 Skill 不自带执行工具。若未来 Skill 配套真实工具，这些工具仍按独立能力机制注册并加入原生 `tools`；不能把工具说明追加到消息就误当成完成了执行注册。
