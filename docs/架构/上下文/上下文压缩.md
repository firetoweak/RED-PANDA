# 上下文压缩

Compact 只切换同一 Session 的模型阅读窗口。执行事实、稳定身份、工具激活与委派关系连续存在；Runtime 始终归约完整 Journal，不因旧内容移出视图重新执行命令。

## 执行模型

业务会话在直接命令收口后的安全位置冻结当前模型输入，交给独立的后台会话生成交接材料；业务继续运行。后台读取的是冻结时实际输入的系统提示、工具定义与消息，不按之后的目录变化重新组装。

后台可以多轮回读冻结来源，但只有只读能力可以执行；不能修改工作区、委派业务、发送消息或执行控制操作。工具定义仍可见不代表获得执行权限。后台自己的阅读记录不注入业务对话，也不竞争业务决策。

只有没有工具调用的非空文本才可接纳为交接材料；等待工具不代表交接完成。已经接纳的材料是不可变、有来源的事实，不能因恢复而重新生成并覆盖。

## 窗口和来源

冻结点与窗口切换点是两个安全位置：冻结点之前的内容由摘要承接，期间新增的全部事实原样保留。两点都不能拆开直接工具调用与结果；不要求普通子协作全部结束，也不按本地 token 估算裁剪这段新增事实或拼接旧历史尾部。

新窗口重述当前能力目录。长期 Bot 的名字、所在群与成员、例行任务由事实重建，在摘要之前呈现；[记忆](记忆.md)原文重述冻结点最近的观察，期间更新仍按真实顺序接入。摘要只承接需要理解的往来、职责、约定与工作，不兼任身份、运行状态或记忆的存储。

交接保留证据原有强度：计划不是已执行，完成声明不是已验证，未知结果仍未知。未结束的往来按对象和工作保留，不假设长期时间线只有一个当前任务；用户指定的命令环境与已验证执行方式也应区分，不把一次子 Shell 的激活写成持续状态。

工具、委派与执行状态可从事实恢复，不需要接手模型一律重验前任所有行动。遇到疑点或矛盾再回查，缺少最终结果时不能由摘要推断原因或诱导重复副作用。

## 历史回查

原始历史和外置材料保留可回读引用。业务模型可以查授权范围内的完整逻辑历史，包括已压缩部分；后台交接只可读冻结来源。来源标识用于溯源，不让模型任意选择其他会话。

历史检索按明确时区的时间范围、事件范围与关键词字面匹配，返回有界原文线索、记录时间和固定引用，保持历史顺序，不做语义排序。线索不表示已经读过全文；事件位置也不是决策步骤编号。工具结果随发起它的助手回合回查。

一次查询固定历史截止位置，续页保持同一切面；后来到达的结果、查询自身的新记录或窗口切换不能改写旧页。多次压缩仍保留原有消息定位，来源链能追溯到原始事实与实际冻结材料。

## 触发与恢复

触发依据是当前窗口最近一次已提交模型响应的实际输入用量，包含缓存命中；没有实际用量时不估算。达到配置阈值后启动后台交接，阈值为业务继续增长留余量，不是请求或窗口发布的硬容量上限。

业务继续期间仍可能超出 Provider 容量，该错误在调用边界明确暴露。窗口切换后旧用量失效，等新窗口实际响应再判断。模型与调用偏好使用后台任务启动时的选择，不被后来的切换改写。

失败保留原始诊断，不自动重试或发布半成品；业务保留旧窗口继续运行，压缩失败不冒充业务模型失败。材料一旦接纳，发布被中断后接续同一次发布，不重新生成摘要，过期来源不能覆盖较新窗口。

停止业务会话不取消后台交接。子协作结束或执行失败后，尚未发布的交接作废，不在父已结束协作后切换子窗口；已经发布的窗口仍保留为历史。

## 为什么不设调用上限

后台交接不以调用次数或总时长强制收尾，进展审视由 [LoopGuard](LoopGuard.md)提醒，继续、调整或报告阻塞由模型决定。读取权限、交接接纳和具体外部操作的资源限制仍由系统保证，未知异常不能包装成正常交接成功。

压缩不能解决工具定义本身独占容量的问题，也不保证摘要质量或服务端缓存命中。这些需要真实模型评测，机械边界的脚本与进程测试不能替代。
