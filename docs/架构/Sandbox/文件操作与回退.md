# 文件操作与回退

> 文件回退的对象是助手操作造成的变化。捕获自动，回退显式。

只处理任务文件视图内的文件状态，不复现整个开发环境。系统配置、挂载外的文件、安装环境、网络和其他外部副作用不属于这条轨道。执行环境见 [执行环境](执行环境.md)，委派成果的比较与合入见[子任务文件交换](子任务文件交换.md)。

## 不变量

**查询与修改属于同一逻辑工作区，读取边界明确。** 只读文件工具与声明只读的命令查询已发布的工作区，不读取正在执行的候选，也不产生文件版本；多个查询可并行，并可与候选执行重叠。助手发布文件时与查询互斥，避免查询读到助手发布一半的结果；用户直接修改仍不参加这条锁。只读声明是调用契约，不是操作系统写入限制，误标产生的写入不在回退范围。文件修改和可能写入的命令在独立候选中执行，封存变化证据后才接受并发布到用户工作区。非零退出或工具报告失败并不证明没有文件变化；候选操作的已知结果保留其实际文件效果。未完成的宿主发布必须显式恢复，未知异常和持久化损坏原样暴露，不猜测执行结果，不静默重跑。

**锁依赖单向。** 修改持有操作所有权，只在同步已发布状态或写回结果时申请发布独占；查询不申请操作所有权。持查询锁的回调不得等待修改或发布完成，发布阶段不回调工具。等锁必须让出执行资源，并允许取消，不能占满负责释放锁的执行线程。

**初始化和 Step 收口不遍历工作区。** 文件内容在实际改变时按块捕获，未触碰的文件不复制。Step 边界只记录已接受操作的位置；工作区总大小不决定初始基线的成本。`.gitignore` 不排除已发生的助手变化。

文件边界必须对应已完成发布的实际状态。已有明确操作证据而发布中断时，先完成已知发布，再提供边界；恢复发布不重新执行工具。未知执行与损坏证据仍明确失败，不能以一个内部操作位置冒充可用文件状态。

**局部文本修改保留目标之外的原文。** 读取与编辑使用相同的原始换行，不因平台默认换行转换扩大修改范围；局部替换不先清空整文件。分散且等长的修改不重写中间无关内容；长度变化造成的后缀移动属于必要成本。文件读写等待与 CPU 处理不阻塞会话的其他异步工作，取消后先等待已发起的文件操作结束再释放文件边界。

**归因依据是操作前后结果。** 记录助手改变的位置及其前后内容，而非监视自然人身份。用户把 X 改为 H 后再改回 X，当前 X 仍可作为助手结果撤销；相同内容不证明期间没有用户写入。

**助手成果可以独立核对。** 文件管理系统从已发布操作证据与当前文件提供修改前后内容及归因，服务修改后的效果核对和收尾汇报，不通过实际恢复反推状态，不新增外部操作历史。查询范围由助手操作涉及的文件确定；连续操作之间观察到的外部值保留其来源，后续助手编辑不能把整个文件据为助手修改。没有基准的范围明确未知，不为查询增加全工作区快照，也不依赖 Git。当前状态只描述可观察的变化，不承诺未来回退一定成功。

**两种回退策略都保留未被助手改变的位置。** 保留策略只撤销当前值仍等于助手结果的位置，保留用户后续值；原值策略允许把助手改变的位置恢复到操作前的值。文件身份变化、命名空间冲突和不支持的结构操作必须明确拒绝，不能用内容相同替代身份判断。

**回退本身也是可撤销操作。** 保存其实际改变前后的证据，撤销回退时恢复真正的执行前状态，包括当时存在的用户值。无需为此扫描整个工作区。

回退结果说明实际改变与保留后续值的范围，不能把成功执行等同于完全撤销。效果取自同一次恢复判定并保存，重试不按后来的文件状态重新解释原结果。变化查询与比较的正文受限时，调用者必须能够继续取得剩余内容；读取当前文件不能代替缺失的修改前内容。

**同一任务根的接受与发布串行。** 多个顶层会话共享一条操作历史；从历史位置撤销后续操作会涉及其间其他会话的助手变化。独立子工作树有独立文件视图。用户直接写入不参加助手串行锁，发布必须核对当前内容和身份；冲突不能覆盖用户变化。

**产品数据与任务根分离。** 操作存储、Journal 和产品资源不能成为任务视图中的可回退文件。当前要求产品数据根位于任务根之外。

**没有有效引用就明确拒绝回退。** 成功事实可以隐藏，失败事实必须让模型看见。未知持久化问题不能降级为“这一步暂时不能回退”。

## 事实与引用

版本位置属于 Assistant 领域事实，不新增 Runtime Event 或 State。Runtime 不认识文件版本，也不解释用户是否需要回退。

模型引用当前上下文中的工具调用，撤销该调用所在整批以及其后的助手文件变化。取该 Step 之前的边界；第一步取初始基线。前一步没有有效引用时拒绝，不顺移到更早的状态。撤销恢复调用时使用它实际执行前的引用。Compact 已移出上下文的调用不可引用。

恢复独占一个模型批次。同批其他调用被明确拒绝，不静默拆批；底层串行锁不能替代这个语义契约。

## 用户时间旅行

人的入口是会话时间线：选中的 Step 属于保留前缀，文件选择跟随会话退到该 Step 完成后的边界。顺序仍是暂停来源、打断、等待静止、切分支、按用户选择处理文件；新身份保持暂停，等待下一句话。

文件处理不是新分支中的补偿 Command。处理结果作为分支起点的领域事实保存；后续编码以这个实际文件起点为基准，不能连同之前的时间旅行一起撤销。保留策略留下的用户值，以及用户选择不退文件时的现状，都属于这个起点。

只退会话时明确告知模型存在保留前缀之外的文件变化。文件回退冲突或保留后续值时，同样告知模型当前文件可能与保留历史不同。成功与失败的内部操作位置都不进入模型上下文；模型只看可观察的结果、相关逻辑路径及下一步动作。

模型自主回退仍是普通工具调用，其 Outcome 进入当前会话；它不截断聊天历史。用户时间旅行与模型自主回退分别编排，共用文件变化证据。

## 分层与不做

文件管理系统的职责边界见[Sandbox 总览](总览.md)。底层 VFS 库负责当前文件状态、SQLite 原子事务和冻结制品；文件管理层负责操作归因、候选、发布与恢复证据。文件操作历史以实际变化前后的证据为准，不在底层再维护一套独立的行级重放历史。冻结数据库制品服务于文件视图，不代表宿主基底文件也已被冻结。

文件控制可以由 Rust 与 Python 协作实现，语言不决定职责边界。Assistant 决定业务意图、记录边界并解析调用与时间线引用；Tools 提供窄入口。Runtime 保持独立。

日常回退不保留 Git 快照路径。Git 只服务独立的子工作树复制、成果比较与显式合入，不能因此重新进入会话初始化或 Step 收口。

当前不做完整环境虚拟化、操作系统安全隔离、挂载外副作用撤销、自动回退、模型可见版本清单、跨 Compact 恢复或证据回收。平台支持以原生构建说明为准；目录重命名、硬链接命名空间改动及其他未支持的结构变化不伪装成可恢复操作。
