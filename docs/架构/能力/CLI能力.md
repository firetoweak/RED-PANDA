# CLI 能力

CLI 提供经 Shell 组合的命令空间。子命令共享程序自己的配置、凭据和状态，通过管道、重定向或结构化输出组合；工作目录仍由模型每次指定。它与 MCP 的逐项工具契约不同，不把每个子命令包装成 Function Tool，也不另建执行器。

## 发现与调用

安装或登记成功只建立程序事实，不预生成子命令清单。加载入口只读取位置、版本与体检结果，不替模型运行程序；需要用法时通过普通命令逐层查看当前帮助。

这样把无副作用的发现与可能挂起、交互或失败的执行分开。陌生命令或未知参数先查帮助，不继续猜选项；完整方法可由 Skill 指导，不为 CLI 建另一套引导机制。

目录过长只缩减描述，不丢弃登记身份，最简目录也过长时仍以身份完整为先。体检记录帮助、版本、输出可捕获等实际表现，不作为安全或功能正确的证明，最终判断归模型。

## 调用授权

所有普通调用仍经[命令执行](执行环境.md)，每次启动按[命令授权](../入口/入口与授权.md#命令授权)处理。CLI 已登记、提供 Shell 或帮助显示只读，都不能推导整条命令已获许可；不解析命令文本建立放行名单。

外部输出只提供带来源的事实，不能改运行规则或证明用户已批准。输出清理与大文本外置复用普通命令能力，不为 CLI 建安全审查 Agent 或注入检测框架。

## 管理与环境

CLI 安装后即登记，没有额外启用状态；卸载移除登记。产品管理环境可刷新新安装位置，工作区命令仍保留独立启动环境，模型使用加载结果中的明确程序位置，安装和加载不暗改项目环境。其他新增系统环境设置可能仍需重启。

安装、更新、修复和卸载先加载管理域，再按控制提案审阅。人批准确定候选而非会移动的“最新版”，执行不能换到相近版本；版本失效就说明失败并重新提案。共享登记与安装文件修改须一致，失败不能覆盖已有可用程序。

支持两类来源：已有本地程序只登记并体检，升级由用户完成；产品下载的发布包则由产品持有安装文件。审批必须说明凭据可被命令访问，以及卸载究竟只删登记还是连下载程序一起移除。

下载发生在批准之后，按确定版本、平台和架构取发布包，在用户态解压，不改系统 PATH，不调用需提权的系统安装器。已有校验材料必须核对对应归档或文件，找不到对应对象不能跳过；无法明确定位程序就失败，不猜可执行文件。

解压、校验和定位全部成功前不替换已有安装。修复本地登记时重新定位体检，修复下载程序时仍使用原确定版本，不借修复暗中升级。手工卸载或升级可能使体检陈旧，需要重新检查，登记本身不证明程序仍健康。

CLI、MCP 与 Skill 各保留自己的生命周期，不建设统一插件框架，不接管沙箱，也不把工具批准当系统提权或凭据隔离。
