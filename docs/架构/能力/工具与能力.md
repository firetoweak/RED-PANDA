# 工具与能力

三种来源，三个端口，加上第四个 [CLI 能力](CLI能力.md)。**不要收成统一 Plugin 框架**——它们的变化原因不同，MCP 变在协议与连接，Skill 变在文本组织，环境工具变在执行面。

呈现规则见[上下文窗口与前缀稳定性](../上下文/上下文窗口与前缀稳定性.md)：工具按名称排序，SYS 与工具描述不混入动态状态，能力目录和更新通过追加事实提供。

## 归属与呈现

**归属**回答"要改变这个能力的存在和语义该找谁"，**呈现**回答"这一步能不能调用它"。两根轴独立：MCP、Skill、CLI 各有且只有一个归属域；域内的工具有的常驻、有的要先加载管理域才出现，换呈现方式不改变归属。

域只给有生命周期和目录的外部能力。环境工具由 Environment 绑定固定，没有装卸与启停，不需要域。域的数量因此不随安装量增长——上百个 Skill 压的是目录，不是域。

归属只出现在两处：模型看见的域地图与帮助，以及装配期"一个名字只有一个主人"的校验。常驻的快速通道仍属本域，地图必须把它算进本域操作，否则模型只看得见被门禁挡住的那一半。**归属不进 Runtime 调度**——Runtime 只有名字到 Binding 的平表，不认识域。

## 环境工具

读文件、写文件、管理、diff、执行命令，按当前 Environment 装配成 Runtime Binding，开工即可见。

工具返回体中的 `ok / code / error / hint` 是**领域协议**，供模型和对应 Adapter 理解，不是 Runtime 状态机协议。Runtime 不解析这些字段；Adapter 若要报告调用层失败，必须显式产生失败 Outcome，而不是依赖 Core 猜测返回的 JSON。

Adapter 只吸收它能够预期并确认的错误：领域拒绝可作为普通结构化结果，确定的调用失败显式报告失败 Outcome。只有未处理异常逃逸、Runtime 又无法确认外部效果时，才落到 `unknown`——不为异常原因扩张 Command 状态枚举。

### 变更证据的职责边界

`get_changes` 给出从代码基线到当前工作区的完整变更，并明确标出哪些内容无法读取或被截断。

它**只回答"工作区实际发生了什么"，不替模型判断任务是否完成**，也不做变更归因。模型在长对话里可能忘记主动核验变更、误以为修改已经完成——那属于[长任务](../未开始/长任务.md)的完成核验，不通过继续扩张这个工具来解决。

读取变更证据不改写用户的 Git 引用、索引或暂存。验收子的成果走[可写子会话](../运行/可写子会话.md)的独立比较入口，不扩张 `get_changes` 的职责。

## MCP（Toolset）

模型开工只看见目录和 `load_toolset`。点名成功后，**下一个 Step** 才出现具体工具。

```text
enabled MCP Server 目录
  → load_toolset("mcp:server_id")
  → Host 发现工具，绑定进 Runtime
  → 下一 Step 的 tools 才含那些 Schema
```

Runtime 不认识 MCP。**Assistant 也不另造"Toolset 已加载"内核事件**：成功的 `load_toolset` 本来就会留下普通 Outcome，其中固定记录 toolset id、revision 和完整工具契约快照。连续交互或进程恢复时，ToolSurface 从这些已提交结果投影激活集合，Provider 只用快照重建参数 Schema 与惰性句柄，不连接外部 Server；真正调用工具时才建立连接。内存中的已加载集合只是可丢弃缓存，不是第二事实源。

### Registry 与 Session 能力面分权

- MCP / Skill / CLI Registry 拥有产品当前的安装、启用、revision 与 Secret 引用；
- 每条 Session 的 Journal 拥有模型已经看见的目录 revision、目录更新和已激活的工具快照；
- ToolSurface 只从该 Session 已提交事实重建，Registry 变化不能直接增删模型当前可见的 Schema。

目录投影按 Session 过滤：仅允许只读外部能力的 Session，目录里只放声明为只读的 Server。**过滤发生在目录这一侧，不在工具出口。**源头不给整个 Server，没进目录的工具就不能加载；允许加载的 Toolset 按普通规则暴露完整工具契约，不再按内建工具名单筛一次。哪些 Session 受限由使用方决定，Toolset 这边只提供「按只读声明过滤目录」这一个能力。

新 Session 在第一次决策前提交初始 catalog snapshot。Registry revision 变化后不扫描或改写所有历史 Session：活跃 Session 在下一次决策前、休眠 Session 在下次显式输入或 resume 时，比较最后已提交的 catalog revision 并向自己的 Journal 追加确定的 catalog update。正在冻结的 Step 不受影响。

删除或更新发生在一次已冻结决策期间时，旧工具调用可以得到明确的"该 revision 不可用"失败，但**不能静默换到新 revision**。已加载快照也不因新目录删除或升级而消失。

### 管理

模型需要管理 MCP 时先调用常驻的 `load_management_tools(domain="mcp")`，从下一 Step 起才可用诊断工具并可见控制提案。

诊断工具只给 Registry 与真实连接事实，**不从 enabled 推断健康，也不返回 `next_action`**——解释事实并决定下一步是模型的事。

安装只接受未登记 ID；recovery 按冻结 revision 重测并重连，不因 enabled 跳过；配置变化必须走显式 update，不借安装暗中覆盖；删除按冻结 revision 移除登记与本地 Secret。其他 Session 不被直接改写，而是在各自下一次决策前提交 catalog update。

### 只读是安装时的声明

一个 Server 是否只读，和 enabled 同一层，在同一道安装闸门里确定，默认否。它**不是工具的属性，是这份安装配置的属性**：只读性由配置这条 transport 的人保证，混合读写的 Server 要给受限 Session 用就装两份，只读那份在启动参数或地址里带上 Server 自己的只读开关。Runtime 因此不判断任何工具是否只读，只执行一条人做过的安装决定。

不逐条判定工具，也不采信服务器自报的只读提示——前者要么靠猜要么靠模型，都不能当安全边界；后者虽然等于「信这个 Server」、和安装时已经做过的一次性信任同源，但它把只读性交还给了一个会随升级变化的自报值，而安装决定必须是冻结的。

只读声明由 Registry 拥有，不复制进 Journal 的目录或已加载工具快照。Journal 仍只记录模型所见的过滤后目录与已加载契约，恢复沿用同一套能力面机制。

测试连接时一并拉取工具清单，让这个决定在启用前有据可依。清单只用于当场呈现，**不进登记**——工具会随 Server 升级漂移，存下来就多一份要跟 revision 的东西。

鉴权 Secret 由 Application 统一抽取，明文只写入 SecretStore，Registry 只存引用。控制提案的事实形状见[入口与授权 · 控制提案](../入口/入口与授权.md#控制提案)。

## Skill

Skill 是指令包，不是执行能力。投影为两个普通工具：

```text
已启用目录通过上下文消息提供
  → load_skill(id) 返回主指令
  → read_skill_resource 读包内文本
  → 做事仍用普通工具 / MCP / execute_command
```

两个读取工具的定义保持稳定，没有启用的 Skill 时目录为空。目录变更按上面的 catalog revision 规则进入各 Session。

### Skill 管理域

Skill 包完整安装在 Agent HOME，由管理域拥有；来源只用于获取与更新，不保留任意外部目录指针。

常驻能力目录只提供管理域入口。加载管理域后提供操作地图及工具；模型可以直接选择操作，用法不明确时查询对应帮助，不要求按固定流程逐项访问。地图、参数契约和帮助引用同一份实际操作定义，不另建激活层或执行循环。

管理域的操作包含帮助、安装信息查询、包校验、安装、更新、启停、卸载，以及正文加载和资源读取。前一组在加载管理域后出现。正文加载与资源读取直接暴露为常驻工具；地图和参数契约引用这两份工具定义，不另建加载入口，也不随管理域加载才可用。

安装信息查询读取登记事实；包校验重新检查实际安装，结果只证明结构与完整性，不证明功能正确或内容安全。

安装并启用是一次用户操作，审批绑定冻结候选；审批后直接发布可用安装，不要求模型串联检查与二次启用。启停与卸载绑定审批时的安装身份，更新仍冻结候选并保持启用状态。变更在下一 Step 通过目录事实生效，启用不意味着正文已经加载。

不提供来源发现、重复的 inspect 或 repair 路径，不以模型内容审阅作为默认安装门槛。

## 不做

- 开工把全部 MCP 工具塞进扁平 Binding
- 把 Skill 做成 Toolset 或新的执行循环
- 为 MCP + Skill + CLI + 判定做统一 Plugin 基类
- 把归属做成 Runtime 的调度维度
- 用 MCP 会话的能力快照当 Runtime 内核状态
- 逐条判定工具只读，或把只读性交给服务器自报的提示
- 把发现到的工具清单存进 Server 登记
- 在工具出口按名字筛掉写工具（目录不给，出口不管）
