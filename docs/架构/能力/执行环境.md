# 执行环境

文件与命令直接作用于真实目录。产品不建立候选文件视图、操作历史或文件回退，也不追踪命令改了哪些文件；可审阅、可撤销的成果关系由 Git 承担，取舍见[AgentFS 演进回顾](../../历史/AgentFS演进回顾1018.md)。

## 文件范围与任务根

任务根由会话装配决定，执行能力只消费本次明确目录，不管理项目。长期 Bot 的个人目录始终是根，代码项目挂载在其中，见[Bot 与协作](../CodingBot/总览.md#项目归属与执行目录)；产品数据根不能用作任务根。

文件工具校验访问范围与读写权限，最具体的路径根决定权限。自己的目录可写，同事目录和已发送材料只读；开放其他宿主路径不取消明确只读边界。材料原件与工作副本见[多模态附件](../上下文/多模态附件.md)。

写文件和每次启动命令都需[授权](../入口/入口与授权.md#命令授权)，命令还校验起始目录。工具范围和批准不是操作系统隔离，不能限制命令文本中的任意路径、网络或系统安装，也不提供提权。任务要求当前没有的隔离时，应说明能力缺口，不假装已阻止。

## 命令环境

产品工具环境与工作区命令的启动环境独立。产品补全和安装路径刷新不覆盖用户项目环境，也不按助手解释器选择任务 Python；模型依据项目约定选择实际解释器和命令。

每次命令在指定目录的新子 Shell 中执行，环境变更不延续到下一次调用。用户指定环境需在每次命令落实；初始化失败不擅自换环境继续。不建立项目环境识别框架或持久保存完整旧进程环境来模拟启动。

当前只承接非交互程序，不在命令内等待 UAC、sudo 密码或硬件确认。需要时由人到工具外完成，再由模型检查条件，工具批准不能代替系统授权。[交互式资源](../未开始/交互式资源.md)仍待设计。

## 命令生命周期与后台执行

命令从启动起由 Host 持有，前后台走同一路径。前台等待到点只结束等待，不杀进程；命令仍运行就返回可寻址的后台身份，也可一开始就后台执行。不设工作区命令总运行期限，不靠 Shell 自行脱离来交接服务。

统一所有者避免超时移交产生新的崩溃窗口。转后台是原调用的终局，保证可查看输出、停止和收到后续完成通知，不表示程序成功、必然结束或服务已经就绪。

程序退出后先保存真实结果，再投递一条新的完成事实；自然结束与被停止都只接纳一次，不注入已经冻结的判断。系统不读输出判断就绪，通知到达也不证明模型已向人或同事汇报。

后台命令不延长 Worker 驻留，也不因切换会话或打断当前轮而停止。前台打断只处理仍在等待的命令，后台程序用独立停止动作结束；进程停止不能撤销已发生副作用。

命令启动前已有稳定身份。Worker 失败而 Host 仍在时只核对该身份，补交真实结果、仍在运行或尚未启动，不重新执行。Host 重启后，有可靠退出记录就补报，没有就报告未知而不重跑；未完成的前台操作也不能猜成失败。

待补报范围来自执行事实，输出记录只保存输出和退出证据，不建立第二份持久进程名册。后台命令、定时提醒和子协作各有生命周期，只复用事实接纳与幂等，不合成通用后台任务框架。

## 平台与回收边界

Host 退出要回收其受管命令及支持的子进程范围。Windows 与 Linux 覆盖受管的普通后代，回收无法确认或管理方失败必须暴露，不能当正常结束；不承诺回收系统服务代启动的程序，也不把其他命令的孤儿算进本命令。

macOS 以命令进程组为边界，主动脱离的程序不承诺自动回收。服务应保持前台模式，再由产品转后台，不能因进程组退出就声称所有后代已结束。具体平台支持与实机验证范围见[快速开始](../../../README.md#快速开始)。

## 依赖边界

文件能力与命令执行互不依赖，也不依赖 Assistant、Runtime 或工具装配。文件根由文件能力解析，执行只按明确目录和环境运行；装配层把它们接到同一任务，不能反向管理工作区或用空的沙箱状态字段声称提供了约束。

[进程沙箱](../未开始/进程沙箱.md)是独立后续能力，不重建文件历史，不代替人的授权，也不以 worktree 充当安全隔离。
