# 执行环境

任务文件范围、命令环境与产品环境的边界。产品配置另见[产品配置](../运行/产品配置.md)。包职责与依赖禁令见[架构总览](../总览.md)，执行隔离的接入方向见[进程沙箱](../未开始/进程沙箱.md)。

## 直接执行

所有会话的文件工具与命令都直接作用于任务根的真实目录。系统不建立候选文件视图、操作历史或回退，也不追踪命令改了哪些文件；可审阅、可撤销的成果关系交给 Git。模型可见的能力与限制必须和这一事实一致：工具说明直接告诉模型改动立即生效、不提供回退，核对改动用 Git。

任务根的选择与生命周期由产品装配负责。普通会话的任务根是会话绑定的工作区主根，工作区开启完全访问时再挂上 Host 根；[Coding Bot](../CodingBot/总览.md) 的 Agent 按身份绑定到已准备好的 worktree。命令执行只消费本次明确指定的目录，不创建或管理工作树。

执行环境绑定工作区文件范围和命令启动来源。工作区登记与路径范围描述任务使用的文件，不定义沙箱实例，也不规定沙箱生命周期。

## 范围与授权

文件工具校验访问范围和读写权限；命令校验启动目录的范围与权限。修改文件的工具和每一条命令都需要人授权，会话既有的自动授权总闸同样适用，见 [Command 授权](../入口/Command授权.md)。命令能做什么无法从文本可靠判断，因此不按命令名称或前缀放行。

启动目录校验和命令授权不是操作系统级文件隔离，不能承诺限制命令文本中任意路径的访问，也不能以授权代替提权。当前不提供进程、系统或网络隔离，也不约束工作区外写入。命令继承本机环境，安装到用户环境、修改系统配置及访问网络可能真实生效，不能描述为系统已经阻止，也不能承诺撤销。任务要求当前没有的隔离保证时，模型应停止相应执行路径并说明能力缺口。

执行只承接非交互程序，不承接 UAC、sudo 密码或硬件确认。需要这类交互的步骤由用户在工具外完成，用户告知完成后再检查条件；不增加命令内等待人工、自动提权或代确认通道。工具授权不授予系统权限，也不构成身份认证。

## 命令环境

产品进程环境与工作区命令环境具有独立来源。Host 对产品内部工具补全本机环境，不改写工作区命令的启动来源；命令执行按给定环境查找 Shell，不猜测项目环境，见[多活跃会话 · 进程身份](../运行/多活跃会话.md#进程身份)。

RED PANDA 自身的运行依赖、内部工具及 CLI 管理使用产品环境。工作区命令使用独立的启动环境，不随产品工具的安装路径刷新而改变，不根据助手的解释器选择任务 Python。模型依据项目约定和用户要求选择解释器、环境管理器与执行命令；命令执行能力负责执行明确的命令，不判断项目语言或代替模型选择环境。

每次命令在请求目录中的新子 Shell 内执行，环境变更不改写 Worker，也不延续到下一次命令。用户指定环境由模型在每次命令中落实，交接规则见 [Compact](../上下文/Compact.md#窗口和来源)。初始化失败不擅自换用其他环境继续执行。

不建立工作区环境配置表、会话环境设置工具或环境管理器识别框架，不持久化完整进程环境来复现旧启动。已登记 CLI 经工作区命令调用时仍使用工作区命令环境，其安装管理不改变这条边界。

## 持续进程

前台命令有界等待，结束、超时或取消时回收任务进程树。Windows 和 Linux 另提供宿主持续进程：明确启动后可跨工具调用运行，具有会话所有权，可查询状态、读取输出并停止整棵进程树；不会随前台命令或空闲 Worker 的结束而回收。启动成功不代表服务已就绪，进程退出不自动重启。启动持续进程与执行命令一样需要授权。

持续进程由 Host 持有，切换会话或暂停任务不停止它；明确停止、归档所属会话或应用退出时回收并确认进程树结束。Host 重启不恢复程序或进程记录。

Linux 的持续任务各自拥有独立的子进程回收上下文，包含脱离原进程组的普通后代；不能把共享 Host 下新出现的孤儿进程一概当作某个任务的后代。Host 意外退出后，任务管理方仍须收尾。无法确认回收及管理方自身故障必须暴露，不报告为正常结束；不承诺管理系统服务代启动的进程，也不提供操作系统级执行隔离。

## 工作区与材料

`RedPandaHome` 只表示产品自身的数据目录，**不能充当任务 Workspace 根**。工作区清单是独立的产品级文件，会话与工作区的绑定是一条会话级事实。从清单删除工作区只移除登记，不删除工作区目录或会话 Journal；绑定到它的会话不再列出，与存量无归属会话采用相同规则。

Session 已发送文件的材料视图作为独立只读根加入执行环境，见[多模态附件](../上下文/多模态附件.md)。

## 依赖边界

文件能力与命令执行互不依赖，也不依赖 Assistant、Runtime 或 Tools；Runtime 不认识文件、执行环境或沙箱；Tools 通过文件与执行能力的窄契约提供模型入口，装配层负责把二者接到同一任务根。

文件工具直接消费文件范围与访问权限，不依赖 Shell 或命令执行。命令工具分别消费文件访问与命令执行能力：前者解析本次启动位置，后者按给定目录和环境执行。工作区注册与宿主文件根发现属于文件能力，命令执行不据此反向管理工作区。不以没有实施效果的网络或沙箱状态字段表示已提供约束。

## 不做

- 不为文件修改提供系统内的历史与回退；撤销靠 Git 或人自己。曾经的候选执行与回退已整体移除，取舍见 [AgentFS 演进回顾](../../讨论/AgentFS演进回顾1018.md)。
- 不按命令文本区分只读与写入、不维护命令放行名单。
- 不预建通用沙箱接口；当前没有沙箱的创建、接入或销毁流程。
