# 执行环境

任务文件范围、命令环境与产品环境的边界。产品配置另见[产品配置](../运行/产品配置.md)。包职责与依赖禁令见[架构总览](../总览.md)。

本文规定工作区、任务文件视图与命令执行的接合。受管文件状态与操作历史归[Agent 文件系统](../Agent文件系统/总览.md)，执行隔离的接入方向见[进程沙箱](../未开始/进程沙箱.md)。

## 执行环境

执行环境绑定工作区文件范围和命令启动来源。工作区登记与路径范围描述任务使用的文件，不定义沙箱实例，也不规定沙箱生命周期。文件操作与恢复的规则见[文件操作与回退](../Agent文件系统/文件操作与回退.md)。

任务文件在该会话绑定的工作区主根，工作区开启完全访问时再挂上 Host 根。

文件访问方式与进程生命周期是独立契约。受管命令接入 Agent 文件系统，承诺指定受管范围内的文件变化具有证据并可恢复；宿主命令直接使用真实文件，不依赖文件服务、挂载或任务 hook，也不提供文件回退保证。两者复用命令执行能力，不能根据命令名称猜测应选哪一种；受管接入失败不得自动降级为宿主执行。

Assistant 装配可以明确选择受管文件视图或直接使用指定的真实目录。直接目录下，文件工具继续校验访问范围和权限，命令复用宿主执行能力；不建立 Agent 文件系统历史，也不提供依赖该历史的变化归因与回退工具。命令授权与文件历史分开，使用自己的目录不代表命令获得本机或网络访问的自动授权。模型可见的能力与限制必须和实际装配一致。

现有 Web 会话与 TUI 仍使用受管路径。[Coding Bot 骨架](../CodingBot/总览.md) 按 Agent 身份将执行根绑定到已准备好的 worktree，直接使用真实目录；Git 历史与子任务成果交换尚未接入，因此当前不提供委派工具。不得借用旧子任务路径重新引入 Agent 文件系统，也不因直接目录执行失败自动切换到受管路径。

宿主执行仍保留启动目录的范围、读写权限及工具授权检查，可能写入的宿主命令须经授权；会话既有自动授权规则同样适用。启动目录校验和命令审批不是操作系统级文件隔离，不能承诺限制命令文本中任意路径的访问，也不能以宿主执行代替提权。

受管路径下，任务根中的修改工具访问和可能写入命令的启动目录投影到独立候选文件视图，只读文件工具与只读命令查询已发布工作区。逻辑工作区位置与临时挂载位置分离，模型和 Web 展示逻辑位置；读取与发布的互斥、文件变化及恢复由 Agent 文件系统管理，见[文件操作与回退](../Agent文件系统/文件操作与回退.md)。绝对命令参数、Host 根和材料根不因 cwd 投影而获得操作系统隔离。

上述分流以整次操作为单位：可能写入的操作以挂载视图为实际任务根，操作内读写同一视图。Windows 受管任务命令另强制宿主拒写约束，其他平台尚未接入。细则见[命令文件视图接入](命令文件视图接入.md)。

任务根的选择与生命周期由产品装配负责；命令执行只消费本次明确指定的目录，不创建或管理 Agent 的工作树。

产品进程环境与工作区命令环境具有独立来源。Host 对产品内部工具补全本机环境，不改写工作区命令的启动来源；命令执行按给定环境查找 Shell，不猜测项目环境，见[多活跃会话 · 进程身份](../运行/多活跃会话.md#进程身份)。

RED PANDA 自身的运行依赖、内部工具及 CLI 管理使用产品环境。工作区命令使用独立的启动环境，不随产品工具的安装路径刷新而改变，不根据助手的解释器选择任务 Python。模型依据项目约定和用户要求选择解释器、环境管理器与执行命令；命令执行能力负责执行明确的命令，不判断项目语言或代替模型选择环境。

每次命令在请求目录中的新子 Shell 内执行，环境变更不改写 Worker，也不延续到下一次命令。用户指定环境由模型在每次命令中落实，交接规则见 [Compact](../上下文/Compact.md#窗口和来源)。初始化失败不擅自换用其他环境继续执行。

不建立工作区环境配置表、会话环境设置工具或环境管理器识别框架，不持久化完整进程环境来复现旧启动。已登记 CLI 经工作区命令调用时仍使用工作区命令环境，其安装管理不改变这条边界。本机执行仍不提供操作系统级隔离。

当前不提供进程、系统或网络隔离，也不约束所有工作区外写入。命令继承本机工作区环境，安装到用户环境、修改系统配置及访问网络可能真实生效，不能描述为系统已经阻止，也不能承诺用文件回退撤销。模型应获得这些可观察限制；任务要求当前没有的隔离保证时，应停止相应执行路径并说明能力缺口，不把文件视图视作完整沙箱。

前台命令有界等待，结束、超时或取消时回收任务进程树。Windows 和 Linux 另提供宿主持续进程：明确启动后可跨工具调用运行，具有会话所有权，可查询状态、读取输出并停止整棵进程树；不会随前台命令或空闲 Worker 的结束而回收。启动成功不代表服务已就绪，进程退出不自动重启。不承接跨调用持续访问候选文件视图的进程。

持续进程由 Host 持有，切换会话或暂停任务不停止它；明确停止、归档所属会话或应用退出时回收并确认进程树结束。Host 重启不恢复程序或进程记录。程序自行产生的文件变化不自动进入 AgentFS 历史；宿主开发服务器可观察受管编辑写回及回退后的文件变化，回退可能触发重新加载，不承诺运行行为不变。

Linux 的持续任务各自拥有独立的子进程回收上下文，包含脱离原进程组的普通后代；不能把共享 Host 下新出现的孤儿进程一概当作某个任务的后代。Host 意外退出后，任务管理方仍须收尾。无法确认回收及管理方自身故障必须暴露，不报告为正常结束；不承诺管理系统服务代启动的进程，也不提供操作系统级执行隔离。

执行只承接非交互程序，不承接 UAC、sudo 密码或硬件确认。需要这类交互的步骤由用户在工具外完成，用户告知完成后再检查条件；不增加命令内等待人工、自动提权或代确认通道。工具授权不授予系统权限，也不构成身份认证。

`RedPandaHome` 只表示产品自身的数据目录，**不能充当任务 Workspace 根**。工作区清单是独立的产品级文件，会话与工作区的绑定是一条会话级事实。从清单删除工作区只移除登记，不删除工作区目录或会话 Journal；绑定到它的会话不再列出，与存量无归属会话采用相同规则。

Session 已发送文件的材料视图作为独立只读根加入执行环境，见[多模态附件](../上下文/多模态附件.md)。

Agent 文件系统与命令执行不依赖 Assistant、Runtime 或 Tools；Runtime 不认识文件版本、执行环境或沙箱；Tools 通过文件与执行能力的窄契约提供模型入口。装配层负责把指定的文件视图和命令执行接合，不将进程管理纳入文件系统。

文件工具直接消费文件范围、访问权限及当前文件视图，不依赖 Shell 或命令执行附件。命令工具分别消费文件访问与命令执行能力：前者解析本次启动位置，后者按给定目录和环境执行。工作区注册与宿主文件根发现属于文件能力，命令执行不据此反向管理工作区。不以没有实施效果的网络或沙箱状态字段表示已提供约束。

## 沙箱与生命周期

沙箱的组合方式与生命周期边界见 [Agent 文件系统总览](../Agent文件系统/总览.md#与沙箱的组合)。执行环境释放时，先终止仍可能写入任务视图的受管进程并等待文件操作静止；当前没有沙箱的创建、接入或销毁流程，不预建通用沙箱接口。
