# 命令文件视图接入

Windows 任务命令采用实际任务路径与进程 hook，保持按操作读写分流。这是普通开发工具的受管执行约束；其他平台的 hook 和完整沙箱不在当前保证内。

## 不变量

读写按整次操作分流：独立只读操作读取宿主中已发布的文件，遵守文件系统既有的读写协调；可能写入的操作使用挂载文件视图，其内部任务文件的读和写都使用该视图，保证写后能读到自己的修改。视图中未修改的文件可以由 VFS 从宿主基底读取。这不是把同一操作中的读请求发给宿主、写请求发给挂载，也不要求所有只读命令进入挂载。

可能写入的命令以指定挂载视图作为实际任务根，在其中启动。相对路径和由当前目录生成的绝对路径按实际挂载位置解释；宿主编辑器继续访问真实工作区。挂载任务根与宿主工作区各有自己的路径身份，不要求同一绝对路径在不同进程中透明指向不同内容。Windows 使用现有 WinFsp 文件视图，其他平台遵守相同职责边界。

hook 的目标是阻止受管任务进程直接写入宿主工作区，适用于只读和可能写入的任务命令。命令使用宿主工作区的绝对路径写入时明确失败，由调用方按实际副作用选择操作类型并使用当前任务位置；不悄悄把它改写成挂载路径。只读声明不构成直接修改宿主任务文件的许可。该约束服务于普通开发工具的受控执行，不承诺抵御恶意程序主动绕过用户态拦截。更强的执行隔离由独立沙箱提供。

所需 hook 应在用户命令执行前生效，并延续到受支持的任务子进程。必要 hook 或本次操作所需视图未成功接入时，不启动用户命令，也不退回仅设置 cwd 的执行路径。具体支持范围须先通过实际开发工具验证，不能从主进程接入成功推导整个进程树都受约束。

任务进程使用期间，挂载位置必须保持有效。执行能力先结束并回收所有受管任务进程，确认不会继续写入后，文件系统才能结束相应文件操作并释放挂载。文件工具与命令应对本次操作的任务文件位置保持一致理解；跨命令挂载路径的有效期仍需在具体设计中明确。

模型获得实际命令启动目录、可观察的写入限制与失败后的下一步动作，不需要理解挂载、hook、内部存储或操作阶段。命令内使用相对路径或从当前目录生成绝对路径；文件工具继续使用工作区位置。命令启动目录不承诺跨调用有效，不能把它与宿主目录当成可互换的位置。

启动约束故障与应用退出具有独立来源，不根据某个退出码猜测接入是否成功。应用尚未放行时失败，明确返回未启动；执行中无法维持约束时停止任务并保留部分输出，实际副作用仍需核对。无法确认进程回收、内部协议损坏和未知内部错误必须暴露，不能降级为普通命令失败。

写入边界与平台后端分开。拒绝写入的根始终是宿主任务根；可能写入的命令以本次挂载视图为启动目录；约束接不上就不启动。这条边界是平台中立的。当前后端是 Windows 的进程 hook。Linux 尚未接入自己的后端，只设置启动目录不能当成同一条约束。

路径是否落在宿主任务根内，按同一条路径身份判断：解析后的最终路径，加上硬链接的其他名字。junction 与扩展路径前缀先收成这条身份，不为每一种别名再加拦截点。进程创建也只有一条准入：受支持的前台创建，并在放行前把约束交给子进程。其余创建请求拒绝。新的绕过先收紧身份或准入，而不是继续增加拦截入口。

Windows 当前受管执行面为普通本机 x64 工具及其受支持的子进程。支持的创建路径传递本次约束，其他进程创建请求明确拒绝；不能让未接入的子进程继续执行。调试、显式挂起和脱离任务进程组不属于当前前台命令契约。不承诺限制代理服务替任务执行的操作，也不抵御恶意进程直接绕过用户态 API。

产品 CLI 安装与体检没有会话任务根，不使用工作区拒写策略；其环境来源和进程回收仍归执行能力。这个入口不能成为任务命令接入失败后的替代路径。

## 职责边界

Agent 文件系统拥有视图、实际文件变化证据、审阅、恢复与成果交换，并管理原生文件服务及挂载的生命周期。hook 不维护另一套文件变化历史，也不根据访问日志推测文件最终结果。

执行能力消费指定视图，拥有命令 cwd、hook 的接入与写入约束、任务进程树、结果收集和取消。原生文件服务虽然也是进程，其生命周期仍归文件系统；Host 的 Worker 生命周期仍归 Host。不能仅按“有没有进程”拆包。

Sandbox 独立拥有更强的资源、网络和文件访问限制；本轮命令接入不以外部沙箱存在为前提，也不新增通用沙箱框架。当前实现与沙箱边界见[执行环境](执行环境.md)和[进程沙箱](../未开始/进程沙箱.md)。

## 已经排除的做法

- 继续以 Silo / Bind Filter 直接连接当前 WinFsp 挂载作为 Windows 接入前提，或使用全局路径替换影响宿主进程。
- 仅改 cwd 就宣称旁路写入已受约束，或将用户态 hook 宣称为不可绕过的操作系统安全边界。Linux 尚未接入后端时，不能把只设置启动目录写成与 Windows hook 对等的约束。
- 为新的绕过继续增加拦截入口，而不先收紧路径身份或进程创建准入。
- 在命令字符串中猜测和替换文件路径，或把宿主绝对路径透明改写成挂载路径。
- 将同一可能写入操作中的读请求导向已发布宿主、写请求导向挂载，造成写后读取旧值；或为统一路径强制所有独立只读操作进入挂载。
- 用 hook 重做 VFS 的文件证据、存储和回退，或通过事后扫描宿主目录弥补未捕获的写入。
