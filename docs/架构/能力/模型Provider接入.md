# 模型 Provider 接入

模型调用使用窄接口，Worker 通过 Host 复用按 Provider 管理的客户端，不直接连接供应商，也不引入外部网关进程或进程内路由器。

## 分工

独立的 thinllm 层拥有供应商表、流式协议、调用结果与错误类型，只回答给定模型和连接怎样发起调用，不依赖 konden。konden 负责会话选择、请求与图片装配、连接配置以及面向用户的错误说明，Agent 循环与上下文仍留在应用侧。

拆分让供应商协议增长保持局部，不把 thinllm 建成通用网关。模型标识明确选择供应商与原始型号，不做隐式路由；内置供应商的地址和协议差异属于代码，本地服务地址与凭据属于个人连接。

供应商型号目录是当前连接下的外部事实，只帮助人选择，不能复制成另一份会话偏好或进入 Runtime 调度。按实际需要局部接入，失败明确展示，不用静态型号表兜底；模型容量与压缩阈值是不同概念。

## 连接生命周期

连接在每次调用边界读取，相同设置复用客户端；设置变化后新调用用新连接，在途请求继续用旧连接，最后一个请求结束才释放。配置损坏不能被旧连接掩盖，也不要求人靠重启同步，见[模型与配置](../入口/模型与配置.md)。

Codex 授权可只读复用已有登录，也可由终端完成新的 OAuth 登录并独立保存、按需续期。同一授权的续期要协调，不能部分覆盖；借用 Codex 登录时其生命周期仍归 Codex，不复制或刷新共享凭据。配置状态查询不启动授权，授权流程与凭据不进入模型执行内核。

## 协议边界

客户端转换流式正文、推理、工具调用与用量，不执行工具。具体供应商差异只对实际遇到的协议要求生效，不能推广到未知型号或回写原始执行事实。

原生推理随所属消息保存和回放，压缩时与旧消息一同移出窗口，不另设只留最新思考的裁剪策略。是否发送历史推理由具体协议决定，不能把历史推理保留等同本轮强制思考，也不能改写成正文。

OpenAI API 与 Codex 共用 Responses 协议，认证方式各自独立；其他供应商按其已支持的协议接入，不因为地址兼容 OpenAI 就推断能力一致。Responses 的原生输出按原顺序保存和回放，保留推理、工具调用与正文阶段的关联；不从拼接后的正文重新猜测这些关系。工具参数的可选性由应用契约决定，不随上游协议的默认严格模式改变。

图片只在请求边界编码，流式预览不成为执行事实；只有完整有效的模型结果可参与决策提交。

## 失败与重试

只有明确识别的认证、上下文超限、暂态传输、服务错误和无效响应才转为相应调用失败，未知内部异常原样暴露，不猜错误文案。

暂态失败只在响应尚未收到任何字节时有限重试。流已开始后，内容可能已展示，失败就原样交回决策失败路径，不能重启调用拼成看似完整的答案。

不做跨 Provider 兜底、负载均衡、熔断、计费或通用模型推荐，不在配置开放任意供应商协议。已有环境的确定适配留在窄边界，不保留废弃 SDK、路由器或网关启动路径。确需复杂路由时，可将外部兼容网关作为一个明确供应商接入。
