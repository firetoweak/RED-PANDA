# 架构总览

本文说明整体结构、分工与设计理由。[运行语义规约](运行语义规约.md)规定跨层运行状态的共同不变量，是相关设计与评审必须对照的规范；各专题说明具体机制。

用户价值见[产品定位](../产品定位.md)，尚待解决的问题见[后续方向](多智能体/方向.md)。

## 运行模型

konden 以长期 Bot 的持续时间线承接协作。每个 Bot 对应一条 Session；人的消息、同事往来、执行结果与定时触发都进入这条生命线，靠上下文压缩继续工作。

> Event 是已经提交的执行事实，State 是事实的确定性归约，Step 是一次模型决策，Command 是外部副作用闭环。

```text
外部输入 → Event → State → Step → Command → Outcome → Event
```

Journal 保存完整事实。模型所见上下文、人看到的对话与执行过程都是投影，不能反过来拥有执行状态。任务是否完成由人或模型判断；Session 不因一次回复结束而进入绝对终态。状态归类和所有权见[运行语义规约](运行语义规约.md)。

## 分工

| 部分 | 负责什么 | 边界 |
|---|---|---|
| Runtime | 持久事实、状态归约、原子决策与命令派发约束 | 不理解目标、工具领域语义或协作内容 |
| Assistant / Host | 模型决策与上下文、会话进程、长期身份、通信和产品装配 | 不代替模型判断任务完成，不复制 Runtime 状态 |
| Channel | Web、TUI 的人的输入输出与授权；外部协作者经 MCP 接入 | 不拥有模型执行循环，外部消息不能产生人的授权 |
| 模型接口 | Provider 协议转换、连接与调用 | 不管理工具执行或 Agent 循环 |
| 文件与命令执行 | 明确范围内的文件访问、按指定目录与环境执行命令 | 两者独立，不管理协作，不提供系统内文件回退 |
| MCP、Skill、CLI | 各自的外部能力、指令包和命令行工具生命周期 | 各用窄端口，不合成通用插件框架 |

每个活跃 Session 由独立 Worker 承载；同一数据根只有一个 Host，Web 是常驻入口，TUI 使用独立数据根。进程隔离使一个会话的阻塞或异常不拖住其他会话，不等于操作系统安全沙箱。模型连接由 Host 按 Provider 复用。

Bot 的稳定身份、个人目录与代码项目分开。没有项目也能对话、私信与建群；需要编码时挂载独立 Git worktree，成果由实际 Git 提交与合并关系表达。所有文件与命令直接作用于真实目录，不另建文件视图、历史或回退层。

## 设计原则

[AGENTS.md](../../AGENTS.md)保留执行时必须遵守的短约束，本节解释设计理由与取舍。

**模型交互边界优先。** 模型看不到系统内部实现。Prompt、工具描述、参数说明、提示与返回只表达可观察行为、参数选择、使用限制和下一步动作，不暴露内部锁、候选、发布、存储或调度机制，也不要求模型猜测这些机制。身份、范围和引用关系必须从实际可见信息中明确取得，不能靠解释内部实现弥补交互缺口。

**机械保证归系统，语义判断归模型。** Runtime 只做确定性的事实归约、调度、不变量和安全边界。目标是否满足、证据意味着什么、找谁协作或下一步做什么，由模型或用户明确作出。

**单一事实源。** 每种状态只有一个所有者，其他层只能读取、投影或缓存。运行事实先提交再进入判断，投影、缓存、Checkpoint 和摘要不能代替或反写权威状态。产品当前值与会话当时的观察是不同对象，不能靠同步或恢复让两者争夺同一状态，具体归属见[运行语义规约](运行语义规约.md)。

**按变化原因组织。** 高内聚让同一类变化集中，低耦合让一个需求少扩散。已遇到的需求局部设计并验证；明确的后续需求只保留接入方向；想象中的可能性和未知第三方需求不提前抽象。能力应能独立删除，不在 Runtime 遗留其名词和生命周期；基础能力优先复用成熟标准库、接口与工具，产品只承担必要的业务适配、权限边界和结果组织。

**渐进加载。** 常驻层只给最小执行面、能力目录与加载入口。具体工具和 Skill 正文按任务读取，成功加载成为已提交事实后才影响后续决策。不为调用方便或前缀缓存把全部能力提前铺给模型。

**内部相信契约。** 外部输入在边界精确校验，只转换语义明确的已知外部错误；内部违规、持久化损坏和未知异常原样暴露，不用缺省值、强转或宽泛捕获掩盖。操作和清理同时失败时保留两者；文件不存在与文件损坏不能混为一谈。

**替换设计时删除旧路径。** 不为废弃契约保留兼容层、双轨或隐式兜底，废弃实现及其专属入口、配置和测试随替换一起删除，不以迁移便利延续过期设计。当前支持的平台和协议仍使用明确适配，这与保留旧设计不同。

**安装与执行内核分开。** 产品准备运行依赖和应用工具，日常启动复用它们，不修改系统 PATH 或安装系统组件。开发者自行选择开发环境，工作区项目的命令环境不被产品环境覆盖；模型连接可在启动后配置。操作见[快速开始](../../README.md#快速开始)。

## 验证原则

**测试必须有独立保护价值。** 优先复用、修改已有用例，新增测试应说明它防止哪种错误及其实际后果。测试保护尚未被覆盖的产品行为、外部边界和关键不变量，在能证明该行为的最低成本层验证。状态转换、幂等和结果归约优先进程内；真实进程只证明跨进程才能证明的行为，真实模型质量另行评测。

断言可观察结果，不约束无关的私有布局和调用次数；只有内部顺序本身影响正确性时才约束它。标准库保证、简单转发、纯重构、重复装配与废弃实现不机械新增或保留测试，不按测试数量或覆盖率评价完成度。

测试代码不进入生产目录，不为维持旧测试或制造可测性增加防御分支、兼容路径或专用生产接口。替换实现时，仍适用的行为继续受测试保护，废弃设计专属的用例同步删除。

本地与 CI 共用验证入口。PR 和主分支采用相同的完整合入检查；失败保留原始结果，不靠自动重试、跳过或忽略错误变成通过。具体命令与矩阵以[验证脚本](../../scripts/ci.py)和 [CI](../../.github/workflows/ci.yml)为准，自动检查不替代业务验收。
