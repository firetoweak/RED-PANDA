# Command 授权

解决"工具副作用需要用户确认"的交互。与 Control Approval（批准安装、更新等管理提案）分离，**两者变化原因不同，不抽象成通用审批框架**。控制提案见[入口与授权 · 控制提案](入口与授权.md#控制提案)。

## 授权判定不产生副作用

每个 Command 签发时经授权判定得出 verdict（`allow` / `ask`）或明确拒绝，随 Command 冻结。判定依据工具、参数与装配的权限边界，不产生副作用。文件写工具在请求确认前只读检查路径权限；明确不能写的目标冻结为拒绝结果，不调用写入函数，也不让人批准一个权限不允许的操作。拒绝之后路径状态变化或进程重启都不能把它变成免审批写入。允许请求确认的命令在真正写入时仍重新检查权限，批准不扩大访问范围，也不保证路径状态不变。

- 修改任务根文件的工具需要确认，只读工具不需要。
- `execute_command` 每次启动命令都需要确认，包含立即转后台的调用——命令会做什么无法从文本可靠判断，不按命令前缀放行，见 [CLI 能力](../能力/CLI能力.md#调用授权)。
- 子 Agent 与父共享工作区，文件写入和命令沿用相同授权。子请求在所属父 Bot 下呈现，人的决定仍绑定实际子调用；父委派或转述不构成授权。见 [SubAgent](../运行/SubAgent.md#能力与授权)。

判定函数随工具 Binding 注入，Runtime 只消费 verdict，不理解规则含义。

授权是**正交的派发 gate**：Command 的执行生命周期只描述跑到哪一步，是否派发由授权事实和拒绝事实决定，两者互不代替。

## 全局总闸

自动放行表达用户对所有会话共用的工具授权选择，现有会话与之后创建的会话使用同一策略。当前实验阶段默认开启；后续细化放行规则，不以会话选择代替规则。

它是 **全局产品偏好，不是任务事实**，所以由 Host 持有、不进 Journal，模型无需知道。用户修改后持久保存；新会话与重启恢复都继承当前选择。Worker 不读写这份元数据，只收 Host 推来的确定值。

**owner 选择只负责驻留和回复路由，不参与授权。** 切换私聊、群聊、页面连接或无人选择时，授权策略保持相同。

verdict 为 `ask` 时：总闸开启则 Host 为该 Command 追加明确授权事实；总闸关闭则等待显式批准。TUI 的 yes/no 一次性处理当前全部待授权命令，Web 按单个 command 处理。**没有任何入口在线时也不会替人改变总闸或伪造批准。**

自动放行在每次推进提交之后立即执行，不等 Session 静止；Host 同步 Session 策略时再补一次。若等到静止才放行，同时到达的新事实会让下一次决策先看到这条命令“在等人授权”，模型据此去找人要授权、又重发同一条命令，放行后两条一起执行。真正允许派发的始终是 Journal 中对应 command 的授权事实。

## 状态归约

工具展示状态里只有 `running` 是可丢弃的活动叠加，其余全部来自 Journal 投影。基础状态按单个 command 归约，顺序固定：

1. 有 Outcome → 成功 / 失败
2. 出现在拒绝事件里 → 已拒绝
3. 在待授权集合里 → 等待授权
4. 已有 Attempt 且无 Outcome → unknown
5. 尚无 Attempt → 排队中

Host 另以精确 command 身份提供活动叠加：只有 Worker 明确报告该 Command 正在执行时，Channel 才把排队或 unknown 临时画成 running。**Session 级 running / idle 不参与单个 Command 的判定。**

自动放行开启时，尚未写入授权事实的调用仍按原有规则等待派发，但对人展示为排队，不作为需要人决定的待授权事项；对话、待处理条与名册遵守同一选择。控制提案仍需人确认。

Worker 报告执行函数已经返回也不能产生终态——终态必须等 Outcome 提交后由 Journal 投影，实时事件只负责提示 Channel 重拉。刷新后等待、拒绝和终态从 Journal 恢复；总闸不在 Journal 里，走 Host 元数据。

## 拒绝语义

用户拒绝某次工具执行，**不是**把工具从可见 schema 中移除。模型仍看得到工具，只是明确知道"这次调用被用户拒绝"，从而避免困惑、不会原样重试。

投影层为被拒绝的调用生成一条对应的 tool 消息，保证每个 tool_call 都有配对回复（Chat Completions 协议完整），并在文本里明确这是**用户拒绝**而非工具失败或超时——两者会导向完全不同的下一步。

## 设计决策

- 总闸是全局产品偏好，不是任务事实，所以不进 Journal；不保留各会话独立选择的双轨语义。
- 创建时不把入口默认值落盘。
- TUI 同样拦截 ask：授权是防误操作的边界，误操作在任何入口都是误操作。
- 被拦命令的完整参数（含 `execute_command` 的命令文本）要出示给用户，否则他确认的是一个看不见的对象。
