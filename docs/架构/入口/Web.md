# Web

Web 是唯一的常驻 Host 入口，以后的长期 Agent 与 Agent 间消息都挂在它上面，见 [Channel 接入契约](Channel接入契约.md)。浏览器只经 Web 后端使用 Assistant 应用操作与查询，不直接读 Journal，也不承担 Session 恢复。

状态归类与所有权按[运行语义规约](../运行语义规约.md)，入口通用约束见 [Channel 接入契约](Channel接入契约.md)。本文只记 Web 特有的边界决策。

## 使用边界

当前面向本机个人使用，不提供登录鉴权、多用户身份与权限隔离，也不建设完整访问安全审计。连接身份、会话归属和工具批准只服务当前交互流程，不能当作调用者认证或多人共享服务的安全边界。需要多人或不可信网络访问时，先满足独立的认证与隔离条件，不把现有 Web 入口视为已经具备这些能力。

## 三层前端状态

服务端投影、Session 瞬时活动（preview、live tool、未读）、纯 UI 本地态（输入框、滚动、折叠、侧栏宽度）分开存放，不互相冒充。当前失败由 Host 持有，浏览器通过查询与实时通知呈现。

侧栏在前台与后台使用相同的执行标记。过程输出不作为需要操作的提醒；待授权、待确认或需要重试的失败才显示操作提醒，查看会话不替代处理。执行静止后尚未查看的结果使用独立标记，不将其解释为任务完成证明。

前端活动叠加必须可丢：刷新后由已提交事实与 Host 当前状态补齐，不跨服务重启恢复。它只能临时叠加在正式投影之上，不能把 Journal 的 `unknown` 推成终态，也不能覆盖已提交的终态。

上下文用量来自当前上下文窗口最近一次已提交的模型调用记录，打开历史会话时直接读取，无需启动 Worker。实时通知只要求前端刷新投影，不另存一份权威用量。窗口切换后尚无调用记录时，用量保持未知，不能沿用旧窗口的数值或显示为零。

一次性定时等待由 Automation 的待触发记录投影到会话视图。前端用绝对到期时间本地计算倒计时；到期与否不由浏览器裁决，定时事实由 Host 投递。倒计时归零不表示模型已经检查完。

Agent 的例行任务列在同一位置，与倒计时同属「接下来会发生什么」：名字、时间表、谁暂停的与下一次运行时间，没有例行任务时不占位。人可以暂停、恢复与取消，取消要二次确认；人暂停的只能由人恢复，这条规则在 Host；界面对两种暂停都提供恢复，只标明是谁暂停的。列表数据直接读 Host 的例行任务记录，变化沿用定时的变化事件重读，浏览器不推算下一次时间，也不判断是否到点。

## 实时事件只叠加，不裁决

工具终态一律来自已提交的 `CommandOutcomeReceived`。Worker 报告"执行函数返回了"不产生成功或失败，只提示前端重拉。

`running` 必须来自 Worker 精确报告的同一个 `command_id`，且只盖在 Journal 的等待态上；Session 级 activity 不参与单个工具的状态判断。精确活动一旦丢失，回到 Journal 的 `unknown`。

Host 是对外 activity 的唯一所有者。Worker 正常静止、已识别失败、未知崩溃或 generation 被接管，都必须由 Host 结束旧 generation 的 running、中止活动 preview、清掉 live tool 叠加并要求前端重拉；这些是展示清理，不能补写 Command Outcome。

已识别的模型失败和进程失败不写 Journal，也不新增持久错误历史；Host 在自身生命周期内保留当前失败，刷新页面或重新选择会话仍能查询原因。界面明确执行已停止；仍有待处理输入不表示正在执行。查询与选择不自动重试失败的请求；用户明确再试时继续原待处理输入，不新增消息或重复已完成工具。新输入仍按既有规则推进，重新开始执行后清除旧失败。压缩 reader 进程的失败不冒充用户会话失败。

错误默认收起为简短提示，完整原文在按需打开的内容页中查看和复制，不能挤占时间线而阻断历史浏览。收起详情只改变展示，不清除失败或触发重试。

文件改动、子 Agent 观察和错误详情共用会话旁的内容页位置，一次展示一种内容；顶层负责切换、关闭与区域宽度，各页保留自己的数据和交互。文件改动页只对 Agent 及其委派的子任务提供，内容是该分支的 Git 差异，其他会话不提供；页面以差异正文为主体，右侧目录可收起，目录与正文独立滚动。时间线不提供可回退的步骤。打开内容页不选择或唤醒会话，关闭也不取消执行；窄窗口在同一区域切换聊天与内容页。

## 入口错误语义

入口只把语义明确的已知错误换算成 4xx/503 状态码。响应带具体原因，Web 原样展示，不把原因吞成通用文案。

不把未知异常或内部契约违规收编成普通 4xx：它们继续原样暴露，浏览器看到的是失败，不是被修饰过的成功。

## 页面连接与 Session 选择解耦

页面 SSE 分配瞬时 connection identity，映射为 Host owner。切换会话只改 owner 选择和中间栏，不取消仍在运行的 Session，也不打断后台工具。断开只释放 owner，不影响投递。

## Agent 名册与工作区

侧栏按项目列 Agent，不列普通会话。Web 没有新建普通会话、改标题或归档的入口，后端也不保留这些接口；即开即用的单次会话由 TUI 承担。创建一个 Agent 要选定已登记的项目并给出名字。项目必须是带首个提交的 Git 工作树根，名字在项目内唯一，区分大小写，不能带首尾空白。调用方不能指定工作树或分支。已知的重名和 Git 条件失败原样返回原因。创建成功后打开该 Agent 的会话。

名册状态只归约已经存在的事实：Worker 在跑或仍有子任务是「干活」；有待授权或待确认是「等授权」；停在等外部事实，或当前有失败，是「等人回话」；否则是「空闲」。不另建处境判断。已声明的负责方向原样显示。内部工作树路径和分支不出现在名册里。

打开首页或某个项目页不自动新建会话。还没有项目时，主区域引导先登记工作区。

输入文字按会话保存在浏览器本地。切换、刷新或关闭页面后可恢复文字，发送成功后才清除；发送失败继续保留。附件不跨页面恢复。停放内容的文字恢复到编辑栏，由用户重新确认发送，不恢复自动发送意图。这些都是 UI 草稿，不成为执行事实。

工作区目录由用户显式选择。目录选择窗口属于本机 Web 交互，选择结果只回填表单；确认创建前不登记工作区、不产生任务事实。窗口在独立进程中运行，等待用户选择不阻塞 Web 服务；取消不改变表单，缺少桌面或图形组件时明确报告不可用。

删除工作区只是从清单摘掉这条登记：工作区目录不删，Agent 的工作树和分支留在项目里，绑到这条登记的 Agent 不再出现在名册里。再次登记同一目录是一条新的项目，不会把这些 Agent 认回来。删除前界面说明这一后果；正在看这条项目里的 Agent 时，先离开到剩下的项目。

输入框接收选择、拖入或粘贴。图片仍走有界快照；本机文件由后端打开选择窗口并挂入，浏览器不提交服务器路径，也不重试旧的任意路径入口；拖入字节流式落盘，不按体积拒绝，也不整件读进 Web 进程。挂入成功后仍属于本地草稿，发送才成为用户消息事实。失败附件保留供重试或移除，不能悄悄跳过它发送剩余正文。运行中停放的消息保留同一组附件，等实际发送时一起提交引用。本机文件选择与工作区选目录一样，窗口在独立进程中运行，界面明示窗口开在运行后端的电脑上；用户显式选择或上传的附件按普通材料处理，不识别、拦截或脱敏其中的内容。

历史消息展示图片与具名文件，并可下载文件原件。附件属于 Session，读取与工作区副本的边界见[多模态附件](../上下文/多模态附件.md)；浏览器不负责解析内容，也不把上传自动变成工作区变更。附件下载与引用以本会话为界：自身挂入的与已发送消息引用的可以读；其他会话的附件不能仅凭 id 下载。发送前的预览不扩大模型材料范围，模型仍只按已发送事实中的引用获得附件。历史原件不做回收。

## 暂停、继续与停放，都不是取消

- **暂停**：当前 Step 与已派发 Command 跑完，之后 Scheduler 不再因 outcome 自动进下一拍。人停止过当前轮、或 Worker 已不在而 Journal 仍可推进，共用同一颗"继续"按钮，只 wake，不写用户消息。
- **停放**：运行中的第一次发送先停在输入框上方，当前轮回到 idle 后按顺序发出，也可以立刻发或退回编辑栏。这只是前端呈现次序，不另建后端队列；重新打开页面后仅恢复文字供编辑。

三者都不是 `cancel_turn`。Agent 自然停在等用户输入时两个按钮都不出现。

`auto_authorize` 与 `paused` 是 Host 持有的 Session 级产品元数据，不进 Journal。页面切换或无人选择时这条 Session 的策略不变，语义见 [Command 授权](Command授权.md)。

名册不提供改名或归档。Agent 的名字由创建事实固定，Host 不另存会话标题或归档标记。

## 时间线的两层归约

长会话只渲染阅读位置附近的轮次，滚动时展示更早或更晚的记录，并保持阅读位置稳定。这只限制页面呈现，不裁剪会话事实或模型上下文；用户查看历史时，新输出不抢占阅读位置，回到最新后恢复跟随。

聊天栏整体可滚动，输入区固定在底部，历史正文为输入区预留空间。输入区两侧空白仍用于翻阅聊天；输入框内有可滚动的长文本时优先滚动文本。

未完成的当前工作计划在输入框上方按需展示，不留空占位。事项被模型全部标记完成后，计划移到更新它的那轮回复末尾，随历史滚动；替换或清除当前计划不抹去已完成的历史记录。它和历史中的计划更新读取已提交事实，不用模型预览或工具瞬时活动推断计划。每轮给模型阅读的计划快照不重复显示为聊天气泡；事项状态是模型记录，不能作为任务完成证明。更新与上下文规则见[工作计划](../上下文/工作计划.md)。

前端按机械事实分两层：有工具的已提交 Step 属于执行过程，可独立折叠；无工具的 Step 原地成为最终回复。

Step 标题回答"这一步在做什么"，优先用该步的意图正文，没有才退回调用预览。默认全部折叠——执行细节由想分析的人自己展开，只有等待授权这类需要用户操作的状态才自动展开。

成功的步不挂状态徽标："完成"每步都一样，不带信息。失败、中断、待授权仍然挂。

一轮是否收口看机械事实：Session idle、没有进行中或待授权的工具、没有未决 control approval。不要求必须出现最终气泡；有工具却没有正文时画一句说明，不写 Journal，也不假装成 `deliver`。

长期 Agent 由同事、群或例行任务开始的一轮是它的工作记录，不是给人的回复（去向规则见 [Coding Bot · 结尾文字的去向](../CodingBot/总览.md#结尾文字的去向)）。时间线把这样连续的步骤收成一行「工作记录」，带开始时间与一行摘要，点开才看到全文与工具；只有待授权这类要人操作的状态才自动展开。它不计未读、不算新回复。Agent 用 `message_user` 发给人的消息仍是普通回复。去向只在后端按触发事实判断一次：历史投影随步骤项给出，实时预览、思考与交付由 Host 按同一输出身份算出后随事件带出，前端不按内容或来源自行推断，因此运行中与刷新后呈现一致。

每轮回复耗时由已提交的用户消息与最终回复时间计算，历史会话可以直接重建。它表示消息提交到回复提交的经过时间，包含思考、工具执行与等待，不是模型纯计算时间；存在已提交回复且本轮收口后才展示。运行中在同一位置按用户消息时间显示实时经过时长，活动依据仍来自 Host；读秒只属于临时展示，不作为结束时间或任务完成证明。

preview、committed cache 和 Journal Step 共用同一个显示身份，没有 Journal 身份的文字不得走 `deliver`。思考增量走独立通道，与正文分开，刷新后从已提交的决策元数据恢复。

控制提案不进时间线，用不能关闭的确认框出示。裁决后的执行说明必须由同一 `request_id` 的 Journal 控制事实投影，Application 不另推一份权威结果。批准、拒绝、执行开始与终态是不同事实，执行已开始却无终态时显示"结果未知"，不再次执行。

## 不提供时间旅行

Web 不提供编辑已发出的消息并开出新会话、从某一步重开、从一轮收口之后另开一条会话，也不维护「新身份顶掉旧身份」的会话线。用户消息可以复制。文件改动不提供系统内回退，撤销由 Git 承担；以后的回退按 [Coding Bot](../CodingBot/方向.md) 的外泄点规则另做，不恢复这条入口。

## SubAgent 入口

`delegate` / `reclaim` 从普通工具卡分出，作为 SubAgent 调用入口；`delegate` 的终态仍是派出回执，不改写成子生命线。父 idle 且有活跃子会话时画一个活动指示，不把父标成 `running`，也不改变"父可以先退、报告再唤醒父"的生命周期。

用户从委派卡片打开右侧观察面板，主会话仍可操作。面板只读子自己的历史、思考、工具活动与流式正文；打开、关闭与切换面板不选择或唤醒子会话，也不改变父 owner。交回与收回依据子自己的交回事实展示，idle 和派出回执都不是子任务完成证明。过程不进入父模型上下文或父 Journal。

页面重连时先补齐仍在进行的瞬时展示，再接收后续增量；已提交历史仍以 Journal 投影为准。浏览器断线清除失去来源的活动叠加，不能假装旧流仍在运行。任务结束后面板保留供回看。

## 技术选型

React + TypeScript + Vite + Mantine + RTK Query。Mantine 只提供布局与视觉组件；聊天界面可参考 assistant-ui 的交互样例，但不接入其 Runtime、Thread 或 Adapter 模型——那会引入第二套会话状态机。

## 群聊

群列在所属项目的 Agent 下面，从项目的操作菜单新建，成员只能选同项目的 2 到 6 个 Agent。群页展示 Host 持有的群记录：人的发言署名为「你」，Agent 的发言链到它的会话；人发言时可以点名，不点名就是叫全体。页面显示 Host 当前在等谁回应，进行中的一串调度可以一键停止，停止像人打断一样作用在被叫醒的成员上，已有的发言保留。

群的创建、群记录、被叫成员或调度是否进行中一有变化，Host 就发一条只带群标识的变化事件，页面据此重读群数据。不能借成员的活动事件代替：最后一位成员变空闲时调度还没收尾，按那一刻重读会一直停在“正在等”。建群、发言与停止都由 Web 调用 Host 的群接口，Web 只校验人的输入（正文非空、只能点名本群成员），调度与上限都在 Host。

## 跨会话收件箱

收件箱把各 Agent 已经等人决定的命令授权和控制提案汇到一处，人不必逐个打开会话，条目用 Agent 名字。非 Agent 会话（子会话、TUI 会话）以及项目已删除的 Agent 不进入收件箱。还没有用户消息的 Agent，只要已经有待决定事项，也会出现。

批准和拒绝沿用会话内的命令授权与控制入口，收件箱不另开一条批准路径。会话里的待处理条照旧保留。

跳数或源头总量达到上限时，收件箱上报该 Agent；人在这个会话里再发消息后，这条上报消失。已暂停且时间线里还有未处理消息的 Agent 也列在这里，继续沿用会话的继续。

人长时间不在 Web，且该 Agent 的未读汇报和例行任务触发都累积到门槛时，收件箱先问要不要继续。仍无回应则暂停当时仍在运行的例行任务并告知 Agent；人选择恢复时只恢复这次暂停的那些。Agent 不能自行恢复。人自己暂停的、Agent 自己暂停的都不在这次恢复里。判据是离开时长、未读汇报数和触发次数，人的选择由 Host 执行。

## 不做

- 不把 Command Authorization 与 Control Approval 抽象成通用审批框架，两者变化原因不同。
- 不让前端缓存参与后端恢复、调度或授权判断。
- 不为停放发送建后端队列。
