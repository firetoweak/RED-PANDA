# 外部编码协作者

让用户正在使用的编码智能体直接联系 RED PANDA 的长期 Bot，减少开发与测试之间手动转交消息的负担。外部端保留自己的上下文、执行环境与工作目录；内部 Bot 继续通过现有私信和群聊组织协作。入口复用 Web 所在的唯一 Host，不另起执行循环。

第一版按接入绑定一位现有 Bot。外部协作者不成为内部名册成员，不取得内部 Session、项目目录或人的入口身份。接入凭据确定外部名字和可联系的 Bot，消息参数不能冒充其他发送者或指定其他收件人；每个接入只读自己的往返消息，不能读取 Bot 的其他私聊、工具结果或群历史。Bot 改名继续保持绑定，删除后不能接收新请求；用户撤销接入后，外部端失去读取与发送能力，Bot 也不能再向它发送新回复。

外部消息是有明确来源的协作事实，不经过人的文本输入、命令授权或控制确认入口。外部协作者转述的批准不构成用户授权。收到消息请求一次决策；回复由 Bot 显式发送，普通结尾文字继续给人看，不自动回给唤醒者。消息展示与模型上下文都标明外部来源。

往返内容与回复关系以 Bot 时间线为事实源。发送重试保留同一身份，同一身份更改内容属于明确的输入冲突；Bot 回复沿原工具调用恢复，不能因未知结果重新发送一条。外部端按本接入的消息顺序续读，连接中断或 Host 重启不改变已经接纳的消息与游标。

测试请求可以携带成果引用与不可变提交版本，回复保持原请求的版本关联。系统不判定测试是否完成、验证是否充分或代码该怎样修；实际测试版本与结论由模型说明。谁负责测试、如何分工、何时复测仍由人和 Agent 在对话中约定。

MCP 负责工具交互，不承担外部编码客户端的执行生命周期。第一版验证外部端主动发送与读取的反馈闭环；自动唤醒、长期群成员身份与通用执行器协议不在此入口内扩展。
