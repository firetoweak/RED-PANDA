# 外部编码端的独立验证

第一版服务一个明确场景：用户在原生编码会话里开发，将需求和一个不可变版本交给 RED PANDA 的长期 Bot 独立验证，反馈回到原会话；编码端修复后交付新版本复验。独立验证从用户操作、需求和边界出发，开发端自测或 CI 通过不能替代它。内部 Bot 继续通过现有私信和群聊组织协作，入口复用 Web 所在的唯一 Host。

人从全局设置生成或撤销连接配置，不给外部智能体取名，也不预选固定交接对象。编码端领取当前会话的身份和自动名称，根据团队公开分工选择验证同事。外部编码端保留自己的上下文、执行环境与目录，不成为内部名册成员，不取得内部 Session、项目目录或人的入口身份。

配置可以跨会话复用；每个原生会话单独领取身份，重连沿用。交流按接入、会话和请求关联，回复只能沿收到的请求返回。共用凭据下的身份用于分流，不构成权限隔离。外部端可见同事的名字和分工，只能读取自身请求和显式反馈，不能读取用户私聊、内部同事通信、工具结果或群历史。撤销接入后，该配置的所有会话停止收发，历史保留。

建立接入表示允许 Bot 在已有协作范围内交换验证所需的任务和结果，常规反馈无需逐条确认；人后续提出的限制仍优先。外部请求是有明确来源的协作事实，不能代替人的指令、命令批准或其他授权，也不能授予读取和披露无关私聊的权限。普通结尾文字继续给人看，回到编码端的内容必须显式发送。

每次交付必须包含可获取成果的引用、完整提交版本和验收需求。进度、必要问题与最终报告明确区分；通过或发现问题的报告必须说明实际验证版本并提供可复查证据。报告可以声明因条件不足而受阻，不能把接纳请求或暂时没有新消息当作验证完成。模型负责判断验证范围、证据是否充分和修复建议，Runtime 不做语义验收。

复验关联前一请求和新交付版本，保留每轮需求、实际测试版本与结论的区别。往返内容以既有 Bot 时间线为事实源；相同提交标识重试只接纳一次，改动内容属于输入冲突。重连与 Host 重启不改变已接纳的请求、回复关系和续读位置。

MCP 提供提交与有界等待反馈。原编码会话继续读取、处理问题并复验；不承诺在客户端结束执行后自动唤醒它。第一版不扩展外部长期 Bot、外部群成员身份、通用执行器协议或多端编码团队平台。
