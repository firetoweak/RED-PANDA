# 处境观测（未开始）

本文只记录尚待设计的问题。现有名册和待人处理提示不等于已经具备卡住或跑偏判断。

## 问题与依据

Runtime 回答能否继续决策，不回答任务处境。等外部输入可能是正常完成，也可能是等人登录或模型说要行动却未调用工具，见[相关观察](../../历史/模型承诺后未调用工具1014.md)。持续执行同样可能在重复失败或偏离要求。

可决策也不代表全部命令已收口，观察应查询真实在途操作，不从一个状态词猜测。已有的通信额度、待授权提示与无人查看保护只提供各自的机械保证。

## 待定问题

需要明确什么情况值得打扰人、谁判断、使用哪些轨迹，以及判断要不要成为事实。轨迹可能含私人内容，交给外部服务分析是产品和授权选择，不能当成无影响的内部读取。

处境视图应是可重建的事实投影，不拥有执行状态。自动采集只供观察，不替子生成语义汇报或灌入父上下文；父需要理解时可以追加要求或提问，子显式回复，见[SubAgent](../运行/SubAgent.md)。

报告不代替事前授权，判断有进展也不证明任务完成。系统不按时长自行认定卡住，不把“等人登录”等含义加进 Runtime，不以没有新事实的唤醒保证可靠性。[LoopGuard](../上下文/LoopGuard.md)只提醒重复行为，仍不判断任务含义。

不为这个方向把临时子任务扩成长期同事；人的调整仍经父，独立持续职责交给长期 Bot。
