# Coding Bot（未开始）

> 本文只记方向、已定的取舍与已经排除的做法。方案确认前不按它实现，也不把它当成现行架构。

## 方向

RED PANDA 从「开一个会话、做完一个任务」转向**几个长期在线的 coding Agent 在同一个项目上自由交互协作**。侧边栏列的是同事，不是历史会话：每个 Agent 有名字、自己声明的负责方向和一条持续的时间线；人可以直接找任何一个说话，Agent 之间自己交接、讨论，需要人判断时再来找人。

系统只提供原语，不预设工作流。谁做什么、何时交接、谁来协调，由人在对话里交代、由模型当场决定；任何 Agent 都可以被交代成临时协调者，协调者不是一种特殊类型。**群聊是核心玩法。**

只做 coding 场景。定时与事件驱动的长期职责（Routine）不在方向内，现有一次性定时保持原样。

## 前提（已落地）

- 一个数据根同一时刻只有一个 Host，Host 独占所有日志写入、Worker 调度与投递，见[多活跃会话](../运行/多活跃会话.md)。
- Web 是唯一的常驻 Host 入口；TUI 是独立数据根的单会话入口，不承载长期 Agent，见 [Channel 接入契约](../入口/Channel接入契约.md)。

## 长期 Agent

Web 的基本单位从会话换成 **Agent 名册**，不保留普通会话列表与名册两套并行。即开即用的单次会话由 TUI 承担。

- **身份**：Agent 是一个稳定名字，指向它当前的 Session。分支与从某一步重开会产生新的 session_id，名字跟随过去；对外寻址、记忆与名册都挂在名字上，不挂 session_id。
- **一条时间线**：一个 Agent 一条长期 Session。人的私聊、同事的私信、各个群的发言按到达顺序排在同一条时间线里，靠 Compact 延续；不为每个群另开上下文。
- **创建与归属**：由人在 Web 创建，一个 Agent 属于一个项目。Agent 不创建同事；需要临时帮手时用 [SubAgent](../运行/SubAgent.md)，委派能力保留。
- **首轮自我介绍**：创建写入一条创建事实并请求一次决策，Agent 不等人开口即醒来，依据自己的名字、当前空间（只读浏览项目）与名册里已有同事的方向，向人提议自己打算负责什么。系统只写事实、触发决策；方向判断属于模型。
- **负责方向由 Agent 声明**：人在对话里认可或修正提议后，Agent 用工具记下自己的负责方向，之后也由它在对话中更新。名册展示的「负责什么」就是这份声明。不设角色表单，不让人写 System Prompt。
- **名册对模型可见的方式**：名册变化作为事实追加，从下一步可见并可重放，与能力目录同一手法；不把随时变化的名册直接写进 System Prompt，以免每次变动打穿前缀缓存。

## 工作区：每个 Agent 一条分支

多个 Agent 共用一个项目，但每个 Agent 有自己的 git worktree 与分支，不碰人自己检出的工作目录。做法参考 Claude Code「每个会话一个 worktree，改动不在主分支」。

**为什么不让所有人直接写同一棵活的工作树。** 写写冲突文件工具和受管命令大体兜得住；兜不住的是「工作区常处于别人改到一半的状态」：A 改三个文件才能对上接口，改到第一个时 B 跑测试失败，B 无从知道原因不在自己。命令还会动到 `.git`、依赖目录、运行中的服务等没有按文件合并语义的共享状态。纯共享工作树只能把这些交给模型自觉协调，系统给不出确定保证。

- **集成分支**：项目有一条本地集成分支，由 Host 在自己持有的 worktree 中合并。人自己的工作目录不被触碰，何时把集成分支合进自己的分支或推到远端由人决定。
- **落地**：何时落地是 Agent 的语义判断；落地本身由 Host 确定性执行——串行合并，能快进则快进，否则产生一个作者为该 Agent 的合并提交。合不进去时返回已知结果，由 Agent 同步、解决冲突后再落地。**落地不经人审批**：落地进的是 git，每次落地可单独撤销；鼓励的小步频繁落地与逐次审批相互矛盾。
- **同步**：Agent 想拿到同事已落地的工作时，主动把集成分支合进自己的分支，时机由它决定。同事尚未落地的改动可以直接去读，协作不必等落地。
- **两层分工**：Agent 文件系统管单个 Agent 内部——每个 worktree 就是它的任务根，照常提供审计与逐步回退；git 管 Agent 之间的集成。不在 Agent 文件系统里另造草稿层与三方落地。
- **SubAgent 挂在 Agent 的 worktree 上**：子任务的临时工作树基于父 Agent 的 worktree，成果合入的是父 Agent 的分支而不是人的工作目录，因此这一步不再需要人授权。
- **要求项目是 git 仓库**；不是的先初始化。
- **已知代价**：每个 worktree 缺少被忽略的依赖与构建目录，需要各自准备。先接受；若实测太痛，再考虑用 Agent 文件系统的写时复制视图透出主工作目录里的这些目录。
- **文件之外的共享资源**（端口、测试数据库、开发服务器）没有合并语义，由 Agent 协商；持续进程本来按会话持有，各自在自己的 worktree 里起。

## Agent 之间的私信

由子会话回传推广而来：任意 Agent 可以给任意同事定向发消息。

- 发送是一条 Command；Host 把消息作为外部事实写进收件人时间线，标明发送者并请求一次决策，收件人不在线就拉起它。投递身份由发送方 Command 派生，重复投递被吞掉。
- 结果只确认「已进入对方日志」，发送方不等回复；回复只是对方的另一次发送，没有请求/响应配对。
- **跳数上限**：消息按线程计跳，回复一次加一；超过上限时发送返回已知结果并上报人。这是确定性计数，不按内容或时间判断「是不是在闲聊」。
- **转述不等于同意**：授权事实只能由人在 Channel 中产生，Agent 无法替人批准。模型语义上仍可能把「对方说用户已经同意」当真，因此私信与群发言必须标明发送者，提示词明确其他 Agent 转述的同意不算数。

## 群聊（核心玩法）

- **公共记录归 Host**：群记录是群里发言的事实源，人与 Agent 的发言都先写入它，再作为外部事实投递进每个成员的时间线，标明群与发言者。成员仍只有一条时间线。
- **发言必须显式**：Agent 用工具在群里发言；它每轮结尾的普通回复留在自己时间线，不进群。发群里还是发私信由 Agent 自己判断，系统不替它选。
- **调度由 Host 确定性执行**：有 @ 只叫被点名的成员，无 @ 或 @所有人叫全体；成员依次被叫醒，后发言者能看到前面的发言。
- **发言按顺序，干活并行**：成员在群里发了言，或本轮结束没有发言（视为跳过），即算完成本轮发言，Host 接着叫下一个；发言者可以继续在自己的 worktree 里干活，干完再发言就是一条新发言。coding 的一轮可能很长，不能让整个群等它做完。
- **硬上限只在 Host 代码里**：成员数、一条人消息最多驱动的轮数与公开回复总数、每个成员每轮的发言条数、整轮无人发言即停。起步参考 Grok Bot 的数值（6 人；3 轮共 10 条；每人每轮 2 条），以实测校准。不靠提示词让 Agent 闭嘴，不设主持人模型。
- **不进群的内容**：命令授权请求与需要人判断的事项只出现在该 Agent 与人的私聊及待处理收件箱。
- **群级停止**：一键打断所有成员当前这一轮，并不再调度新轮次。停止不撤销已经完成的动作。

## 人在环内

- **跨 Agent 待处理收件箱**：汇集命令授权请求、控制提案与跳数超限上报，人不必挨个打开 Agent 查看。
- **命令仍需授权**：worktree 只隔离文件，命令仍可能联网或写到工作区之外。保留按 Agent 的「全部放行」开关，由人逐个决定；真正的解法在[进程沙箱](进程沙箱.md)。无人值守时授权请求堆积的程度，以实测为准。
- **停止**：单个 Agent 打断与群级停止。
- **成本**：硬上限与跳数上限兜住失控；先在界面展示各 Agent 用量，不做预算。

## 记忆（之后的第一重点）

压缩之后的连续性决定长期 Agent 有没有用。记忆不进第一版，但第一版必须不堵它的路：

- 记忆挂在 Agent 身份上，不挂 session_id；
- 记忆放在 Agent 各自的产品数据空间里，不放进 worktree，否则会被落地进仓库；
- 记忆必须能指回来源，Journal 事实与落地提交就是现成的来源坐标，见[记忆](记忆.md)。

首轮自我介绍届时也可以依据记忆提出方向。

## 依赖关系

群聊依赖 Agent 身份、各自的 worktree 与落地、私信投递；Agent 身份与 worktree 落地完成后，「两个 Agent 改同一个项目并各自落地」即可单独验证。

## 已经排除的做法

- **所有 Agent 直接写同一棵活的工作树。** 半成品状态会干扰同事，命令对 `.git`、依赖与服务的副作用没有合并语义。
- **在 Agent 文件系统里自造草稿层、三方合并与落地。** 这是在文件系统层重写 git 的分支与合并。
- **落地经人审批。** 与小步频繁落地矛盾；git 已提供逐次撤销。
- **合并进人当前检出的分支或工作目录。** 会撞上人未提交的改动。
- **每个群一个独立上下文。** Agent 会在不同群里分裂成不同的人，前缀也不稳定。
- **主持人模型调度发言，或靠提示词限制回复数量。**
- **按时长、内容判断 Agent 之间是否在闲聊。** 只做确定性计数。
- **Routine、周期定时与 webhook 事件触发。** 不在方向内；没有鉴权也不对外暴露服务。
- **Agent 自行创建同事。**
- **角色表单或由人编写 System Prompt。** 负责方向由 Agent 提议、人认可、Agent 声明。
- **普通会话列表与 Agent 名册并存。**
- **把随时变化的名册直接写进 System Prompt。**
