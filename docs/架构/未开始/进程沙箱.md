# 进程沙箱（未开始）

> 命令当前直接在任务根执行，具体沙箱接入设计未开始。本文只记方向与已排除的做法，不作为实现方案。

## 方向

Sandbox 独立负责进程、内存等资源、网络权限和基础文件访问限制。可以引入完整的外部沙箱模块来运行任务进程，也可以把整个 konden 部署在外部沙箱中；后一种方式不要求系统拥有该沙箱的创建与管理能力。

沙箱衔接的是现在的直接执行：文件工具与命令都作用于任务根的真实目录，沙箱只为同一个任务根和它的命令施加限制，不另建文件视图、文件历史或回退。成果关系仍由 Git 承担，沙箱不接管成果验收。

沙箱可以在会话开始前建立、会话归档后销毁，可以跟随 [Coding Bot](../CodingBot/方向.md) 的 Agent 身份，也可以由多条会话共用。其生命周期不决定文件成果的生命周期：释放沙箱不隐含撤销文件或删除提交，需要保留的数据必须留在任务根或 Git 里。

## 当前边界

本机命令执行尚未提供操作系统级安全隔离；文件工具的根集合与逐根权限只约束工具访问，不限制进程、网络和安装行为。Workspace 是任务文件范围，不是沙箱实例。独立 Worker 也不等同于安全沙箱。每条命令经人授权是当前唯一的执行边界，见[执行环境](../能力/执行环境.md)。

外部环境已有的限制与产品自行实施的限制应如实区分，不猜测部署方是否提供了沙箱。模型只需要知道实际可用能力、限制和失败原因。

## 相关需求

- 子任务沿用父的命令执行与授权；沙箱不作为其基础执行能力的前提。需要额外执行限制时另行设计，不能把工作目录约定当作安全隔离。
- 命令授权与实际执行边界相关，见[Command 授权](../入口/Command授权.md)。所有命令一律需要授权，[Coding Bot](../CodingBot/方向.md) 的长期 Agent 无人值守时，逐条授权请求会堆积。沙箱让按 Agent 全部放行这一人的决定变得可以承受；授权仍由人做出，沙箱不替人批准。
- Coding Bot 给每个 Agent 一条 git worktree，但它只隔离文件：命令仍能写到 worktree 之外或联网。这与下文排除的"用独立工作树代替执行隔离"是同一条边界。
- [交互式资源](交互式资源.md)中的浏览器、ssh、REPL 活过 Command 后，需要明确其进程与资源释放责任。

## 已经排除的做法

- 为接入沙箱重新引入系统内的文件视图、操作历史或回退。
- 从沙箱销毁推导会话历史或文件成果应当删除。
- 用独立工作树或根集合检查代替执行隔离。
- 按命令名字或判别模型的语义判断建立安全边界。
- 为未知沙箱预建统一策略、生命周期或跨平台实现框架。
- 为外部部署沙箱强制引入一个内部控制模块。

## 尚未确定

采用哪种沙箱、覆盖哪些平台、施加哪些资源和访问限制，以及由谁创建与释放沙箱，都需要在实际接入需求下确定。无法取得所需限制时如何拒绝执行，也随具体方案明确。不提前实现沙箱适配层。
