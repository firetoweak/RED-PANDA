# 进程沙箱（未开始）

当前没有操作系统级执行隔离，本文是接入方向，不是可用保证。[执行环境](../能力/执行环境.md)与工具授权仍是实际边界。

## 接入方向

沙箱独立限制进程、资源、网络和文件访问。可以由外部模块承载任务，也可将整个 konden 放进外部隔离环境；后者不要求产品自己创建管理沙箱。

隔离施加在真实任务目录和命令上，不重建文件视图、历史或回退，成果仍归 Git。沙箱销毁不等于撤销副作用、删除历史或丢弃成果。

## 必须保持的边界

worktree、文件工具的范围校验和独立 Worker 都不是安全沙箱。工具批准只表示人允许操作，不授予系统权限；额外隔离可以帮助人决定是否放行，不能代人批准。部署环境已有保证与产品自身保证也须区分，模型只需知道实际限制与失败。

子任务基础执行不以沙箱为前提。跨调用资源的存续和释放需与[交互式资源](交互式资源.md)一起明确，不能靠共享目录假定生命周期一致。

采用哪种方案、覆盖平台、具体限制、创建释放责任，以及无法取得限制时如何拒绝执行，都留待实际需求确定。不预建统一沙箱策略或适配框架，不从命令名称或模型判断构造安全边界。
