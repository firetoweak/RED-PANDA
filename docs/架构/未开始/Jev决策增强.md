# Jev 决策增强（草稿）

> 状态：未开始 · 建议放在 `docs/架构/未开始/Jev决策增强.md`

## 定位

Jev（TypeSafe 的 System 1 决策模型，`typesafe/jev-1.13`）作为**可选增强**，只在需要模糊决策时提供概率化建议。

## 硬约束

1. **不启用不出错**：未配置、关闭、超时、报错、返回异常时，行为与当前 main 完全一致，Jev 等同于从未被询问。
2. **只建议，不阻塞，不接管**：Jev 不改路线、不调用工具、不替模型或人做决定。
3. **可重放**：每次询问与结果作为 Observation 写入 Journal；重放读 Journal，不重新调用 Jev。
4. **不改主循环结构**：Event→State→Step→Command 不变，Jev 只是 Step 之间的一个可选旁路。

## 接口

```
DecisionAdvisor
  ask(state_summary, questions) -> Advice | Unavailable
```

- 默认实现 `NullAdvisor` 永远返回 `Unavailable`。
- `JevAdvisor` 读个人配置中的 Key、模型版本、阈值；任何失败一律降级为 `Unavailable`。
- `Advice`：每个问题的选项概率 + 模型快照名 + 耗时。

## 接入点一：等人还是卡住

- **触发**：Session 进入 `WAITING`，或长时间无进展。
- **问题（Choice）**：等人回复 / 等外部结果 / 卡住需升级 / 正常推进 / 无法判断（no-match）。
- **输入**：最近若干 Event 摘要、等待时长、最后一个 Command。
- **处置**：高置信「卡住」→ 提示人或唤醒父任务；低置信 → 保持现状。

## 接入点二：环路或跑偏（LoopGuard 增强）

LoopGuard 继续负责硬规则（完全重复调用等）；Jev 负责模糊部分。

### 触发（任一满足即问一次）

| 信号 | 建议初值 |
|---|---|
| 步数兜底 | 每 8–10 个 Step |
| 重复信号 | 同类工具连续 ≥3 次；同一文件反复修改/回退 |
| 时间 | 同一工作计划项 in_progress 超过 10–15 分钟无推进 |
| 冷却 | 两次询问之间至少 3–5 个 Step |

数值均为配置项，先用 verify-redpanda 的长任务校准。

### 问题

- **Noul**：最近 N 步是否在原地打转？（只有 yes 概率；≈0.5 表示不确定，不是“轻度打转”）
- **Score**：当前动作与原目标/工作计划的贴合度；每档写成具体情境。
- 同一状态下的问题（含接入点一）**合并为一次请求并行询问**。

### 三级升级

| 级别 | 条件 | 主链路 | SubAgent |
|---|---|---|---|
| 1 | 首次判为跑偏 | 上下文中插入轻提示，照常继续 | 同左 |
| 2 | 冷却后再次判为跑偏 | 加重提示，要求下一步明确回应「继续/调整计划」，回应写入 Journal | 同左 |
| 3 | 连续第三次 | 阻塞，等人确认 | **不自停**，上报父任务，由父任务用现有接口 reclaim 或放行 |

任意一次判为正常 → 计数清零。阻塞是暂停等决定，不改路线。

## 使用 Jev 结果的规则（依据 TypeSafe skill）

- **置信度 ≠ 许可**：升级由代码按“连续命中次数”决定，不由单次概率决定。
- **推断与事实分离**：Journal 中标记为 inferred observation，不混入 Event 事实。
- **新鲜度检查**：应用前确认状态未变化；已变化则丢弃。
- **阈值本地校准**：cookbook 数值仅作参考，以 verify-redpanda 长任务数据校准。
- **实现前读线上文档**：https://docs.typesafe.ai/llms.txt（API / Python SDK / Confidence / State）。

## 配置

- 开关（默认关）、API Key（与模型 Key 同目录、同权限）、固定模型版本、各阈值与触发参数、请求超时。

## 测试

- 关闭状态：现有全部测试必须不变通过。
- 故障注入：超时、错误、畸形返回 → 行为与关闭一致。
- 升级路径：模拟连续跑偏判定，验证三级提示与清零逻辑；SubAgent 第三级只上报不停。
- 重放：Journal 重放不触发新的 Jev 调用。

## 不做

- 用 Jev 替代主模型规划或生成。
- Jev 直接阻塞或接管执行。
- 命令风险判断、SubAgent 完成检查（留作后续接入点）。
