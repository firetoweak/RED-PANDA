# 个人记忆与自动提炼（未开始）

> 本文只记个人记忆与自动提炼的方向、已定约束和已经排除的做法。长期 Agent 压缩之后的连续性仍是 [Coding Bot](../CodingBot/方向.md) 的重点；提取、结构与检索仍待设计，不按本文直接实现。团队共同维护的短笔记已落地，边界见[共同记忆](../上下文/共同记忆.md)，不代表个人记忆和自动提炼已经实现。

记忆让长期 Agent 在压缩之后仍能接着工作。原始会话记录仍保存完整经历，记忆不取代它。

**先做 Agent 自己维护的笔记，系统提炼放在后面。** 第一个具体需求来自协调者：派单记录（哪个 PR、哪个提交、派给谁）与一天里多次调整的规矩，跨天必然被压缩，见 [Coding Bot · 记忆](../CodingBot/方向.md#记忆之后的第一重点)。这类内容由 Agent 自己判断该记什么、何时改，系统只提供持久位置与压缩后的取回入口，不解释内容。由系统从会话记录提炼可复用知识，是之后的另一层，等笔记暴露出不够用的地方再设计。

**身份不是记忆。** 自己的名字、所在群与成员是可确定归约的事实，压缩后应像能力目录一样确定性地重新呈现，不靠记忆或交接文本转述。

现有工作计划和共同记忆都能跨压缩确定性重现，但分别服务当前任务与团队约定。个人笔记采用什么载体、如何复用已有能力，在本文设计时决定，此前不扩展工作计划。

## 先厘清要承接的内容

共同记忆保存团队共同约定，工作计划表达当前任务的推进；个人笔记先承接两者之外、属于这位 Bot 的跨任务连续性：稳定偏好、协作经验、尚欠的交付、正在等待的事实，以及后来被修改或撤回的约定。内容由模型理解和维护，系统不从笔记推断任务状态、依赖、优先级或下一次行动。

等待一份报告和安排一次唤醒不是同一份状态。笔记帮助模型记住为何等待；命令、消息与自动化各自保管实际执行和触发事实。笔记不能声称一个未登记的提醒会发生，也不能把一次触发当作已经观察或已经交付。跟进方向见[主动跟进与后台更新](../CodingBot/方向.md#主动跟进与后台更新)，不在记忆内再建一套调度器。

先保留这层内容边界，不预设字段、任务层级、笔记文件全集或专用角色表单。载体与当前工作计划的关系仍待设计；不要为了个人笔记把现有计划扩成全部长期职责的数据库。

## 硬约束

**必须能指回来源。** 笔记的每次写入是 Agent 留下的事实，系统提炼的记忆由会话记录和产物而来；两者都不能成为无法核验的第二事实源——这与 Journal 是唯一执行事实、投影不得反向拥有状态是同一条原则，见[运行语义规约](../运行语义规约.md)。Journal 事实与 Agent 的落地提交就是现成的来源坐标。

写入来源与内容依据分开：写入记录证明谁记过，原消息、工具结果或产物支持其中的结论。未经核验的同事报告与模型推断不能因被记住就升级成已核验事实，仍须保留其来源与不确定性。

**挂在 Agent 身份上，不挂 session_id。** 长期 Agent 以名字寻址，session_id 只在内部使用；记忆跟着名字走，见 [Coding Bot · 稳定身份与名册](../CodingBot/总览.md#稳定身份与名册)。

**放在 Agent 各自的产品数据空间里，不放进 worktree。** 放进 worktree 会被当作代码改动落地进仓库。

```text
会话记录 / 产物
        ↓
提炼并保留来源
        ↓
存储与检索
        ↓
一次决策开始时冻结检索结果
```

检索结果在一次决策开始时确定，和 Decision Context 同一个冻结边界，避免决策过程中模型所见悄然变化。

**当前依据可以纠正，历史不被改写。** 用户更正、撤回或要求不再使用一项记忆时，后续取回必须能明确呈现其变化，不能只删掉当前正文，再让旧摘要或提炼任务把同一结论恢复。较晚写入不自动代表内容更可信；事实依据冲突时由模型核查。停止作为当前依据与删除原始历史是不同承诺，不能把清空笔记描述成已经删除 Journal、产物或外部副本。具体纠正、停用与删除的产品操作仍待设计。

个人笔记应让人能够查看并纠正，不能只能从 Bot 的回答推测它记住了什么；具体入口随笔记形态设计，不预建记忆管理界面。

**可回忆不等于可分享。** 私聊形成的个人记录不自动进入共同记忆或群消息；跨任务承接不能扩大原信息的可见范围。记住通信对象或既有职责也不能授予新的操作权限。

## 待设计

笔记的结构、大小上限与压缩后的取回方式，以及系统提炼的提取时机、结构、更新规则和检索策略都未确定。另有一个由长期 Agent 带出的问题：

- **注入位置与前缀稳定性。** 决策开始时冻结只解决一致性，不解决前缀缓存。随时变化的记忆若写进 System Prompt，每次变动都会打穿前缀缓存；名册已经选择作为事实追加、从下一步可见，记忆是否同一手法，待定。

Bot 的长期分工、偏好和协作经验应从正常交流与实际工作中形成，由模型整理承接，用户无需另填角色或负责方向。这是隐式个人记忆的目标，不是新增一个角色资料表；记忆不得覆盖用户当前要求，也不构成新的操作授权。提炼时机、取回方式和纠正路径仍待设计。

自动提炼只在在线笔记已暴露实际漏记后设计。届时以新增材料和已观察的更正为依据，不默认每次唤醒扫描完整历史；检索索引只能是从正式内容重建的派生物。先验证压缩后的取回、纠正是否生效、引用是否支持判断及读取成本，再决定是否需要关键词、向量或混合检索，不预先选数据库、嵌入模型或重排服务。外部材料及未验证范围见[调研记录](../../讨论/主动跟进与记忆调研1027.md#记忆工作时写下与后台整理互补)。

## 已经排除的做法

- 在提取、结构、检索确定之前预建领域状态机。
- 和 [SubAgent](../运行/SubAgent.md) 的后续扩展或[自动化](../运行/自动化.md)合并成统一的"增强能力"框架——三者变化原因不同。
- 把记忆放进 worktree，或挂在 session_id 上。
- 把个人笔记、共同约定与任务进度混成一份不断膨胀的正文。
- 在没有漏记与检索证据前引入固定周期的全历史提炼、人格画像或自动反思流水线。
