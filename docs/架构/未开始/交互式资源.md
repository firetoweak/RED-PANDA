# 交互式资源（未开始）

本文保留方向与排除项，不是实施设计。当前命令执行见[执行环境](../能力/执行环境.md)。

## 要解决的问题

浏览器登录、SSH 和 REPL 等资源需要跨工具调用存在。模型说明需要人完成一次登录不难，难的是人完成后下一次调用还能寻址同一资源，以及重启后能否如实知道它仍可用。

后台命令已能持续运行并通知结果，但不等于提供这些资源的登录态或交互恢复。UAC、sudo 密码和硬件确认仍由人在工具外完成，不因此开放命令内人工确认。

## 待定边界

需要明确资源身份、所有者、存续与释放责任，是否随 Bot、项目或 Session，以及能否跨成员共享。持久记录证明曾创建过资源，不能证明进程重启后它仍活着；失效必须让模型看见，不能盲目重建。

人在外部完成操作后，以新消息让模型继续检查。无人可问时如何升级归[处境观测](处境观测.md)，端口、服务器等共享资源仍需协商。

不增加 Runtime 的“等人登录”状态，不让工具从事实之外的侧通道读人输入，不轮询等待人完成，不把资源存活藏在内存里，也不提前建设通用资源状态机。可复用[能力加载](../能力/工具与能力.md)的身份与事实思路，具体方案待真实需求确定。
