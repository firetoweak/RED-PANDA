# Agent 文件系统

Agent 文件系统为助手提供可审计、可回退的任务文件状态。它独立拥有文件视图、操作证据、变更审阅、恢复与子任务文件成果交换；Sandbox 负责执行隔离，两者按需要组合。

设计目标见[Agent 文件系统设计目标](../../Agent文件系统设计目标.md)。命令启动与文件视图的接合见[执行环境](../能力/执行环境.md)；沙箱接入尚未设计，方向见[进程沙箱](../未开始/进程沙箱.md)。

## 职责与依赖

| 层 | 拥有的职责 |
|---|---|
| Assistant / Host | 委派、回收、结果验收、授权与回退意图，以及业务事实和文件操作的关联 |
| Agent 文件系统 | 文件视图、受控操作与审计证据、变更审阅、发布与恢复、子任务基准及成果交换 |
| 原生文件管理服务 | 候选文件执行、变化证据、接受与恢复执行 |
| 底层 VFS 库 | 文件系统语义、存储事务、写时复制、冻结制品与挂载适配 |
| 命令与进程执行 | 按给定目录和环境启动命令、收集结果、取消并终止所管理的进程 |
| Sandbox | 对进程、内存等资源、网络权限及基础文件访问施加执行限制 |

上层通过 Agent 文件系统使用完整的文件能力。原生控制协议、对象存储和 Git 比较合并属于其内部实现，不由 Assistant、Host 或 Tools 分别编排。语言不决定职责归属。

Agent 文件系统基于原生文件管理服务，原生服务使用底层 VFS 库。底层库不认识 Session、Step、委派或验收，不维护另一套产品回退历史。VFS 库提供文件系统机制，Agent 文件系统拥有操作审计与回退语义。

命令执行消费指定的任务文件视图，视图内的受控文件变化由 Agent 文件系统记录；进程生命周期归执行能力管理。Sandbox 可以使用同一文件视图并施加访问限制，沙箱自身的基础文件能力不接管 Agent 操作历史。

命令的实际任务根与旁路写入约束见[命令文件视图接入](../能力/命令文件视图接入.md)。hook 接入与任务进程树归执行能力，原生文件服务和挂载仍归 Agent 文件系统；两者不能因同为原生代码或进程而混合归属。

## 与沙箱的组合

沙箱可以只包住任务进程，也可以是整个 RED PANDA 的外部运行环境；部署方提供的外部沙箱不需要内部控制模块。审计与回退契约不以沙箱存在为前提；文件视图隔离不能替代执行限制，Sandbox 也不能凭执行结束或文件可丢弃代替 Agent 文件系统判定实际改动。

沙箱、会话、文件视图与审计历史各自管理生命周期，不要求一对一绑定。销毁沙箱只释放执行环境，不产生文件回退，也不删除文件成果、操作证据或回退依据；需保留的数据必须位于可保留的存储中或先持久化。子任务工作树的清理见[子任务文件交换](子任务文件交换.md)，不由沙箱销毁触发。不新增归档存储协议或通用资源生命周期框架。

当前本机执行不提供完整操作系统级隔离。挂载外文件写入、安装、系统配置与网络副作用不属于文件回退范围；外部服务直接修改文件也不自动成为受控操作证据。

模型只接触逻辑文件位置、可观察结果、使用限制与下一步动作。内部锁、候选、发布阶段、存储和版本坐标不能成为要求模型理解的前提。

## 不做

- 将 Agent 文件系统纳入 Sandbox，或用文件回退充当安全隔离。
- 让沙箱创建、重建或销毁决定操作历史的保留与删除。
- 为适配未知沙箱预建统一策略、存储或生命周期框架。
- 把文件控制扩展为所有外部副作用的回滚机制。
