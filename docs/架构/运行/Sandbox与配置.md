# Sandbox 与配置

执行环境边界与产品配置的所有权。包职责与依赖禁令见[架构总览](../总览.md)。

长期目标与演进约束见 [Sandbox 设计目标](../../Sandbox设计目标.md)；本文描述当前已落地的执行环境边界。

## 执行环境

**Sandbox 是整体，VFS 是其中的文件管理子系统。** 文件子系统统一管理工作区视图、受控读写、操作证据、回退以及子任务文件成果的交换与合入。底层虚拟文件系统负责文件语义和事务持久化，文件管理层负责视图与操作历史；不将业务编排塞入底层存储引擎。

产品层决定委派、验收与回退意图，并保存业务事实与文件操作的关联；文件状态和文件操作历史由 Sandbox 管理。进程执行和网络控制按各自边界演进，权限约束贯穿文件、进程和网络；文件管理能力不代表这些执行边界已经实现。

任务文件在该会话绑定的工作区主根，工作区开启完全访问时再挂上 Host 根。

任务根中的修改工具访问和可能写入的命令启动目录投影到独立候选文件视图，只读文件工具与声明只读的命令查询已发布工作区。逻辑工作区位置与临时挂载位置分离，模型和 Web 展示逻辑位置；读取与发布的互斥、文件变化及恢复由 sandbox 管理，见[工作区版本](工作区版本.md)。绝对命令参数、Host 根和材料根不因 cwd 投影而获得操作系统隔离。

**Agent 不拥有工作目录**，Environment 描述的是"在哪里执行"，由调用方每次指定。

产品进程环境与工作区命令环境具有独立来源。Host 对产品内部工具补全本机环境，不改写工作区命令的启动来源；Sandbox 按给定环境查找 Shell，不猜测项目环境，见[多活跃会话 · 进程身份](多活跃会话.md#进程身份)。

RED PANDA 自身的运行依赖、内部工具及 CLI 管理使用产品环境。工作区命令使用独立的启动环境，不随产品工具的安装路径刷新而改变，不根据助手的解释器选择任务 Python。模型依据项目约定和用户要求选择解释器、环境管理器与执行命令；Sandbox 负责执行明确的命令，不判断项目语言或代替模型选择环境。

每次命令在请求目录中的新子 Shell 内执行，环境变更不改写 Worker，也不延续到下一次命令。用户指定环境是持续指导后续调用的会话指令，由模型在每次命令中落实，修改与取消仍由用户消息表达；上下文交接保留这一约束及其证据强度。初始化失败不擅自换用其他环境继续执行。

不建立工作区环境配置表、会话环境设置工具或环境管理器识别框架，不持久化完整进程环境来复现旧启动。已登记 CLI 经工作区命令调用时仍使用工作区命令环境，其安装管理不改变这条边界。本机执行仍不提供操作系统级隔离。

`RedPandaHome` 只表示产品自身的数据目录，**不能充当任务 Workspace 或 Sandbox 根**。工作区清单是独立的产品级文件，会话与工作区的绑定是一条会话级事实。

Session 已发送文件的材料视图可以作为独立只读根加入执行环境；这是窄材料入口，不把整个产品数据目录变成任务文件系统。只读由文件工具契约执行，本机命令不具备操作系统级隔离。原件不作为可写根，处理副本与产物由模型写入任务工作区，见[多模态附件](../上下文/多模态附件.md)。

Sandbox 不 import Assistant、Runtime 或 Tools；Runtime 也不 import Sandbox；Tools 只消费 Sandbox 的窄契约。

## 配置

个人数据目录保存用户偏好、连接设置和运行资源。候选模型与新会话默认选择由用户维护，供应商密钥和本地地址单独保存；它们的变化原因不同，密钥不经过 Web。会话自身保存独立的模型选择，见[会话模型选择](../入口/会话模型选择.md)。

工作区有自己的资源清单，不混入模型偏好或连接配置。个人数据根可以整体更换；同一台机器并行运行多个实例必须分开数据根，见[自举开发](../../自举开发.md)。

配置在外部边界严格解析，消费者使用领域内部类型。模型偏好在决策边界读取，连接设置在调用边界热更新；首次缺少个人配置时创建初始文件，连接尚未填写也可启动 Web 配置页面。损坏的持久配置原样暴露，不采用旧值兜底。
