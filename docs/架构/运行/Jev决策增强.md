# Jev 决策增强

## 定位

机械判定是独立可用的基础能力，Jev 是可选的语义决策增强。第一版只检查正在自动推进的任务是否可能出现环路或执行链路异常；等待诊断暂缓。

机械判定只观察严格重复行为并提醒，不判定任务无进展、不自动中断。Jev 可以选择继续、提醒或暂停；暂停权限显式授予 Jev，不由代码按次数升级。

## 旁路边界

LoopGuard 的机械检查和 Jev 检查都属于 Assistant 的独立旁路。主决策流程不调用、不等待、不解释检查器，Step 提交、历史重放和上下文投影不承载检查器专属流程。Runtime 不认识 Jev，也不判断环路、进展或任务含义。

旁路只读已提交执行事实，通过通用系统消息入口和现有中断入口施加干预。以后增加检查策略，也只改变旁路；主链路只处理通用消息和控制。

检查器不绑定决策元数据，提醒只有通用系统消息这一条接入路径。机械判定规则和仅提醒的动作边界独立于 Jev 保留。

## 机械基础与可选增强

| 情况 | 最终判定 |
|---|---|
| 用户不启用或未配置 Jev | 使用机械判定 |
| Jev 超时、发生已知调用或协议失败、响应不合法或置信度不足 | 使用机械判定 |
| Jev 返回满足置信度要求的有效判决 | 使用 Jev 判决 |

同一次检查先计算机械结果；启用 Jev 时，在旁路内以有界超时等待它的结果，失败则使用已经计算的机械结果。主执行链路始终继续运行。同一次检查只执行一个最终判决，不先发送机械提醒再应用 Jev 判决。

有效的“继续”表示本次不干预，不是调用失败，也不触发机械降级。Jev 不可用时，机械判定仍然只提醒，不因失去增强能力而获得中断权限。

降级只转换可明确识别的外部服务或协议失败；内部契约违规、持久化损坏和未知异常原样暴露。失败诊断不伪装成有效判决，也不写成主任务的模型失败。

## 动作与固定提示

Jev 只选择动作，不生成解释、理由或提示文字。

| 动作 | 处置 |
|---|---|
| 继续 | 不干预，不代表任务完成 |
| 提醒 | 投递固定系统提醒，供后续主模型决策读取 |
| 暂停 | 复用现有 `cancel_turn` 中断，生效后通知用户或父模型 |

“暂停”完全沿用现有中断语义：停止当前模型调用、打断支持中断的在途命令并关闭自动续跑。已发生的副作用不回滚，未知结果与后续恢复也沿用既有契约，不新增暂停状态或恢复协议。

主模型提醒、父模型通知和用户界面警告使用固定文案，不编造 Jev 未提供的具体原因：

| 场景 | 文案 |
|---|---|
| 提醒主模型 | 任务可能出现环路或执行链路异常，请审视当前做法并决定下一步。 |
| 子任务中断后通知父模型 | 子任务可能出现环路或执行链路异常，已暂停，请检查并决定后续处理。 |
| 主任务中断后的界面警告 | 任务可能出现环路或执行链路异常，已暂停。 |

子任务与主任务使用相同的中断语义，差别只在通知接收方。用户或父模型沿现有入口决定后续处理；Jev 不自行恢复执行。

## 触发与有效期

Jev 按已完成的主模型 Step 数量间隔发起检查，不叠加工具族频率、修改文件次数或所谓无进展时长等多套触发规则。正常等待中的会话不因检查而被唤醒。

每个会话最多有一次检查在进行。检查期间主链路继续推进，再次达到间隔也不积压请求；下一次检查取新的执行快照。

普通执行进度前移不使判决失效，提醒和中断允许延后生效。新的用户输入、当前自动执行链结束、中断或恢复会使旧检查失去适用范围，迟到判决不能干预后续执行链。

## 状态输入

每次检查固定一个 Journal 截止位置，从截至该位置的事实及其引用的已保存材料确定性地构造状态，不从 Host 可变内存拼接任务含义。

状态只提供：

- 任务要求与有序的用户修正，保持原文，不由代码归纳目标。
- 当前工作计划及正在进行的事项，如有；计划记录不冒充完成证明。
- 最近若干完整 Step 中的工具名、参数要点、结果和已有操作时间记录。
- 近期主模型回应、已经投递的提醒，以及提醒后的解释和执行行为。

操作发起、实际开始和结果返回按已有记录区分；尚未开始、尚无结果或内容被省略均明确标记，不把发起时间当成执行时间，也不把缺少结果当作失败或未执行。代码不定义“上次进展”、不生成“无进展时长”，进展与异常判断全部交给 Jev。

状态保留原文语言，以数千 token 的短输入为设计目标，保持完整调用批次及调用与结果的对应关系。参数选择与文本裁剪采用固定规则；预算不足时减少较旧的完整批次并标明省略，不增加摘要模型调用，也不按代码猜测的重要性筛选证据。

Compact 后复用已接纳的交接摘要作为背景，并保留最新要求、当前计划及近期执行记录。交接摘要不单独替代近期操作证据，也不因窗口切换重置检查范围。

## 固定英文判决题

使用一道 Choice 直接选择动作。题目与选项描述固定使用英文，状态可以保留中文原文，不叠加其他评分或连续命中计数来替模型决定处置。

题目要求依据任务、计划、操作结果、操作时间及已有提醒选择干预程度；明确重复、失败和耗时本身不足以证明环路，明确暂停会中断当前调用和正在运行的命令。各选项区分合理探索、仍可自主纠正的疑点，以及缺少有效纠正且不宜继续自主执行的明确异常。固定题目正文由代码维护。

提醒次数不决定暂停。提醒后的回应和新结果属于下一次判断的证据；有充分依据时 Jev 可以直接选择暂停，不要求先走完提醒流程。

## 历史与上下文语义

旁路检查的触发、计数、请求和中间判定不进入 Session Journal，不绑定 Step 提交。实际投递的系统提醒和实际生效的中断沿通用消息与控制事实保留历史，能够解释后续模型行为及执行停止的来源。

上层事件与会话投影保留系统来源，提醒不冒充人的输入、不计入用户要求。模型协议角色只在底层消息组装时映射；提醒位于完整工具响应组之后，不破坏工具调用与返回的配对，也不改变以真实用户输入为依据的脱水保护边界。

已经发出的模型请求不追加内容，也不为送达提醒而取消重发；提醒供后续调用读取，不单独唤醒已经结束自动推进的会话。

Journal 快照及其引用材料可重建检查输入；再次调用 Jev 属于重新评估，不保证复现原判决。恢复只读取已经发生的提醒与控制事实，不重新调用 Jev 来复现历史干预。

## 中文场景校准

固定模型版本、英文题目和状态构造规则，从真实中文任务的 Journal 截取状态样本，以人工参考判决分别校准提醒与暂停的置信度门槛，再用未参与调参的样本验证。重点关注正常探索被误暂停、提醒打扰和明确环路漏检。

置信度门槛只决定是否执行选中的动作；不足时使用机械判定，不把暂停改成提醒，也不根据累计次数升级。官方示例阈值不直接作为产品依据。模型版本、题目或状态裁剪方式变化后，需要重新验证既有校准结果。

接口与模型限制以 [Choice](https://docs.typesafe.ai/primitives/choice)、[State](https://docs.typesafe.ai/concepts/state)、[Models](https://docs.typesafe.ai/models) 和 [Jev 模型限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13) 为依据。

## 明确不做

- 第一版不做等待诊断、命令风险判断或 SubAgent 完成判定。
- 不让主执行链路等待检查，不把 LoopGuard 或 Jev 专属流程扩散到决策、提交、重放和上下文投影。
- 不由 Runtime、机械计数或置信度分档替模型判断是否需要暂停。
- 不用 Jev 替代主模型规划、生成文本、选择工具或调整计划。
- 不为可选增强建立通用 Advisor 框架、策略插件系统或另一套中断恢复语义。
