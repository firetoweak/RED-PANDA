# 打断

> 打断终止仍在前台等待的命令，被终止的 Attempt 得到「已中断、结果未知」的终局。**中断不降级成失败，现场由模型收拾。**

不是新入口，是 `cancel_turn` 的语义扩展：原来只关闭自动续步权、让 Command 跑完，现在同时终止该 Step 仍在前台等待的命令进程。见 [Runtime · 取消当前自动决策链](Runtime.md#取消当前自动决策链)。这是一条窄协议，不是通用 Cancel。

## 为什么现在才做

终止进程树的能力一直都有，超时路径已经在用。挡住打断的是没地方安放「不知道它干了什么」——Attempt 一被终止就是 unknown，而未知不得降级成普通失败。

现场由模型收拾的前提是现场不再变化：一个打断之后仍在写文件的进程，会在模型读到中断结果之后继续改动工作区，模型看到的现场随时失效。**所以打断必须真的终止进程，不能只是放手不再等待。**

命令已经造成的文件改动与外部副作用不会因打断而撤销。中断事实要如实划出这条界线，不暗示一切都能撤销。

## 不变量

**顺序是关续步权、终止、记录。** 三步各有理由：续步权不先关，中断终局会在它还开着时落库，模型不知道本轮已取消就多走一步；记录早于终止，会在杀不掉时说谎。终止本身失败是未知异常，原样暴露；终止之后、记录之前 Worker 退出留下的未知 Attempt，按命令身份向仍存活的 Host 查询补报；Host 已退出则按前台结果未知处理。

**中断不是失败。** 用独立结果码表达「已中断、结果未知」，不复用任何失败码，也不自动重试。已知外部失败可以转换，取消不得降级——这是 [Runtime](Runtime.md) 的既有不变量，打断不是它的例外。

**中断终局必须能投影成一条工具结果。** 模型协议要求每个调用有配对结果，[Compact](../上下文/Compact.md) 也不允许拆开调用与结果。中断因此必须产出可投影的终局，不能只留一个悬空的 Attempt。

**打断作用于该 Step 全部在执行的 Command。** 停哪个是语义判断，而用户说的是「停」。Step 提交后、命令派发完之前到达的打断也算：关闭续步权要等这个 Step 的命令全部派发完，否则排在后面的命令会在打断之后才启动、无人终止。

**部分输出是证据，不是结果。** 已经捕获的输出如实保留——模型需要它判断跑到哪了——但必须标明它不构成结果，不能被当成命令的产出。

**不自动回退。** 打断本身不许顺手动文件：要不要撤销已经发生的改动不归打断回答，Runtime 只把现场如实摆出来，由模型或人用 Git 等手段收拾。

## 竞态

终止请求与 Outcome 自然到达会撞车，走投递幂等：同一投递 id 只接纳一次，先写入的终局胜出。SubAgent 的结束与消息确认也遵守同一投递身份只接纳一次，见 [SubAgent](SubAgent.md)。

## 范围

只打断仍在前台等待的 `execute_command`。已返回「已转后台」的调用已终局，暂停会话不停止后台命令；需要结束它时使用独立的停止动作，完成事实仍可靠送达。文件写工具本身很快，打断的收益接近零；MCP 工具的取消需要协议层支持。为所有工具预建统一取消协议是替不存在的问题加抽象。

## 不做

- 通用 Cancel，或为所有工具预建取消协议
- 自动回退、自动重试
- 把中断降级成普通失败，或塞进调度器的失败回调
- 从用户文本推断「停」（打断是显式动作，普通后到消息仍走原规则）
- 打断终止 Session，或为它新增 Session 终态
- 选择性打断一个 Step 里的部分 Command
- 给整个 Agent 任务加总超时，或建通用超时框架：超时只是具体操作的资源限制——模型请求由模型客户端管理，工作区命令只设置前台等待时长，到点转后台，不设置总运行期限；系统内部处理只计时不设超时，等待用户不自动超时
