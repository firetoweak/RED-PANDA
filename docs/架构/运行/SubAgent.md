# SubAgent

> 子 Agent 是本次任务里的临时协作者。它的普通回复直接送给父 Agent；回复、等待新消息或自称完成，都不结束协作。父负责验收并明确结束。

父子各有独立 Session、进程、历史和工作目录，执行边界见[多活跃会话](多活跃会话.md)。父子关系属于 Assistant，Runtime 不理解委派身份或任务是否完成。

## 为什么保留独立会话

上下文隔离是主要理由，并行是次要理由。父只收到子的普通回复与明确的执行失败，不自动接收完整思考和工具过程。人可以从独立观察页旁观；观察不改变执行，也不把完整过程塞进父的上下文。

子是临时协作者，不因此成为长期 Bot 名册成员。它看不到父的对话，父交代任务或追加要求时必须给足背景。

## 自然回复与任务判断

子正常说话就是对父说话。成果正文、分批交付、进度、阻碍和澄清都通过普通回复表达，不要求另用回复工具或结束工具。协议形态与实际收件人一致，避免模型已经写出答案而父收不到。

**回合收口、等待消息和协作结束是三件不同的事。** 子说完一轮后可以等待父；父可继续追问、要求修改或补充下一批。即使子说“已完成”，也只是供父验收的陈述，系统不从正文推断完成。

父理解用户目标并验收实际成果，决定是否继续；验收完成、任务取消或不再需要时，父显式结束协作。结束停止子的执行，保留历史与文件，不能再向这项委派追加要求。需要重新开展工作时重新委派。

普通回复送达让父获得判断机会；子同时还在执行工具时，原工作照常推进。只剩等待新消息时保留协作关系，不自动续问、不循环唤醒，也不强迫子用空确认维持运行。

## 指令与结束的边界

父可以询问、追加指令、调整方向，也可以让等待中的子继续。正在执行时，追加指令打断当前思考，等待已发出的工具收尾；原历史、工作目录和已经发生的改动保留，新的要求如何改变目标交给模型判断。调整方向不回退副作用，也不创建新的子任务。

正常结束由父决定；明确的模型失败、未知异常或恢复发现执行结果未知，仍作为执行失败通知父并结束这项协作。保留原始原因，不降级为无产出或自动重试。未知异常同时向人暴露；通知父不代替故障诊断。

结束与追加指令遵守同一项协作的先后关系。已经接纳的同一指令恢复时只确认，不再次打断。结束后拒绝新回复，但已经送达的旧回复仍可确认，不能因确认丢失而重复投递。

用户插话只取消父当前执行，不自动结束子协作。父自行判断保留、继续、调整或结束哪些子；系统不从人的文本替父做判断。用户明确停止父会话时，父的所有未结束子协作一并结束，父保持暂停，子的消息不能自行解除它。

## 可观察状态

父可以查询自己委派的子当前是否正在执行、等待消息、暂停或已经结束。状态只表达实际执行情况，不代表完成百分比，也不从工具过程生成语义进度摘要；需要进展时父直接问子。

保留协作不等于正在干活。父本轮空闲时不因为还有子协作就被标成执行中；页面可以保留中性的未结束协作提示，子观察页独立显示运行或等待。

## 可靠投递与恢复

初始任务、父的追加指令、子的普通回复与协作结束分别留在相应历史里，标明来源，不伪装成人的输入。每条子回复有自己的稳定身份；回复送达但确认丢失时，恢复核对原消息，不重复投递，也不将它误判为任务失败。

委派确认只表示子已创建，不等待它交稿。创建恢复认回同一子身份，不能因确认丢失多创建一位。父在恢复时找回自己的协作，子独立恢复时也认回父及能力边界。

未结束协作集合由已委派、确定创建失败与明确结束这些事实推导，不维护第二份计数。每个子只结束一次；并行子之间的通知不需要攒齐，父决定哪些回复会影响当前结论。

上下文压缩沿用普通会话规则。等待父不作废后台交接；协作结束或执行失败才成为截止边界，见 [Compact](../上下文/Compact.md)。

## 文件与能力

普通会话以及未指定项目的子只读父的目录；任务要求修改时，子自然回复建议或正文，由父决定怎么处理。指定项目的子从父已提交的工作切出自己的 worktree，允许改文件，看不到父未提交的修改，也不直接改父的目录。

父可以在子停下来等待消息时比较成果，不必先结束协作。需要修改时继续指挥同一个子；合入仍由父单独决定，不因回复或结束自动发生。比较与合入只针对当时可核对的文件成果，不能把子自述当作验收依据。子正在执行时先等待或明确结束，不能并发整理它正在修改的文件。

内建工具采用显式名单，新增能力默认不进入子。子不能执行命令、再次委派或指挥兄弟；修改权限取决于是否有独立项目副本。外部工具只提供已声明只读的 Server，仍按需加载，不另造一套能力供给机制。授权与能力边界见[工具与能力](../能力/工具与能力.md)。

## 不做

- 为普通回复另设必须调用的消息或终局工具。
- 从模型正文猜测任务完成、自动结束，或按空闲时长收回。
- 把子完整执行过程自动送给父，或让子读取父的上下文。
- 让 Runtime 理解目标、验收成果或决定协作者是否还需要。
- 把临时协作者直接扩展成长期名册成员或递归委派树。
