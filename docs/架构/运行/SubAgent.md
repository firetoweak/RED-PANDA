# SubAgent

子 Agent 是本次任务里的临时协作者，与父共享工作区，拥有独立会话、上下文和执行过程。父负责分工、调整、验收和回收；Runtime 不理解委派目标或任务是否完成。

## 共享文件，独立上下文

子直接读写父的真实工作区，能看到未提交内容，修改立即相互可见。可指定已有的起始目录，访问与授权边界沿用父的执行环境。无项目的任务同样可以修改文件和运行命令。

目录安排、修改范围、并行顺序、Git 分支和提交由父按任务决定。系统不为子建立工作树，不替子提交，不提供专用比较、合入或冲突解决流程。共享工作区不承诺并发修改安全；父应安排协作并核对实际成果。

独立上下文减少父接收执行细节的负担。子看不到父的对话，父必须交代必要背景；父只接收子的普通回复与执行失败，可以按需观察过程，不自动复制完整历史。

## 能力与授权

子具备任务所需的文件、材料、图片读取与修改、命令和后台命令能力，可按需加载 Skill、CLI 和外部工具，包括浏览器。沿用现有执行与授权，不因子身份免除文件写入或命令授权，也不以沙箱接入作为开放能力的前提。命令的实际边界见[执行环境](../能力/执行环境.md)。

基础工具采用显式名单，新增能力默认不进入子。团队通信、长期安排、扩展安装管理与再次委派保留给父。父交代任务不构成人的授权；需要人的决定时，子报告给父，实际工具请求由人的入口处理。

后台命令的完成结果回到启动它的子，供其继续分析、修正和验证。子向父提供结论、实际检查证据和未验证范围，父决定是否接受，不能把子自述当作验收。

## 自然回复与调整

子普通回复直接送给父，可以表达成果、进展、阻碍和澄清。回复、等待新消息和结束协作是三件不同的事；子自称完成只供父判断，不自动结束。

父可向同一个子追加要求、询问或调整方向，保留历史、目录与已发生的改动。新要求如何改变任务由模型判断，系统不从正文推断停止范围或自动广播用户消息。

父在子工作期间可以正常回复人；一轮对话结束不表示委派结束。父理解目标并验收实际成果，决定继续还是回收。

## 回收与资源

父在验收完成、取消或不再需要时必须显式回收，并确认成功。系统不从自然语言或空闲时长判断任务完成，也不要求父每次回复前回收仍在进行的任务。

回收停止子执行与新操作，收口已经发出的命令启动，停止属于子的前后台命令，并关闭子持有的会话连接。资源回收成功后才确认协作结束；失败原样暴露，不能宣称资源已经释放。共享文件、成果和历史保留，不回退修改。

命令归属用于准确停止，不限制父子共享文件。外部工具已经产生的持久副作用不能因断开连接视为撤销，须按对应工具的实际能力处理。受管进程与平台边界见[执行环境](../能力/执行环境.md)。

明确结束后拒绝新指令和新回复；已经送达的回复仍可确认。重复回收认回原结果，回收期间的旧完成通知不能重新启动子工作。

## 投递与恢复

任务、追加要求、普通回复和结束分别留在相应历史，来源明确，不伪装成人的输入。委派只确认子已创建，不等待交付；确认丢失时认回同一身份。回复重投只接纳一次，不因确认未知误判执行失败。

未结束协作从委派、确定创建失败和明确结束事实推导，不另存计数。并行子逐个回传，由父判断哪些结果影响当前任务。

明确的模型失败、未知异常和恢复发现结果未知仍如实交给父，未知异常同时向人暴露；不自动重跑可能已经产生副作用的操作。上下文压缩沿用普通会话规则，等待父不作废后台交接，结束协作才成为截止边界。

## 不做

- 系统强制父子分支隔离、自动提交或合入。
- 用自然语言判定完成、自动验收或按空闲时间回收。
- 为子再建执行器、通用任务引擎或递归委派树。
- 把子扩展成长期名册成员，或把完整过程自动塞给父。
