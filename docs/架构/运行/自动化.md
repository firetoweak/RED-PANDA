# 自动化

自动化让模型在任务进行期间，**自主决定何时再次观察，并根据新结果调整行动**，无需用户逐次发消息推动。

典型场景是检查一个运行中的系统：模型自己编写并运行检查脚本，分析当前结果，估算下一次值得检查的时间并安排唤醒；到点后再次观察，根据变化决定修正脚本或执行方式、继续等待，或报告完成。检查间隔、检查内容、修正策略与结束时机都由模型根据目标和观测结果决定。

当前以**一次性定时唤醒**支撑这一闭环。模型登记下一次检查后，Command 立即结束；Host 负责计时，Automation 作为非 Channel 的外部事实源，在到期时向原 Session 投递一条要求决策的事实。事实携带计划时间和实际触发时间，让模型有明确的时间依据继续判断。模型需要继续观察时，再安排下一次唤醒；持续观察由这些模型决策串起，Runtime 不内置检查频率，也不判断任务进展或替模型选择行动。

长期 Agent 另有**例行任务**：它自己的长期安排，由名字、写给未来自己的意图与时间表组成。时间表是按 Host 本地时间解释的 5 段 cron，或固定间隔，两次运行至少间隔 5 分钟。Host 只决定「什么时候」；每次到点，Automation 向这个 Agent 的时间线投递一条要求决策的事实，带名字、意图、计划时间与实际触发时间，做什么仍由模型当场判断。例行任务与人的消息、同事私信排在同一条时间线里，天然串行，不另开会话。

例行任务由 Agent 用工具新建、改写、暂停、恢复与删除，不经人确认；每个请求以发出它的 Command 为身份只生效一次，恢复时按原身份取回原结果。改写会让按旧定义安排的触发作废：一次触发的身份由例行任务、定义版本与计划时间组成，记录触发与推进下一次时间在同一个事务里完成，记下但尚未送达的触发在 Host 重启后按原身份补投。Host 停机期间错过的时间点不逐个补发，恢复后至多补一次。时钟可能比计划时间早一点醒来，下一次时间总是从计划时间与当前时间中较晚的那个算起，不会把刚触发的时间点再排一次。

人在 Web 上可以暂停、恢复或删除任何例行任务；人暂停的，Agent 不能自行恢复或删除。人看到的时间安排是这份时间表的可读说法，读不出时保留原文。每次触发留下计划时间、实际触发时间和是否送达；人按时间倒序查看。已送达的触发就是时间线上的那条事实，可以从记录跳到 Bot 当时的回复。人长时间不在 Web、未读汇报和触发次数都到了门槛时，Host 先在对应 Bot 的对话中询问，仍无回应则暂停当时仍在运行的例行任务；人恢复时只恢复这次暂停的那些，Agent 同样不能自行恢复。压缩之后，例行任务清单与名字、方向、所在群一起在新窗口里重述。

定时身份来自已提交 Command 的身份。Automation 持久保管计划时间、首次触发时间与投递进度；Worker 退出后时钟仍由 Host 运行，Host 重启会补投逾期项。同一项重试沿用同一个投递身份和同一份事实内容，Journal 只接纳一次。确认事实进入 Journal 后才标记投递完成。

模型可以撤销本 Session 中尚未开始触发的检查。目标变化、提前完成或观察已无必要时，由模型主动取消对应定时项；取消后不再唤醒，前端展示随剩余定时项更新。取消与首次触发按持久化顺序决定胜负：取消先完成则不触发；触发先开始则明确返回无法撤回，已产生或正在投递的时间事实继续保留。重复取消已取消的定时项仍视为成功，重启不恢复已取消项。

Command 的 Attempt 若在登记或取消之后、Outcome 之前中断，只对这一类有稳定身份的定时操作核对并补交结果。取消结果与其 Command 身份一起持久保存，恢复沿用原结果。恢复不盲目重跑其他未知副作用。

前端倒计时只是待触发定时项的展示投影。归零不代表检查完成；检查由到期事实唤醒后的模型决策完成。

一次性定时与 SubAgent 不合并成「后台任务」机制。长期 Agent 的周期性职责由例行任务承担，方向见 [Coding Bot](../CodingBot/方向.md#例行任务与验证闭环)；文件监听不在方向内。
