# 自动化

自动化负责“何时再次判断”，不决定观察什么、是否有进展或何时完成。模型依据目标与观测选择行动，定时只把一个新的时间事实送回原 Session。

## 一次性唤醒

模型安排下一次观察后，登记调用即结束，由 Host 计时，到期投递计划时间与实际时间。要继续检查时由模型再安排，不内置轮询频率或任务完成判断。Worker 退出不影响时钟，Host 重启会按原身份补投逾期项。

定时、投递和结果沿用稳定身份，同一项重试不重复接纳，确认进入目标 Journal 后才算送达。登记或取消已经发生但结果确认丢失时，只核对并补交原结果，不盲目重跑其他未知副作用。

模型可取消尚未开始触发的安排。取消先完成就不触发，触发先开始则明确无法撤回并继续送达；重复取消认回原结果，重启不恢复已取消项。前端归零只表示到时间，不证明检查完成。

## 例行任务

长期 Bot 可保存自己的长期安排：名字、给未来自己的意图与时间表。每次到点成为新的行动源头，进入同一长期时间线，不新建任务会话；做什么由模型当场判断。

Bot 可创建、改写、暂停和删除自己的安排，无需逐项确认；实际副作用仍受原有授权。人可在 Web 控制，人的暂停不能由 Bot 自行恢复或删除。

改写只影响尚未发生的安排。每次触发保留当时名字、意图和时间，后续补投或历史不能拿新定义覆盖；记录触发与推进下次时间必须一致，重启按原身份补齐未送达触发。停机错过的多个时间点至多补一次，不追赶全部历史，也不把刚触发的时刻再安排一次。

时间表按 Host 本地时间解释。前端读取正式安排与触发记录，展示可读时间、暂停来源、计划与实际触发及送达状态；已送达记录可定位原回复。上下文压缩重述例行任务，不靠摘要保管安排。

## 无人查看时的取舍

每次触发都是新源头，单次通信额度不能限制长期空转。因此在人长时间离开、未读汇报与触发次数都达到条件时，先向人询问，仍无回应再暂停当时在运行的安排并告知 Bot。

恢复只作用于这次暂停的项目，不动人或 Bot 另行暂停的安排。条件是确定的时间与计数，不能解释任务是否有价值，人的选择由 Host 执行。

自动化不与子协作合成通用后台任务机制，也不监听 GitHub webhook。观察仓库、版本和验证结果的方法由项目 Skill 维护，后续问题见[方向](../CodingBot/方向.md)。
