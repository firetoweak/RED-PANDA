# 会话进程与恢复

每个活跃 Session 在独立 Worker 中拥有自己的执行循环、Runtime、工具、MCP 客户端与 Journal。模型调用经 Host 级接口复用 Provider 客户端。进程隔离的是会话执行的故障域，产品级资源不必因此逐会话复制；独立进程不等于安全沙箱，也不把每个工具调用再拆成一个进程。

当前内存驻留、卸载代价与存储访问路径见[运行机制](运行机制.md)。

## Host 与 Worker

同一数据根只有一个 Host。它必须先独占数据根、完成旧执行接管，再开放定时投递和外部入口；第二个实例明确报错。占用随持有进程结束释放，Worker 不跨 Host 存活，这使启动恢复可以确信没有旧写入者。

Host 负责定位会话、保证单个 Worker、投递事实与唤醒、路由父子回传和维护入口选择。它不解释消息正文、不归约 Runtime 状态，也不决定任务是否完成。执行可否推进仍由对应 Journal 与 Runtime 判断。

不同页面连接分别声明正在查看的会话。这个选择只决定空闲 Worker 驻留和回复路由，不产生人的授权；Session 静止与 Worker 是否存活是两件事。

## 进程身份

本地进程沿用启动者的操作系统身份，文件和命令权限随该身份。产品内部工具环境与工作区命令的启动环境分开准备，用户项目环境不能被产品补全覆盖；命令按明确环境查找 Shell，不扫描项目猜解释器。

Worker 不继承 Channel 的协议管道。Web、TUI、子 Agent 与后台交接走同一套启动约束；缺少环境或无法构造时如实报告，不因入口不同隐藏例外。

Windows 补全本机用户会话环境并保留调用方已有设置；其他平台不为未经实测的环境差异预建登录环境模拟。

## Worker 生命周期

Worker 只处理一个 Session，打开对应 Journal，重建投影并推进。模型调用或前台命令未结束时保持存活；静止后有入口选择则继续驻留复用连接，没有则可退出。待人确认的提案活在事实中，不靠进程内存保住。

退出需与 Host 确认当前没有尚未接纳的请求，确认期间有新活动就继续工作。启动或退出中到达的投递等待这次转换，事实可靠写入目标 Journal 后才能确认送达。

未知异常结束 Worker 并由 Host 原样暴露，不因页面仍在查看就自动重启。下一次真实请求再恢复；待确认事项可重放，已经开始但结果未知的操作不自动重试。Host 还须清除旧进程的运行、预览和工具活动展示，但不能补写工具终态。

Host 重启后，原来仍会自行推进的顶层 Session 自动接续；静止父会话如仍有子协作，也要恢复原关系，子只随父恢复。已经批准但尚未开始的操作可继续，待批准仍等待，结果未知仍保持未知；仅等外部输入的会话不提前拉起。

停止当前轮不形成持久暂停状态，后续消息和结果照常接纳。后台命令不延长 Worker 驻留，按[执行环境](../能力/执行环境.md#命令生命周期与后台执行)的独立生命周期补报结果。

## 事实与进程的边界

每 Session 一个 Journal，避免不同会话竞争写入和扫描无关历史。Host 的查询缓存可以丢弃，后续读取仍须看见新事实，缓存不能参与幂等接纳或恢复判定。

跨进程只传应用请求与生命周期信号，不复制 Runtime 状态。投递成功以目标事实已经接纳为准，进程失败保留原异常，不改写成普通工具结果。

产品配置与扩展登记按数据根共享；任务文件范围由会话绑定。长期 Bot 的任务根是个人目录，挂载项目不改变这一绑定，见[多智能体](../多智能体/总览.md#项目归属与执行目录)。

## 父子 Session

子协作与普通会话使用相同进程和 Journal 边界，父子关系属于 Assistant。委派先在父侧形成事实，再按稳定身份确保子任务存在，最后启动子 Worker；派出成功不表示任务完成。父不持有或等待子进程，可以先静止退出。

子回复先保存在自身事实中，再可靠投递给父；恢复沿用原身份重投，父只接纳一次。父从自己的未结束委派恢复协作，不扫描无关会话。子空闲不等于结束，成果是否足够由父判断并显式回收。

## 租约与接管

租约到期只允许竞争接管，不能据此宣布正常但停顿的执行者失败。只有成功接管才产生新执行代次；原执行者提交与新执行者接管原子竞争，最多一个有效写入者，没有接管时原执行者恢复仍可提交。

时间经过本身不能制造结果未知。接管确认旧执行者已不再运行后，按 [Runtime](Runtime.md#副作用与恢复)记录其未完成执行，保留原 Attempt 与全部证据。

子若尚无回传而旧执行中断，就经原回传通道告知父结果未知、未自动重试及相关操作；已有回传优先，恢复只重投，不重新调用子模型。未知异常退出前也要尽可能先保存回传并暴露原错误，Host 释放失败进程后再投递，不能让回传等待形成死锁。

子任务事实与 Journal 必须在首次启动前原子建立，使初始化失败也能找到父。持久化损坏不能被补成普通失败。本阶段只保证父知道中断，不建设子会话续跑或通用恢复协议。
