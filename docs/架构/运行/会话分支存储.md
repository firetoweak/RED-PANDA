# 会话分支存储

会话历史是有序 Event 流。分支固定来源历史的截止位置，继承那段不可改写的事实，只保存自己后续新增的事件。来源继续追加或再次分支，都不改变已经固定的历史。连续派生展开为有序的来源区间；读取不必沿父子身份逐层追溯。

Session identity 是逻辑历史的身份，不是某一份 Journal 文件的位置。分支重放按区间拼接事件，以当前 Session identity 归约。Step 的依据由所见事件确定；共享的 Step 不因读取者身份不同而改写。历史 Command 只作为事实重放，不重新执行。

## 写入与恢复

每条 Session 仍有独立 Journal，且只向自己的尾部追加。Step 领取、决策消费、Command 与 Attempt 的可变事务状态都属于当前 Session；继承历史只读，不能把来源的索引当作自己的可变状态。分支创建与推进不进行跨会话数据库写事务。

数据库事务只覆盖有界的事实与索引写入。模型调用、状态归约、文件操作与等待不占有事务。长历史可以分段读取并在进程内缓存不可变前缀；缓存可丢弃，Journal 仍是唯一持久事实源，不引入另一套服务存储。

## 附件与工作区

Artifact、图片与上传文件的原件留在写入它们的 Session。后代按继承的引用读取同一原件，材料视图在自己的 Session 下生成。编辑消息从目标消息之前分支时，目标消息携带的附件引用会随编辑后的新消息继续使用，即使目标消息不在继承前缀内。

会话回退创建新身份，不裁剪旧身份的事件或原件。工作区回退只改共享的文件轨道；产品数据不随之回退。本机路径挂入的文件仍是外部路径引用，路径后来消失就无法读取，不获得上传快照的保留保证。

## 生命周期

改写顶掉身份、归档身份都不删除它；旧身份仍可打开。将来显式删除某个身份时，先使它不可见，再按仍存活会话引用的历史区间与原件判断回收。只要后代依赖，底层事实和原件就保留；最后一个依赖消失后才可回收。当前没有删除入口，也不主动回收孤儿附件。

## 不做

- 不复制完整事件前缀或附件目录来创建分支。
- 不让工作区文件版本轨道承担 Journal 的分支存储。
- 不共享两个 Session 的可变事务索引，不用 Redis 充当第二事实源。
