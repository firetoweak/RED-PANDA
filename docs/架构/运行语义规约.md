# 运行语义规约

跨层判断先分清“这是什么状态、谁拥有它”，再看具体协议。本文保留共同不变量，事实推进见[Runtime](运行/Runtime.md)，进程驻留见[会话进程与恢复](运行/多活跃会话.md)。

## 四条约束

**运行事实先提交，再进入判断。** 稳定系统规则、静态工具契约与显式配置属于决策机制；会变化且要被当作已经发生的内容必须先提交。预览、进程内存或前端缓存不能冒充缺少的事实。

**每种状态只有一个所有者。** 其他层只查询、投影或缓存，缓存可丢弃，投影可重建。当前产品值与“会话当时观察到什么”是不同对象，例如[记忆](上下文/记忆.md)的当前正文不能由旧观察或摘要反向恢复。

**不同生命周期使用各自身份。** 会话、消息、决策、命令、执行尝试和连接不能混用。跨异步边界明确关联对象，不靠到达顺序、列表邻接或“当前那一个”推断归属。

**无法确定就保持未知。** 进程退出或确认丢失不能证明副作用成功或失败，也不能据活动、时间经过或后续行为补写终态。结果未知不自动重试，实时运行叠加丢失后仍回到事实中的未知。

## 状态归属

| 状态 | 所有者 | 其他层的边界 |
|---|---|---|
| 已提交输入、决策、执行与授权事实 | Journal | 追加与重放，不原地改写或补猜终态 |
| 执行可否推进、命令等候与结果归约 | Runtime | 读取投影，不从进程或 UI 反推 |
| 文件与实际提交、分支和合并关系 | 真实目录与 Git | 直接读写或比较，不复制另一套文件历史 |
| 能力激活、当前计划、名册等事实投影 | 对应应用投影 | 从正式来源重建，不由缓存改写 |
| 偏好、当前记忆、扩展登记与外部会话关系 | 对应产品存储 | 查询同一份值，需要成为模型运行依据时提交观察 |
| 某次执行的瞬时活动 | 对应 Worker | 按精确身份叠加，不作为可重放终态 |
| 进程驻留、连接选择、当前失败与对外活动 | Host | 提供查询与通知，不代 Runtime 裁决 |
| 预览、草稿、滚动与折叠等展示 | 对应连接或前端 | 不参与后端恢复、调度、授权或模型判断 |

## 评审用法

新增状态前，明确类别、唯一写入者、跨异步边界的身份，以及来源丢失后能否重建。不能重建时必须如实保留未知，不能找另一个缓存来接管事实。

所有权调整要明确改变契约并删除旧写入路径，不靠层间同步维持双轨。字段和具体状态枚举以代码为准，不在本文维护实现清单。
