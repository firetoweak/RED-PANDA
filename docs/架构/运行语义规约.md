# 运行语义规约

本文规定单会话执行与多智能体协作共用的不变量，作为跨层设计与评审的依据。先分清状态属于哪个对象、谁拥有它，再看具体协议。事实推进见[Runtime](运行/Runtime.md)，进程驻留见[会话进程与恢复](运行/多活跃会话.md)。

## 四条约束

**运行事实先提交，再进入判断。** 稳定系统规则、静态工具契约与显式配置属于决策机制；会变化且要被当作已经发生的内容必须先提交。预览、进程内存或前端缓存不能冒充缺少的事实。

**每种状态只有一个所有者。** 按业务对象与作用域确定唯一权威来源，其他层只查询、投影或缓存，缓存可丢弃，投影可重建。当前产品值与“会话当时观察到什么”是不同对象，例如[记忆](上下文/记忆.md)的当前正文不能由旧观察或摘要反向恢复。

**不同生命周期使用各自身份。** 会话、消息、决策、命令、执行尝试和连接不能混用。跨异步边界明确关联对象，不靠到达顺序、列表邻接或“当前那一个”推断归属。

**无法确定就保持未知。** 进程退出或确认丢失不能证明副作用成功或失败，不能仅据活动、时间经过或后续行为补写终态。领域协议可沿原操作身份核对并补交确定结果，或在已有幂等保证下补投原操作；其他未知副作用不自动重跑。没有新的确定证据，结果仍保持未知。

## 多智能体作用域

每位 Bot 在自己的 Session 中推进，Runtime 只裁决该 Session 的执行。群级协作与共享资源由对应领域维护，任一成员的运行状态不能代表整个团队的任务状态。

群记录是群消息与协作进度的权威来源；成员时间线记录各自收到的消息，不作为群状态的恢复来源。跨会话投递沿用稳定身份幂等接纳，恢复时补齐未完成投递，不从某位成员已收到或处理推断其他成员的结果。具体规则见[群聊](多智能体/群聊.md)。

消息接纳、请求模型判断、实际处理与任务验收是不同语义。收信或提醒回执不证明对方已处理，任务是否完成由人或模型依据证据判断。协作消息和自动提醒保留来源，不能产生人的授权。

## 状态归属

| 状态 | 所有者 | 其他层的边界 |
|---|---|---|
| Session 已提交的输入、决策、执行与授权事实 | 对应 Journal | 追加与重放，不原地改写或补猜终态 |
| Session 执行可否推进、命令等候与结果归约 | 对应 Runtime | 读取投影，不从进程或 UI 反推 |
| 文件与实际提交、分支和合并关系 | 真实目录与 Git | 直接读写或比较，不复制另一套文件历史 |
| Bot 身份、项目挂载、能力激活与当前计划 | 所属 Session 的应用事实 | 名册及其他投影从事实重建，不反写事实 |
| 群成员关系、群消息与协作进度 | 群 Journal，由 Host 维护 | 成员投递事实与群级进度分开，内存调度从正式记录恢复 |
| 项目登记、定时安排与触发记录 | Host 的对应领域存储 | 与 Bot 的项目挂载、会话中的触发观察分开，恢复沿用原操作与投递身份 |
| 偏好、当前记忆、扩展登记与外部会话关系 | 对应产品存储 | 查询同一份值，需要成为模型运行依据时提交观察 |
| 某次执行的瞬时活动 | 对应 Worker | 按精确身份叠加，不作为可重放终态 |
| 进程驻留、连接选择、当前失败与对外活动 | Host | 提供查询与通知，不代 Runtime 裁决 |
| 预览、草稿、滚动与折叠等展示 | 对应连接或前端 | 不参与后端恢复、调度、授权或模型判断 |

## 评审用法

新增或调整状态前，明确业务对象与作用域、权威来源、写入入口、跨异步边界的身份，以及恢复依据。

缓存和瞬态展示可丢弃或重建；应存在的权威记录缺失、损坏或不符契约时原样报错；已开始但无确定结果的操作保持未知。不能让另一份缓存接管权威状态。

所有权调整要明确改变契约并删除旧写入路径，不靠层间同步维持双轨。字段和具体状态枚举以代码为准，不在本文维护实现清单。
