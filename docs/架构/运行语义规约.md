# 运行语义规约

本文规定跨 Runtime、Assistant、Host、Channel 与前端的最高运行约束，用于设计和代码评审。它只回答“某类状态是什么、由谁拥有、其他层能做什么”，不重复各专题的具体协议。

事实与推进以 [Runtime](运行/Runtime.md) 为准；进程与驻留以[多活跃会话](运行/多活跃会话.md)为准；入口、输出和 Web 展示分别见 [Channel 接入契约](入口/Channel接入契约.md)与 [Web](入口/Web.md)。专题文档与本文冲突时，应先判断状态归类和所有权是否发生了明确调整，不能在实现中形成隐式例外。

## 最高规约

### 1. 只有已提交的运行事实能够成为未来决策的事实依据

模型对任务世界的认识只能依据 Journal 中已经提交的 Event。稳定 System Prompt、静态工具契约和显式产品配置属于决策机制，不冒充任务事实；凡是会随运行变化、并要被模型当成“已经发生”的内容，都必须先提交。preview、SSE、Host 内存、Worker 驻留、前端缓存和 UI 状态不能成为第二事实源，也不能替代缺失的 Event。

### 2. 每种状态只有一个所有者

所有者负责写入和定义语义；其他层只能通过窄接口读取、投影、缓存或展示。缓存必须可丢弃，投影必须可由其正式来源重建。禁止 Host、Worker、Channel 或前端分别维护同一事实并靠同步保持一致。

### 3. 不同生命周期必须使用各自的稳定身份

Session、Event、Step、Command、Attempt、输出和 Channel owner 分别使用自己的 identity。identity 可以由另一个稳定 identity 确定性派生，但必须保留类型和一对一关系，不能在共享命名空间里把两种对象当成同一个对象。跨异步边界只能通过明确 identity 关联，禁止依赖“当前对象”、到达顺序、列表邻接或进程内槽位推断归属。

### 4. 无法确定的结果必须保持 unknown

进程退出、IPC 中断或结果提交失败后，只要无法证明外部副作用的终态，就不得根据异常、Session activity、瞬时进度或后续运行推断成功或失败。unknown 不自动重试，不降级为普通失败，也不由展示层改写成终态。Worker 若仍明确报告同一 `command_id` 正在执行，Channel 可以叠加可丢弃的 running 展示；精确活动一旦丢失，必须回到 Journal 的 unknown。

## 状态分类与唯一所有者

| 类别 | 典型内容 | 唯一所有者 | 其他层允许 | 禁止 |
|---|---|---|---|---|
| 持久执行事实 | 用户消息、Step、Command、Attempt、Outcome、授权裁决、领域事实 | Journal | 追加新事实；按事件重放 | 原地修改；由 Host 或前端补写终态 |
| 确定性归约 | `CanonicalState`、`DecisionState`、`StepState`、`CommandState`、`RUNNABLE` / `WAITING` | Runtime projector | Assistant 和 Channel 读取投影 | 根据 Worker、owner 或 UI 状态反推 |
| Assistant 确定性投影 | ToolSurface 激活、catalog 视图、待裁决 control、待回收 SubAgent、当前窗口已提交的模型输入用量 | Assistant projector | Host 和 Channel 读取投影 | 从 Registry 或进程缓存直接改写模型所见状态 |
| 产品级持久元数据 | Session pause、Session `auto_authorize`、Workspace 与 MCP / Skill / CLI Registry、SecretStore | Host 的对应产品存储 | Worker 通过 Host 窄接口读取当前值；需要进入模型视图时先追加 Session 事实 | 写入 Journal 冒充任务事实；Host 与 Worker 双写 |
| Worker 本地执行活动 | Scheduler running / idle、当前正在执行的 `command_id`、本地取消状态 | 该 Session Worker | 向 Host 发带 Session / Command identity 的瞬时信号 | 当作可重放事实；据此补写 Outcome |
| Host 进程与入口活动 | Worker 驻留与 generation、owner 选择、对外 `session_activity`、进程失败 | Host Supervisor | Channel 查询或订阅当前活动 | 反推 Runtime State；把 owner 选择当授权身份 |
| Channel 瞬时展示 | preview、reasoning delta、tool progress、`lastError` | 对应 Channel 会话与连接 | 前端按精确 identity 临时叠加到正式投影 | 影响模型决策；把 unknown 推成终态；覆盖 Journal 终态；跨重启恢复 |
| UI 本地状态 | 输入框、滚动、折叠、尚未发送或停放的草稿 | 前端 | 本地交互 | 参与后端恢复、调度或授权判断 |

## 评审用法

新增状态、字段或事件前，先回答：

1. 它属于表中的哪一类？
2. 唯一写入者是谁？
3. 跨异步边界使用哪个 identity 关联？
4. 来源丢失或进程中断时，能否从正式来源重建；不能时是否如实保持 unknown？

无法明确回答时，不进入实现。需要改变所有权时，先更新本文及对应专题文档，再删除旧写入路径，不保留双轨。
