# Coding Bot

Coding Bot 的当前边界。产品方向与尚未落地的部分见[后续方向](方向.md)。目前完成的是身份与装配骨架，Host 创建真实 Git 工作树，Agent 通过命令主动管理 Git 历史，Agent 之间的私信，名册对模型可见与首轮自我介绍，Web 上的 Agent 名册，落地与同步，基于 Agent 分支的委派，Git 变化查看，以及群聊后端。群聊的 Web 入口与界面还没有接入。

## 稳定身份与名册

一个 Agent 属于一个项目，以项目内唯一的名字寻址，指向一条长期 Session。名字区分大小写，不带首尾空白，可以使用中文；当前不提供改名或复用身份。Session 身份只用于内部定位，不作为模型寻址同事的地址。

Host 拥有创建与名册查询。固定的身份关系随创建事实写入该 Session，先持久化，再允许启动 Worker；名册从这些事实重建，不独立保存另一份身份清单。并发创建也必须守住项目内名字唯一。项目继续使用工作区登记，不另建项目清单。

负责方向是 Agent 用工具声明的事实，写入它自己的时间线，名册读取它自己的最新声明；声明不反向修改身份，也不是系统认定的人类授权。系统不解析对话中“同意”的含义，不维护隐藏的方向审批状态。

名册对模型的呈现分两部分：查询给出当前快照，事实给出之后的变化。Agent 可以用工具查询同项目同事的名字与负责方向，不包括自己；查询结果不带内部 Session 或项目坐标。同事加入与声明方向时，Host 把对应事实投递进同项目其他 Agent 的时间线，不请求决策，从下一步可见并可重放；同事离线时为此拉起它的 Worker。名册不写入 System Prompt。

创建在持久化身份后，先向同事投递加入事实，再重新投递创建事实拉起新 Agent 的 Worker；这样同事总是先知道它加入，再看到它做的任何事。Agent 不等人开口即作出第一次决策：创建事实向模型提示先了解项目、查看同事方向、向人提议自己负责什么，人认可或修正后再声明。是否只读浏览、提议什么由模型判断，系统不在首轮限制工具。

Web 只向人展示已经写下的方向，没有声明就不显示。

## 项目归属与执行目录

项目归属固定，Agent 的任务根是自己的真实 worktree。不能把每个 worktree 登记成一个新项目，也不能为了运行 Agent 改写原项目的工作区路径。Host 根据身份选择装配，Worker 按给定任务根运行；模式不由模型选择。

Agent 的文件工具和命令直接作用于真实目录，不依赖 Agent 文件系统；访问范围、文件权限与命令授权仍各自生效。Worker 与 Host 重启不改变这个选择，后台上下文压缩也继承所属 Agent 的任务根和装配方式。

Host 根据项目与 Agent 名字建立分支和 worktree，不接纳调用方指定执行目录或分支。项目登记路径必须是 Git 工作树根，不能借登记子目录扩大任务范围；裸仓库、未初始化的目录和没有首个提交的仓库不能用于首次创建。

每个项目有一条本地集成分支与 Host 持有的集成 worktree，首次从项目当时的 HEAD 建立，只取已提交内容。之后创建 Agent 都以集成分支为起点，不跟随人检出或移动的分支，不重置已有 Agent 的工作树。人的暂存区、未提交与未跟踪文件不进入这个起点，也不要求人先清理它们。

集成与 Agent 工作树位于应用数据目录，必须在人的项目工作树之外。它们与项目共享 Git 对象和分支，不另建仓库副本；不同数据根各自拥有集成分支，不能争用同一条。Git 元数据承载这些关系，不再另存一份项目分支清单。已存在但与所属项目或分支不一致的集成工作树必须暴露错误，不自动覆盖或重建。

创建先准备工作树，再写入 Agent 创建事实，完整身份提交后才允许运行。事实写入失败时撤销本次新建的 Agent 工作树与分支，项目集成工作树继续保留；请求取消也必须等待本次创建收口，不能提前释放创建权。创建 Git 工作树时不执行仓库钩子，宿主进程继承的 Git 路径覆盖也不能改变项目归属。

TUI 继续使用受管装配。Web 从名册按项目和名字创建 Agent，不接受调用方指定的工作树或分支；创建后打开该 Agent 的会话。文件审阅读取 Agent 尚未落地的 Git 差异，见[变化查看](#变化查看)。不向用户提供手填内部工作树路径的入口。

当前 Agent 不提供文件回退、历史分叉或依赖 Agent 文件系统的变更归因。旧的历史分叉入口不能复制长期 Agent 的身份。委派不借用旧子任务路径重新接回 Agent 文件系统。

## Git 文件历史

Agent 主动管理自己的工作分支：在修改代码的任务中判断何时暂存、提交哪些修改、如何说明，以及需要哪些验证，通过现有命令能力执行 Git。只读任务和用户要求不提交的任务遵守各自范围。Git 操作沿用命令授权，负责提交不等于可以替人批准命令，也不等于获准推送远端、修改他人分支或重写既有历史。

修改任务收尾时，Agent 应核对相关修改已经提交；存在阻塞时说明未完成的部分。Bot 命令使用自己的 Git 作者与提交者身份，不继承启动者的提交身份，不改写用户或项目的 Git 配置。提供执行身份不意味着系统代替 Agent 发起提交。

系统不在 Step 收口、回复结束、上下文压缩或重启时自动暂存和提交，不为 Step 创建或补齐文件版本。真实执行与结果随普通命令留在时间线，文件历史以实际 Git 提交为准，不另建一份版本映射。未提交、已暂存与已提交修改分别用对应的 Git 差异核对；未提交差异为空不能证明任务没有修改。

不承诺每个对话步骤都有文件回退位置；未来回退需要单独明确对话与 Git 提交的关联。被忽略的文件不强制加入历史，现有提交不由系统压缩或重写。Git 命令失败由 Agent 根据实际结果判断下一步，系统不替它判断冲突解决或成果已经完成。

## 落地与同步

何时落地、何时同步是 Agent 的语义判断，由模型调用工具发起；合并本身由 Host 确定性执行。两个工具都必须单独调用，不与同一步的其他工具并行。Git 提交仍由 Agent 自己决定，落地与同步只移动已提交的内容。

落地把 Agent 分支上已提交的工作合入项目集成分支，未提交的修改不随之带走：能快进则快进，否则产生一个作者为该 Agent 的合并提交。同一项目的落地由 Host 串行执行，取消请求也要等本次合并收口才释放。冲突时放弃这次合并，集成分支保持不变，结果列出冲突文件，由 Agent 同步、解决后再落地。落地不经人审批；每次落地都是一个可单独撤销的 Git 动作。集成工作树里有会被覆盖的文件时落地不执行，结果列出这些文件，由 Agent 告诉人去清理，不替人清理。

同步把集成分支合进 Agent 自己的分支，只拿到同事已落地的工作。冲突时合并停在冲突状态，交给 Agent 用普通 Git 命令解决并提交，或放弃。工作区里会被覆盖的未提交文件让同步不执行，不替 Agent 丢弃改动。Git 是否以退出码区分「冲突」与「拒绝合并」随合并方式而变，判断依据是合并是否留在进行中。

落地、同步、合入子任务和固定子任务成果时，Git 的其他失败（残留的 `index.lock`、文件被占用等）作为这次工具调用的失败结果，带着 Git 原文交给 Agent，不终止 Agent，也不改写成「文件会被覆盖」。只有 Git 明确说会覆盖文件才归为挡路；其余失败的含义交给 Agent 和人判断，结果也不声称工作树没有变化。

落地的合并结果作为该工具调用的结果留在 Agent 的 Journal 里，是之后判断外泄点的事实来源；集成分支的名字与位置不进入模型上下文；Git 失败原文里带出的路径例外，它原样交给 Agent，好让人找到出错的位置。

## 委派

Agent 的 [SubAgent](../运行/SubAgent.md) 沿用委派、回收、交回与能力名单的全部规则，只把文件世界换成 Git：子任务的工作树是从父 Agent 分支切出的一条分支，起点是父分支上已提交的工作，父未提交的修改不在其中。子在这棵真实工作树里直接改文件，仍然不能执行命令，写入不需要授权。重放委派复用同一条分支，不把子的改动重置成父的新状态。

子任务不能执行命令，也就不能自己提交。交回后父第一次比较或合入时，Host 把它工作树里未被忽略的全部成果固定为子分支上的一个提交，作者是父 Agent；这条分支只是父比较与合入的载体，系统仍不替父 Agent 提交它自己的分支。

父验收看的是子分支相对分叉点的差异；合入是把子分支合进父 Agent 的分支，不碰人的工作目录，所以不需要人授权，仍必须单独调用。合入冲突时放弃这次合并，父分支不变，只返回冲突清单。解冲突的子任务从父分支切出后先开始这次合并，冲突标记留在它的工作树里，交回时它的解决结果作为这次合并提交。父分支上还有未完成的合并，或会被覆盖的未提交文件时，合入不执行。

子分支跟随长期 Agent 保留，不随子任务交回或 Agent 文件系统的子任务清理而删除。TUI 与尚未替换的 Web 会话的子任务仍走[子任务文件交换](../Agent文件系统/子任务文件交换.md)。

## 变化查看

Web 对 Agent 的会话变化查询改由 Git 差异提供，不连接 Agent 文件系统。Agent 的变化是它尚未落地的工作：工作树当前状态（含已提交、未提交与未跟踪，不含被忽略文件）相对它与集成分支分叉点的差异；落地之后这些变化随之消失。委派子任务的变化是它尚未合入父分支的工作，基准是父 Agent 的分支。查询借用一份临时索引收集未跟踪文件，不改动 Agent 自己的索引与 `git status`。

Git 不知道每一行出自哪次工具调用，差异整体视为该 Agent 的工作，不区分会话外修改；同步进来的同事成果已在集成分支上，不出现在差异里。分页续读以文件两端的对象身份校验，文件已变化时要求刷新。

## 通信事实

创建、私信、群发言、群消息回应请求与负责方向声明分别表达确定的事实，复用 Runtime 的领域事实接纳，不新增执行循环或通用消息框架。事实重放必须遵守当前完整契约；损坏和未知错误不能被忽略或补成默认值。

私信按同项目的同事名字寻址，只接受收件人、正文与可选的回复引用。名字不存在、发给自己、跨项目和引用不属于这两位同事的私信，都返回已知结果。发送成功只确认已进入对方时间线，不等待回复；收件人离线时拉起 Worker，正在工作时沿现有外部事实路径接纳。

人的暂停不能被私信解除。暂停的收件人仍接纳消息，但不产生新的 Step；发送结果明确说明对方暂停、须由人继续。暂停 Agent 的未处理消息提示留给 Web 名册与跨 Agent 收件箱。

回复引用由 Host 校验，继承被引用消息的交流链，每回复一次增加一跳。超过上限拒绝发送，在发送方留下不触发决策的上报事实，并在与人的聊天中呈现。上限只约束显式引用的链，不判断正文是否属于同一话题。

另起新链不能绕过总量：每条 Agent 消息（私信与群发言）都带一个源头，即最终驱动它的那条非 Agent 外部事实，例如人的一条消息或一次定时触发。Host 从发送方 Journal 确定性推出源头：发送命令由哪一步发出、那一步由什么触发；触发者是续跑结果时沿命令回溯，是同事消息或群回应请求时继承那条消息的源头。同一源头驱动的 Agent 消息有总量上限，超限同样上报给人。按源头而非“上次收到人消息以来”计数，同事交来的新任务不会占用另一件事的额度。上限数值是起步值，按实际协作调整。

私信身份由发送方 Command 确定性派生，收件方幂等接纳。发送方接管时，对未知发送使用窄恢复：按原身份核对收件方 Journal，已经送达就补交确定结果，尚未送达就按原身份投递；不能把未知结果直接留给模型再发一条新消息。双方同时恢复时可以先接纳事实，但模型决策须等待自身的发送恢复完成。损坏与身份冲突原样暴露，不降级成普通发送失败。

## 群聊

群是 Host 持有的公共记录：每个群一份事实日志，放在会话目录之外，不是会运行模型的会话，也不进入名册、收件箱或启动时的会话遍历。群按项目内唯一的名字寻址，成员 2 到 6 个同项目 Agent；创建时向每个成员投递不触发决策的入群事实，第一版不改成员。

发言先写入群记录，再作为不触发决策的事实投递给其他成员；发言者自己的时间线里已有这次工具调用。是否轮到某个成员回应由单独的回应请求表达，它请求一次决策。被叫醒时，之前到达的群发言都已在上下文里，一次决策就能看到全部；因此不需要改变 Runtime“一条外部事实一次决策”的规则。Agent 只能用工具显式发言，它每轮结尾的普通回复留在自己的时间线。

调度由 Host 确定性执行，不设主持人模型，不靠提示词让 Agent 闭嘴：

- 点名的消息只叫被点名的成员，不点名叫全体，发言者本人除外；按点名或成员顺序依次叫。
- 被叫成员在群里发言，或这次被触发的处理结束仍未发言，即算完成；发言后它可以继续工作，Host 接着叫下一位。被人暂停的成员直接跳过。
- 一轮里各条发言按同样规则算出的成员合起来是下一轮；整轮无人发言即停。
- 硬上限：一条源头最多驱动的轮数与回复总数、每个成员每轮的发言条数。超限的发言返回已知结果与下一步，不写入群。数值是起步值，按实际效果调整。
- 同一个群只由最新的源头调度：人的新发言、或带新源头的 Agent 发言会取代正在进行的那一串，旧源头的后续发言仍可送达但不再叫人。
- 群级停止：清空待叫队列，并像人打断一样打断当前被叫醒的成员；已完成的动作不撤销。

调度状态只在 Host 内存中。Host 重启后不恢复中断的轮次：启动时本就会暂停未完成的会话，已投递的回应请求在人让成员继续后照常处理，尚未叫到的成员不再叫。群发言身份同样由发送方 Command 派生，复用私信的窄恢复与幂等投递。

通信要保留明确的发言者、消息引用、线程与因果来源。消息身份、发送者和跳数由 Host 根据真实来源确定，不由模型工具参数自报。授权只能来自人的入口；同事转述的同意不构成授权。私信、群发言和同事查询只装配给有长期身份的 Agent，普通会话、SubAgent 与后台压缩不因此取得同事通信能力。

模型只看到自己的名字、发言者、群、正文、可引用的消息以及需要回应的提示。内部 Session、项目索引、分支、线程计数和投递坐标不直接进入模型上下文。真实任务目录由执行环境说明；名册变化不能作为可变内容直接写入 System Prompt。

## 不做

- 为身份增加独立的持久名册、通用注册框架或第二份项目清单。
- 让 Runtime 解释角色、负责方向、人的同意或消息正文。
- 系统代 Agent 暂存或提交，或为每个 Step 追补文件版本。
- 在工作树与落地中加入协作工具、群调度或记忆。
- 落地时自动压缩提交、经人审批，或合并进人当前检出的分支。
- 给废弃的普通 Web 会话模型预建迁移与兼容路径。
