# Bot 与协作

本文说明长期身份、项目与通信的当前边界。输入和回复政策见[交互与响应](交互与响应.md)，待解决问题见[后续方向](方向.md)。

## 稳定身份与名册

一个 Bot 对应一条长期 Session，以全局唯一的名字寻址，身份独立于代码项目。改名保留会话、目录和群关系，旧消息仍指向原身份，新通信使用当前名字；曾用名不再分配给其他 Bot，避免历史指向另一个人。

Host 先持久建立身份，再允许执行。名册从创建与变更事实重建，不独立维护第二份持久身份清单；并发创建也必须保证名字唯一。新成员先被同事知晓，再开展首次交互，加入通知本身不要求其他成员决策。

角色和分工来自任务与交流，不要求创建时填写方向或系统提示。持续约束放在[记忆](../上下文/记忆.md)，经历查原始历史，知识按需读取。新 Bot 可直接问候人并介绍能力，不由特殊成员独占产品使用知识。

模型查询当前同事名字、工作目录和可观察活动，之后变化以事实接续；名册不写入系统提示，也不暴露内部会话或分支坐标。是否卡住、要不要改派由模型判断。压缩后重述自己的名字、群成员与例行任务，见[上下文压缩](../上下文/上下文压缩.md)。

删除 Bot 使身份永久退出运行与协作，停止其执行、子任务、命令和定时，不再接受新工作。历史、个人目录与项目成果保留，只读可查，不自动落地或丢弃，也不提供恢复入口；名字仍属于原身份。

## 项目归属与执行目录

每位 Bot 自动获得持久个人目录，始终作为任务根，重启和压缩不改变它。不关联项目也能交流、处理文件和执行经授权的命令，普通目录不自动初始化 Git。

代码项目是可挂载资源，一位 Bot 可同时挂多个，也可中途关联或解除。挂载为该 Bot 准备独立 worktree 与分支，模型从事实取得项目和真实目录，个人任务根不切换。这样不用为每个项目重装会话或修改系统提示，代价是操作项目时须明确路径和命令目录，实测见[项目挂载](../../历史/执行环境实测.md#任务根与项目挂载)。

项目复用本地 Git 仓库登记，不为每份 worktree 再登记项目。人的目录选择确认后才生效；模型指定新本地路径要人批准，引用已有登记不需要。仓库须已有首个提交，不接受无效根或裸仓库。Host 准备执行目录与分支，不让调用方指定内部工作树。

每项目有独立集成分支与集成工作树，首次从人的检出当时已提交内容建立。之后挂载从集成分支开始，不随人的检出移动，不复制人的暂存、未提交或未跟踪内容。工作树位于人的检出之外，共享 Git 对象；不同数据根不争用同一集成分支。

自己的文件目录可写，同事目录只读；开放其他宿主路径不取消这个只读边界。一起修改或验证时各自挂载项目，不共享一棵半成品工作树。命令的授权与实际隔离边界见[执行环境](../能力/执行环境.md)。

解除只移除本 Bot 的项目工作树与分支，不动项目和其他成员。存在未提交、未落地、进行中合并或未结束子协作时拒绝解除并说明原因，不替人丢弃成果；重新挂载从当前集成分支开始。

创建、挂载与解除按原操作身份收口，确认丢失先核对事实，不能误删已经接纳的资源。进程恢复先完成原操作再让 Bot 使用项目；清理不遮蔽原错误，结果不明时不删除。外部 Git 环境覆盖和仓库钩子不能改变准备操作的项目归属。

## 编码方法与工作流

系统提示保留任务、证据、通信与能力边界。编码方法和 Git 协作分别作为 Skill 按需加载，可以独立使用；用户流程与适用的项目约定优先。普通个人目录也支持工作约定和自定义 Skill，不因一次编码任务自行初始化仓库。

Skill 提供方法，不授予能力或权限，也不规定固定角色与流水线。项目挂载仍由工具保证分支隔离；父子共享文件的安排由父决定，不因提取方法而改变执行边界。

## Git 历史、落地与同步

Agent 主动决定提交范围、时机和验证，不由系统在回合结束、压缩或重启时自动暂存提交，不为每个对话步骤补版本。提交使用 Bot 自身 Git 身份而不改写用户配置；负责提交不代表可以推远端、改他人分支或重写历史。文件成果以实际提交为准，未提交差异为空也不能证明没有修改。

落地把已提交工作合入项目集成分支，同步把已集成工作合回自己的分支；何时调用由模型判断，合并由 Host 确定执行。这两种操作单独调用，不与同一步其他工具并行。落地不逐次审批，不自动压缩提交，也不碰人的检出；同一项目集成修改串行收口。

落地冲突就放弃该次合并，集成分支不变；同步冲突留在自己的工作树，交给 Agent 解决提交或放弃。会被覆盖的文件阻止操作，不自动清理；其他 Git 错误原样保留，不能都归为冲突，也不声称失败必然未改现场。

取消等待已开始操作收口。重启只在仍能证明现场对应原合并时完成原操作，不能猜测冲突或外部修改。落地结果作为原调用事实保留，不把内部集成分支与目录变成模型必须理解的操作坐标。

当前不提供文件回退或对话分叉。Git 也不覆盖被忽略文件等全部副作用，历史取舍见[AgentFS 的取舍](../../历史/AgentFS取舍.md)。

## 委派

[SubAgent](../运行/SubAgent.md)共享父的个人目录和项目文件，能看到未提交内容；父安排范围、顺序和是否使用 Git。系统不为子建工作树、提交或自动集成果。

子普通回复给父，完整执行过程不自动灌入父上下文。父验收实际文件与证据后显式回收，保留共享成果与历史；解除相关项目之前先结束子协作。

## 私信与通信边界

私信按同事当前名字寻址，可明确引用双方往来消息。发送只确认进入对方时间线，不等待回复；离线成员由 Host 拉起处理。停止当前轮不冻结协作，之后消息照常接纳。

通信保留发言者、引用和因果来源，身份与计数由真实事实确定，不由模型自报。回复链受跳数限制，另起话题也受同一非 Agent 源头驱动的消息总量限制；超限拒绝并向人说明，不从正文或时长猜测闲聊。不同任务的额度不混在“上次人发言以来”的计数中。

重试与恢复沿用原发送身份。未知发送先核对收件方，已送达就确认，未送达才补投，不能让模型换身份再发；自身发送恢复完成后才继续判断。损坏和身份冲突不降级为普通发送失败。

同事转述的同意不是授权。团队通信只提供给长期 Bot，普通 TUI、子 Agent 和后台压缩不因此取得成员身份。普通回复给人，发给同事或群必须显式发送，见[交互与响应](交互与响应.md#普通回复给人协作消息显式发送)。

## 群聊

群以名字寻址，成员关系不受项目限制。群记录是公共交流事实，不是另一条会执行模型的会话；成员仍在自己的长期时间线中工作。

发言先成为群事实，再送入其他成员的时间线，送达本身不触发决策。单独的回应请求才叫成员判断，调用时已到达的群记录共同可见；点名只叫对应成员，不点名叫除发言者外的成员。通知继续派送，不等待任何成员回执、发言或执行完毕。

是否回应某条消息由模型显式引用表达，系统只校验引用与待回应状态，不猜当前行动归属。同一次回应只认一次，引用不表示工作完成；继续报告或没有对应待回应请求的发言开启新讨论，并入队列，不覆盖其他待叫成员。

Host 按明确规则推进讨论，以轮数、回复量和源头总量限制互叫，不设主持人模型或靠提示词收住。轮数用完的发言可留下但不再叫人；消息总量仍限制不断另起讨论。整轮无人发言则停止推进。

人的新发言取代正在进行的讨论，是转移话题，不打断成员正在做的工作。不提供群级强制停止；人通过单个 Bot 的停止控制执行。需要人的授权与决定留在该 Bot 的私聊，不移进群。

群记录保留已接受的发送与回应进度，重启按原身份补齐，不能从聊天内容重新生成派单。解散后停止新发言和回应，重启不恢复旧讨论；群历史只读保留，成员其他工作继续，群名不重新分配给另一个群。
