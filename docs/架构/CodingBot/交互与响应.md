# 交互与响应

长期 Bot 同时面对人的要求、同事往来、定时工作与执行结果。输入何时进入判断、命令是否占着等待、回复交给谁，是三个独立问题：收到不等于处理，转后台不等于完成，普通回复也不等于通知了同事。

## 人的要求优先进入下一次决策

人会修正目标和要求，系统应把已接纳、尚未处理的全部人的输入共同交给下一次判断，保留原文与顺序，让模型理解关系。系统只按输入来源排序，不读正文寻找更正，也不把同事转述算成人的授权。人持续发言可能延后其他来源，这是接受的产品代价。

新消息不改写在途模型调用，也不撤销已开始操作。旧工具未返回时，人仍可继续交流；模型面对真实的结果未明状态决定是否等待或检查。旧结果无论在插话前还是之后到达，都应可靠进入一次后续判断。消费仅表示得到共同判断机会，不证明逐条回答或任务完成，完整契约见 [Runtime](../运行/Runtime.md#用户输入与后到消息)。

## 长命令释放 Agent，结果可靠回来

命令前台只等待有限时间，未结束便转后台，也可直接后台执行。Agent 因而能继续接待请求或等结果回来，不需占着模型调用反复查询。

转后台保证命令可寻址、可看输出、可停止，结束后有一条新的完成事实回到原会话；它不承诺成功、必然结束或服务就绪，也不创建另一项任务上下文。模型结合届时的新要求判断结果和汇报对象。

命令没有默认总运行期限，系统不按静默时长或输出内容判定卡住、就绪或完成。切换会话、停止当前轮与停止后台命令是不同动作，已发生副作用都不会撤销。重启补报确定结果，缺少结果就说明未知，不自动重跑，详见[执行环境](../能力/执行环境.md#命令生命周期与后台执行)。

## 普通回复给人，协作消息显式发送

长期 Bot 的普通回复直接给人看，包括同事、群、例行任务或后台结果开始的工作。实时和历史遵守同一规则，不再另分工作记录与给人的正文。对同事或群的消息必须显式发送，不自动回复唤醒者；发言引用表示回应关系，不代表任务完成。

群里开展的分派、澄清、版本变化、发现和结论优先留在原群，让成员共享判断依据。点名表示需要谁行动，可见范围表示谁可知情；需要某一位处理并不自动成为转私聊的理由。私密内容与用户指定例外仍走私信，用户无关的私聊不能转入群。

已授权范围内的日常往来按约定继续，不逐条询问；新增参与者与另起工作仍须符合用户授权。承担统筹时根据既有报告追问证据缺口或补派，不默认完整重复已经分派的工作，也不要求群报告再私发副本。角色、节奏和验收方法由团队约定，Runtime 不读正文强制流程。

需要人下载文件时显式交付工作区文件副本，同事之间仍直接读取工作目录。格式与图文表达由模型按任务选择，结论和依据保持可见，不增加固定模板或格式配额。

曾要求给人回答也调用独立工具，但真实模型会漏发，追加提醒不能稳定纠正，见[回复交付实验](../../历史/回复交付1020.md)。因此让普通回复与人的可见性一致，不让系统猜正文并补发。子 Agent 的普通回复仍给父，后台压缩不向人交付；这些边界不随长期 Bot 的展示规则扩大。

## 从长期处境组织提示

长期时间线里不同往来交错，提示先说明团队成员的处境与来源归属，不默认所有后续消息都延续同一任务。人的要求和授权优先，同事请求在已有范围内可接手；身份、名册和群关系由事实呈现，不动态写进系统提示，也不假设 Bot 已在某个群。

协作约定只针对真实失败：不因同事加入就发起寒暄和分工，不发纯确认，同一问题不反复问人，由接手者汇报，也不在普通回复中重复刚发到群的内容。这些是模型行为指引，不是系统对任务内容的判断。

当前长期 Bot 的每轮工作仍保留普通回复。允许无回复结束试验中，模型虽能判断应沉默，却不能可靠产出空结尾，见[协作约定实验](../../历史/协作约定1021.md)；因此缩短自主工作的收尾，不以没有正文推断执行结束。

## 可观察行为是交互边界

工具和消息只说明来源、可选动作、实际发生的结果与下一步，不要求模型理解内部调度、进程或存储。例如后台返回应说清仍在运行、会收到完成通知，以及如何查看或停止。

系统保证输入和结果可靠进入判断、输出去向明确，不能保证模型采取正确行动。是否完成、重跑或汇报仍由模型与人判断，不能从承诺文字推导任务状态，也不把输入成批、后台命令和消息投递合成通用任务框架。
