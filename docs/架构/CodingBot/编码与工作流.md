# 编码与工作流

群组提供持续协作的空间，不代表一组固定角色或固定流水线。Bot 的身份、具备的能力与当前分工相互独立：用户交代目标和协作约定，模型理解任务、选择方法并决定如何交接。编码是优先做好的专长，不是每个 Bot、每次任务与每个工作目录的前提。

## 按需加载方法

系统提示保留任务范围、证据要求、通信去向和工具使用边界。编码方法与 Git 协作分别作为内置 Skill 提供，只在目录中呈现用途；模型按当前任务读取正文，普通聊天不需要加载编码流程。

编码 Skill 负责理解代码、聚焦修改与验证结果；Git 协作 Skill 负责适用场景下的提交、同步和成果集成。两者可以独立使用，用户指定的流程与适用的项目 Skill 优先。没有 Git 的目录也可以修改、验证与交付代码，不因编码任务自行初始化仓库。

项目知识随工作目录提供，Skill 引导模型按需读取相关说明和文档，不将项目全文固化进系统提示。目录中的工作约定适用于资料整理等非编码任务，不能只有加载编码 Skill 才能得知；开始文件工作时由模型读取，约定发生变化或上下文缺失时重新取得。

## 流程与能力分开

Skill 可以指导模型调用工具准备工作树、传递文件或组织协作；操作能否执行、实际产生什么影响，仍由工具契约、授权与执行边界决定。读取 Skill 不授予新能力，也不代表获得操作授权。

用户可以采用 Git 分支协作，也可以通过文件交付组织任务；不预设协调者、开发者、审核者或固定交接顺序。工作目录中的自定义 Skill 无须以 Git 项目登记为前提，沿用同一套发现与读取机制。不为流程组合建立额外的调度框架。

当前关联代码项目的 Bot 仍由系统准备独立工作树，项目工具继续保证分支隔离与合并正确性。提取 Skill 不解除这条执行路径的约束，父子共享工作区，子协作方法由父根据任务安排。已有 Bot 的项目关联与切换仍是[后续方向](方向.md)。
