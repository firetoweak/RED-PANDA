# RED PANDA 文档

RED PANDA 以长期 Bot 协作为核心，是以编码为主的泛用 Bot：Agent 以名字为身份，通过私信与群聊协作，人设定目标、授权并调整方向。编码是优先做好的主要场景，讨论想法、分析资料与推敲方案同样属于协作。Bot 已能独立于代码项目创建与协作，代码项目是可选的执行资源；当前边界见 [Coding Bot 总览](架构/CodingBot/总览.md)，后续演进见[后续方向](架构/CodingBot/方向.md)。源码安装与日常启动从[快速开始](../README.md#快速开始)进入。

当前系统按 **Session / Event / State / Step / Command** 运行。

架构文档只记代码里读不出来的东西：设计意图、不变量、关键决策及其代价，以及明确的「不做」。**实现位置、字段形状、端点、默认值和测试覆盖不进文档**——那些的事实源在代码里，写进来就是第二份会漂移的事实。

每个主题一份准绳，对照文档只在改那个边界时打开，不要从专题笔记交叉入门。讨论与实验记录保留当时事实，不作为当前实现说明。

## 架构

`docs/架构/` 按**变化原因**分子目录。**文件夹本身就是进度**：上半部分是已落地的准绳，下半部分是只有方向、还没有设计的专题——那几个文件夹就是路线图，不另立计划文档。

```text
架构/
  总览.md          分层、包边界与依赖禁令、测试分层
  运行语义规约.md    跨层最高约束：状态分类与唯一所有者

  运行/            事实怎么记、进程怎么起、会话怎么分
  上下文/          模型每一步看见什么
  能力/            模型能调用什么、命令执行环境
  入口/            人从哪进来、怎么授权
  CodingBot/       长期 Agent 的身份、工作区与协作

  未开始/          只有方向与已排除做法的专题
```

`未开始/` 里只有方向和已经排除的做法，**不是准绳**，不要照着实现。某个专题真的动工、长出多份文档时，再把它移出来建自己的目录——那次移动就是状态变化本身，不需要另外记录谁什么时候落地。

同理，已落地的目录也是内容长到需要分组才建的。不为预计会有的内容提前建目录。
