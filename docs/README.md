## 理解设计

先读[产品定位](产品定位.md)，了解用户价值与产品边界；再读[架构总览](架构/总览.md)，理解整体结构与设计理由。[运行机制](架构/运行/运行机制.md)说明当前进程、内存、调度与存储如何配合。

涉及运行状态的设计与评审，须先对照[运行语义规约](架构/运行语义规约.md)中的跨层不变量，再按问题进入具体专题。[后续方向](架构/多智能体/方向.md)只记录尚待解决的问题。

架构文档解释设计理由、关键不变量、当前运行机制与资源代价。具体行为以代码与测试为准，操作步骤放在使用指南，不维护第二份实现清单。`架构/未开始/` 只有方向，不能据此直接实施。
