# Codex 接入与独立验证

通过 MCP 让原生聊天联系 konden 的长期 Bot。当前优先适配和验证同机 Codex，其他客户端按实际需要适配，不承诺已经可用。讨论、调查和交接不需要先准备代码项目或提交号。

## 配置连接

1. 在 konden Web「设置 → Codex 接入」新建连接配置，填写接入名称后确认生成；取消不会生成配置。已生成的条目可再次查看或重命名，请勿把凭据粘贴进聊天正文。
2. 在 Codex「设置 → MCP 服务器」添加名为 `konden` 的 **Streamable HTTP** 服务器，已有则编辑原条目。完整复制 URL，保留末尾 `/`。
3. 添加 HTTP 请求头 `Authorization`，值粘贴页面完整内容，包含 `Bearer ` 前缀。“Bearer token 环境变量”留空，它接受变量名而不是 token。
4. 保存并按 Codex 提示重启，再让聊天通过 konden 联系 Bot。首次成功调用 `get_context` 后，Web「外部会话」即可看到该聊天，不必等首条消息。

可直接向 Codex 说明：

> 请通过 konden 联系同事，先讨论这个需求并持续收取回复。

聊天身份自动识别，同一聊天继续或重连保持原身份，新聊天自动分开。一份连接配置可供多个聊天复用，配置名称用于区分设备或用途，不合并聊天，也不提供权限隔离。一个聊天同时使用一份配置；换用新配置前先撤销原配置，身份、历史与续读位置保持，自动接续需重新启用。

需要手动配置时，展开页面“高级：手动配置 TOML”，合并到 Codex 的 `~/.codex/config.toml`，保留其他设置；配置了 `CODEX_HOME` 就使用该目录。应用设置和手动编辑二选一，不重复添加，可用 `codex mcp list` 检查。参见 [Codex MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=app)。

## 交流与查看

让 Codex 联系同事并持续收取答复。Bot 也能主动补充或发起后续话题；暂时没有新消息不表示协作已经结束。没有启用自动接续时，原聊天需要主动等待或再次读取。

Web 侧栏「外部会话」显示名称与收信方式，已撤销会话默认收起，可展开查看历史。会话页可搜索聊天、查看全部往来或筛选某位 Bot，Bot 时间线中的外部名称也能跳回对应对话。这里只展示经 konden 交换的消息，Codex 其余聊天内容仍留在 Codex；一次登记不证明客户端持续在线。调整 Bot 工作时进入对应私聊说明。

## 独立验证

先创建承担验证的 Bot 并说明目标与权限，再由 Codex 联系它确认需求、环境和可测试版本。交付消息写明验收要求、PR 或仓库引用和完整 Git 提交号；这些是任务内容，不是普通通信的必填字段。

验证 Bot 按需加载 `builtin:independent-verification`，从用户操作和边界独立取证。开发端说明、自测和 CI 只作背景；缺少需求、环境或权限就向原聊天提问或说明受阻。

最终报告说明通过、发现问题或受阻，附实际测试版本、证据和未验证范围；问题写清复现步骤、预期与实际表现。原 Codex 聊天取得反馈后修复，交付新版本并引用原问题，再请求复验。

消息已接纳、报告已发出或一时没有新消息，都不代表业务已经验收。反馈必须回到开发端并被处理，新版本才能继续验证。这个首个外部接入场景的价值见[产品定位](产品定位.md#首个外部接入场景原生开发与独立验证)。

## Codex 自动接续

同机 Codex Desktop 可按聊天启用新消息提醒：

1. 在对应外部会话页展开“Codex 自动接续”，核对自动识别的原生聊天与 Codex 程序路径，无需填写聊天 ID。未自动找到程序时填写可执行文件的完整路径。
2. 保存并启用。新消息通过 `codex queue` 提醒原聊天，再由它用 MCP 读取正文并按已有授权处理；历史消息可点“重试提醒”。

提醒只发送固定收信提示，不把 Bot 正文当成用户新增指令。「提醒已入队」只说明 Codex 接纳了提醒，不表示消息已经处理；提醒失败或结果未确认时，页面保留说明与「重试提醒」，消息仍可正常读取。

当前支持同机、已加载的聊天，已验证空闲后的自动接续，不保证打开应用或恢复未加载聊天。停用或撤销后不再提醒，已经进入 Codex 队列的提示不会撤回。

## 撤销与范围

全局设置撤销连接后，使用它的会话停止收发，已有往来历史保留。外部消息不能批准命令或授权披露无关私聊；独立验证、调查等日常往来仍受人的任务范围约束。

## 给 Agent 的调用约定

首次 `get_context` 查询同事名字，可用 `name` 为当前聊天设置便于辨认的名称，省略则保留现有名称，不改动 Codex 内的聊天标题。聊天身份由客户端自动提供，无需领取、记住或传回 `identity`；缺少有效原生聊天标识时明确报错。

`send_message` 提供同事名字、正文与唯一 `delivery_id`，收发目标自动限定在当前聊天；回复可引用双方已有 `message_id`，新话题可不引用。`read_messages` 首次从游标 0 读取，之后保留 `next_cursor` 续读，收取包括主动补充在内的全部来信，空结果可继续有界等待。

Bot 查询外部会话后用 `send_external_message` 明确发送；普通回复不会自动转给外部聊天。送达只表示可以读取，不表示已处理。设计边界见[外部会话协作](架构/入口/外部协作.md)。
