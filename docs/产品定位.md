# 产品定位

## 长期协作的通用 AI 团队

konden 提供一支有名字、能互相交流的长期 Bot 团队。用户可以直接在 konden 中讨论想法、交流问题、检索资料、生成内容，或完成简单代码等任务；需要时再让多位 Bot 共同调查、推敲和交付。

每位 Bot 有持续的对话和持久工作目录，通过私信和群聊协作，让背景、约定与成果在后续工作中接续，减少重复说明和人工协调。人设定目标、决定授权与最终取舍，分工和工作方法在交流中形成。日常使用从对话开始，代码项目与外部工具按需接入。

## 首个外部接入场景：原生开发与独立验证

外部接入把长期团队的协作延伸到用户已有的工具中。首个场景是用户在原生编码工具里开发，再联系 konden 的团队开展讨论、调查与独立验证。当前外部会话接入与验证聚焦同机 Codex，其他客户端按真实需要适配。

独立验证从需求和真实用户操作出发，补足开发端沿自身实现思路自测的缺口；反馈回到原聊天，修复后继续复验。它检验跨工具协作能否减少人工转交与协调。使用步骤与交付要求见[Codex 接入与独立验证](外部协作.md#独立验证)。

## 产品边界

Bot 可以在个人目录中处理文件、生成成果和执行经授权的命令，需要代码项目时再关联独立 worktree。能力由工具和 Skill 按需提供，任务目标、协作方法与验收判断由人和模型决定，系统不预设固定角色或工作流水线。

接入外部工具时，konden 通过 MCP 提供聊天身份与持续双向通信。原生工具保留自己的界面、上下文、执行环境和会话管理；konden 不包装或托管外部 Coding Agent，也不建设统一开发会话平台。身份接续与提醒限制见[外部协作指南](外部协作.md)。

## 使用体验

私聊便于持续交流，群聊给完整报告留出阅读空间。身份与权限归属清楚，项目按需出现；人能查看执行、介入决定并接续原来的阅读与草稿。界面约束集中在 [Web](架构/入口/Web.md#界面设计原则)，后续问题见[后续方向](架构/多智能体/方向.md)。
