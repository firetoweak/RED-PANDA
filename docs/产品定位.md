# 产品定位

## 使用者

主要使用者是在 Codex 中开发，需要独立验证和持续协作的人。他们希望保留已经顺手的开发体验，让一支长期 Bot 团队承担调查、验证和跟进，减少自己重复说明背景、发起验证和转交反馈的工作。当前先适配同机 Codex，其他编码工具尚未适配，不因采用 MCP 就承诺通用客户端支持。

## 产品目标

让用户保留顺手的 Codex 开发体验，按需联系一支长期存在、能够独立判断并互相协作的 Bot 团队，获得可复查的结果和持续跟进，减少在不同会话和成员之间搬运信息、同步决定与推动下一步的负担。

Bot 以名字维持身份，各有持久工作目录，通过私聊和群聊协作。人负责目标、授权与最终取舍，具体分工与工作方法在交流中形成。编码是优先场景，代码项目是按需使用的执行资源；讨论想法、分析资料和推敲方案也可以独立成立。长期身份、协作记录与持续职责服务于跨任务的连续性，个人记忆等后续能力仍按实际需求推进。

## 首个场景：独立验证

首个聚焦场景是一个 Codex 聊天与 konden 的独立验证团队协作。用户照常让 Codex 完成修改、自测并提交 PR，编码端通过协作入口交付需求和明确版本；团队从真实用户操作、需求和边界条件出发独立取证，把反馈交回原 Codex 聊天，修复后继续复验，减少用户逐轮发起验证、转交报告与催促后续处理的工作。

这个场景来自一个真实缺口：开发端的自测容易沿着自己的实现思路和局部修改展开，前端操作与端到端使用仍会暴露遗漏。CI 可以承载端到端测试，但绿灯只说明既定检查通过。盲验先按需求与实际行为形成判断，不把开发端的实现解释、自测结论或 CI 状态当作验收结论；根据观察定位问题时可以查阅代码。

用户收益由两个交接是否接通决定：准备好的版本能够交付验证，独立团队的反馈能够回到对应的开发会话并被处理。报告应提供复现步骤、预期与实际表现、可复查证据和实际验证版本，条件不足时明确说明受阻。不能把请求已接纳、报告已生成或消息已发送当作闭环完成。

第一阶段的价值验证围绕一次真实的「开发交付 → 独立验证 → 原会话取得反馈并修复 → 新版本复验」展开，观察有效问题是否补足自测遗漏、证据能否支撑修复、用户还需要介入多少次转交与协调。内部团队按验证需要分工和讨论，Bot 数量与聊天次数不作为价值指标。

## 产品边界

用户保留 Codex 的界面、上下文、执行环境和会话管理。konden 通过 MCP 提供独立的外部会话身份与持续双向对话，每个新聊天分别登记，原聊天重连后接续。外部会话在 Web 可见，用户能查看它与长期 Bot 的消息往返。讨论、调查、交接和独立验证都在这个通信基础上开展，不要求普通消息遵循验证流程。产品不以替代 IDE、包装或托管外部 Coding Agent 运行时、统一开发会话作为路线。Bot 自身仍可按任务需要分析代码、修改文件和执行经授权的命令。

MCP 是连接方式，独立判断、可信反馈与协作连续性才是用户收益。当前接入范围与限制以[外部协作](架构/入口/外部协作.md)为准；Codex 主动等待反馈与自动接续需要分别对待。同机 Codex Desktop 可由人按聊天启用收信提醒，提示入队不代表已处理，也不承诺打开应用或恢复未加载聊天。

多个 Codex 聊天可以分别与长期 Bot 保持对话，同一接入配置不合并这些聊天的身份或消息。独立验证继续作为首个产品价值验证场景。外部会话之间直接通信与群参与按具体场景验证后扩展，不要求外部会话取得内部长期 Bot 的执行身份。

验证方法与协作流程由人、Agent 和项目 Skill 维护，系统提供身份、通信、执行与授权原语，不判断业务是否验收成功，也不预设通用测试引擎或固定开发工作流。

## 使用情境

用户在 Codex 与 konden 团队之间交换需求、成果引用、问题与验证证据。人会在私聊里连续追问、说明目标和授权，也会离开群聊一段时间后回来补读完整报告。

私聊以交互为主，群聊以阅读为主。多位 Bot 连续发送长报告、短确认与交接，包含正文、列表、代码和 diff；人需要在引用、群聊和私聊之间往返并接续原来的阅读与草稿。

## 能力与约束

保留现有真实 Bot、群聊、分组、模型配置、文件附件、授权、停止与继续、例行任务、执行过程和子 Agent。外观与导航服务这些已有能力，不能用演示数据替代生产数据，也不能让引用自动成为点名或授权。架构事实仍以 docs/架构和代码为准。

## 界面原则

采用「轻盈协作」，私聊便于持续交流，群聊优先给阅读留空间。身份清楚，权限归属各 Bot，项目按需；采用成熟组件，不额外增加产品层级。视觉、阅读与输入交互的约束统一见 [Web 界面设计原则](架构/入口/Web.md#界面设计原则)，具体配色、尺寸和样式以代码为准。早期设计资料、原型和截图可从 Git 历史回看，不再单独维护。
