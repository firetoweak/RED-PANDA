# 产品定位

## 为谁解决什么问题

konden 面向在原生编码工具里开发、需要独立验证和持续协作的人。用户保留顺手的开发体验，按需联系一支有名字、能互相交流的长期 Bot 团队，减少重复说明背景、转交报告和推动下一步的工作。当前接入与验证聚焦同机 Codex，其他客户端按真实需要适配，不承诺已经可用。

Bot 各有持久工作目录，通过私信和群聊协作。人设定目标、决定授权与最终取舍，分工和工作方法在交流中形成。编码是优先场景，代码项目是按需使用的执行资源；讨论想法、分析资料和推敲方案也可以独立成立。

## 首个场景：独立验证

用户让 Codex 完成修改、自测并提交 PR，再把需求与明确版本交给长期团队。团队从真实用户操作、需求和边界条件出发取证，把问题与证据交回原聊天；编码端修复后交付新版本复验。使用步骤见[Codex 接入与独立验证](外部协作.md#独立验证)。

这个场景补足开发端容易沿自身实现思路验证的缺口。自测与 CI 是背景，独立团队先按需求和实际行为形成判断；定位问题时可以查代码。报告应提供实际测试版本、复现步骤、预期与实际表现、可复查证据和未验证范围，条件不足时明确说明受阻。

价值由两次交接是否接通决定：准备好的版本能否进入验证，反馈能否回到对应的开发聊天并得到处理。接纳请求、生成报告或发送消息都不能单独证明闭环完成。真实场景重点观察有效问题是否补足自测遗漏、证据能否支持修复，以及每轮减少了多少人工转交与协调；Bot 数量和聊天次数不是价值指标。

## 产品边界

原生工具继续拥有自己的界面、上下文、执行环境和会话管理。konden 通过 MCP 提供外部会话身份与持续双向通信，不包装、托管外部 Coding Agent，也不建设统一开发会话平台。内部 Bot 仍可按任务需要分析代码、修改文件和执行经授权的命令。

每个新聊天分别登记身份，原聊天重连后接续；共用连接配置不合并身份或消息。外部会话在 Web 中可见。同机 Codex Desktop 可按聊天启用收信提醒，但提示入队不代表已处理，也不承诺打开应用或恢复未加载聊天。

验证方法、分工和协作流程由人、Agent 与项目 Skill 维护。系统提供身份、通信、执行和授权原语，不预设固定开发流水线，不判断业务是否验收成功，也不为未知需求建设通用 Agent Framework。

## 使用体验

私聊便于持续交流，群聊给完整报告留出阅读空间。身份与权限归属清楚，项目按需出现；人能查看执行、介入决定并接续原来的阅读与草稿。界面约束集中在 [Web](架构/入口/Web.md#界面设计原则)，后续问题见[后续方向](架构/CodingBot/方向.md)。
