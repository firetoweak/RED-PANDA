# Windows 命令生产链路接入验证

后续的 [Windows 隐藏属性验证](Windows隐藏属性.md) 已补齐本文接入阶段保留的默认 Git 初始化缺口；本文保留该阶段的验证事实。

2026-10-14，Windows 11 x64，非提权。Windows 任务命令已经从[独立原型](WindowsHook原型.md)接入真实工具装配和命令执行器。当前任务入口不再只设置 cwd：只读和可能写入的任务均接入宿主拒写约束；必要组件或接入失败时不执行用户命令。完整沙箱仍未实现。

## 实际接入

Assistant 装配本机任务命令时必须传入任务根。Windows 执行器按这条绑定使用原生启动器和 DLL，不根据命令字符串判断或替换路径。只读命令使用宿主目录，可能写入的命令消费现有文件操作给出的实际挂载目录；进程接入与回收留在执行层，文件视图、证据和发布留在文件层。

生产实现见 [Windows 任务适配器](../../redpanda/execution/local/windows_task.py)、[PowerShell 执行器](../../redpanda/execution/local/powershell.py)与[原生命令组件](../../native/execution/README.md)。产品 CLI 安装和体检没有会话任务根，保留自己的管理执行入口；任务接入失败不能转到这个入口。

原生启动器先等 Python 将其纳入外层 Job，再挂起创建任务 Shell，加入内层 Job，写入本次策略并接入 DLL。DLL 完成接入后握手，随后才放行 Shell。支持的子进程执行同样流程；`CreateProcessW/A` 之外进入已拦截原生创建入口的请求，以及 x86、调试、显式挂起和脱离 Job 的请求明确拒绝。子进程替换完整环境也不会丢失策略。

任务状态使用独立管道，命令输出与退出码不承担控制协议。应用正常返回 125，仍是应用退出；不能据此猜测接入故障。放行前失败返回未启动，运行中的约束故障停止任务并保留部分证据。协议损坏与回收故障原样暴露。正常结束、超时、用户停止和 asyncio 取消都先回收任务进程；只有确认进程静止后，文件操作才能结束。

模型可见描述只新增可执行的路径和写入规则，返回实际 `command_cwd`；没有要求模型理解 hook、锁、内部存储或控制协议。命令内使用相对路径或从当前目录生成绝对路径，文件工具继续使用工作区路径；实际命令目录不承诺跨调用有效。

### Git 的设备访问

生产工具补测发现 Git 使用 `NUL` 时任务被停止。原因是对象已经被识别为非文件设备，却又继续查询其“文件父目录”，产生错误 6。修正后，已确定的非文件对象不参与磁盘父目录检查；磁盘文件继续按原规则约束。为此新增 `NUL` 回归，随后重新验证 Node、Clang 与 Git，没有添加命令名称特判或未接入重试。

默认 `git init` 的隐藏属性限制仍是现有 VFS 的独立缺口。此次开发工具验证先在可信测试准备阶段建立真实仓库，随后通过实际任务入口执行 Git 暂存与差异；不能把这些结果写成挂载内默认初始化已经修复。原始属性对照见[原型验证](WindowsHook原型.md#git-初始化的现有限制)。

## 构建与交付

Detours 固定到 `1dbd4ea281d73d478aa8d09a8b83fbd265f715f7`，上游源码未经修改，离线编译使用现有 LLVM MinGW。Windows 文件服务构建同时构建命令组件；两者分别保存制品、许可证与 SHA256。命令组件独立安装到 `redpanda/execution/bin/`，没有放进 VFS 或重新建立总 Environment。

发布版本固定为 `0.4.2`。本地已生成文件服务包和 `redpanda-execution-windows-x86_64.zip`，SHA256 均已验证；Windows CI 会分别打包并上传，准备脚本分别安装两类组件。组件不完整或校验失败时停止，不在运行命令时编译。**本轮没有向 GitHub 发布运行包。**

实际环境、两类构建清单、源码和制品摘要、包校验值见[元数据](Windows命令链路接入数据/metadata.json)。归档时没有遗留 WinFsp 挂载或文件服务进程。

## 当前边界

这里只保护绑定的宿主任务根，任务根之外的文件、网络和其他副作用不因此获得完整隔离。已测范围是普通 Windows x64 开发工具和当前 WinFsp。代理服务、直接系统调用、主动修改拦截及检查与打开之间的竞争不在保证内，不能称为对抗恶意进程的沙箱；其他平台没有得到同等 hook 保证。

DLL 装载使用完整路径的无损系统代码页编码，必要时使用 Windows 短路径。若系统代码页不能表示安装路径且没有可用短路径，启动会被拒绝；这项限制已写入原生组件说明及跨代码页测试契约。没有通过修改项目 PATH 或丢弃约束来绕开它。

## 复现

构建、打包与标准测试命令见[原生组件说明](../../native/execution/README.md)。额外开发工具检查可从项目根目录运行：

```powershell
redpanda-env/Scripts/python.exe tests/execution/verify_tools.py
```

该脚本只在 `.tools/windows-execution-tools/` 内新建夹具，通过真实 `execute_command` 工具与文件操作执行 Node、Clang 和 Git，结果保存在该目录的 `results.json`。它要求本机已有这些开发工具，不会替用户安装项目工具链。
