# VFS 数据库执行层迁移验证

2026-10-10，迁移提交 `43171f3`。这是当时的验证与测量记录，不表示当前格式兼容性或当前系统性能。

从 Turso 切换到 SQLite 的目的是复用成熟的事务与持久化能力，减少项目自行维护的数据库代码。迁移没有通过削弱文件同步、吞掉错误或保留双引擎路径换取性能。

Windows 上的常规回归、真实挂载、进程中断恢复和产品文件操作专项通过。未修改的基线制品也完成只读对照，验证前后内容一致；这只证明该样本互通，不构成对所有历史格式的兼容承诺。

## 当时的挂载性能对照

同一 Windows 环境、相同操作序列与构建配置，每个引擎运行三轮并交替先后顺序；下表为各轮吞吐的中位数。

| 负载 | Turso → SQLite，次/秒 |
|---|---:|
| 4 KiB 打开、读、关闭 | 1256.5 → 2841.4 |
| 64 KiB 打开、读、关闭 | 1035.3 → 2719.2 |
| 元数据查询 | 1607.4 → 4541.1 |
| 创建、写、同步、改名、删除 | 37.3 → 92.8 |
| 局部写、同步、关闭 | 321.4 → 584.5 |
| 四客户端混合读取 | 974.6 → 1786.7 |
| 四客户端混合写入与同步 | 243.7 → 446.7 |

测量包含 Windows I/O、挂载适配与数据库成本，不是纯 SQL 或冷盘吞吐，也不是完整 Agent 任务性能。不能据此判断更高并发、长时间压力或其他平台；前期纯核心并发实验中的读取退化，也没有被这组挂载结果排除。

后续已移除当时的底层历史机制。现行测试入口见[VFS 验证说明](../../native/vfs/docs/TESTING.md)，具体实现与依赖以代码为准。
