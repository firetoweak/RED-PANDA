# Windows 文件视图强制接入实验

2026-10-14，基线 `007ff9b`，独立实验。

尝试通过 Job Object、Silo 和 Bind Filter，让命令沿原逻辑路径访问 WinFsp 文件视图，同时保持宿主编辑器的视角。**当时的本机组合未通过，不进入生产实现。**

| 检查 | 普通权限 | 管理员权限 |
|---|---|---|
| Silo 创建及进程启动 | 成功 | 成功 |
| 普通 NTFS 目录绑定 | 拒绝访问 | 拒绝访问 |
| WinFsp 挂载绑定 | 拒绝访问 | `ERROR_FLT_DO_NOT_ATTACH` |
| 直接访问 WinFsp 视图 | 成功 | 成功 |

提权、补充进程权限、容器初始化和缩小绑定范围均未解决问题。因此不能归因为用户没有确认 UAC，也不能承诺换一个账户就能工作。普通目录拒绝访问的根因当时未定位；WinFsp 卷附加失败是另一项独立阻碍。

由于绑定失败，原路径透明映射、子进程继承及绕过场景没有得到验证。Silo 启动成功不等于文件接入成功，更不代表完整操作系统隔离。

此后改为保持实际路径身份、从挂载目录启动可能写入的命令，并通过进程 hook 拒绝宿主工作区写入。选型与落地分别见[原型验证](WindowsHook原型.md)和[生产接入](Windows命令链路接入.md)。本实验不证明所有 Windows 方案都不可行。
