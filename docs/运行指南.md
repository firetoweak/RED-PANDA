# 运行指南

首次安装与启动从[项目 README](../README.md#快速开始)开始。这里说明运行参数、模型配置和其他入口；开发环境由开发者自行选择，见[开发指南](开发指南.md)。

## 运行环境

源码运行需要 Git、ripgrep、fd、Node.js 与 npm；Linux 引导脚本还需要 curl。准备脚本自动下载运行所需的 Python 3.13，创建 `redpanda-env`，安装前后端依赖并初始化配置。这个环境只用于运行 RED PANDA，不要求开发者用它修改或测试代码。

准备脚本自动下载固定版本的已编译沙箱。Windows 按需安装 WinFsp 驱动，Linux 需自行准备 FUSE 运行组件与设备权限；要求见[沙箱运行说明](../native/sandbox/README.md)。普通安装不检查或安装 Rust、LLVM、SDK，也不编译原生程序。

### 准备选项

| 准备选项 | Windows | Linux |
| --- | --- | --- |
| 只初始化配置文件，不进入模型向导 | `-NoConfigure` | `--no-configure` |
| 只检查项目所需系统工具 | `-Check` | `--check` |

参数传给 `scripts/setup.ps1` / `scripts/setup.sh`。检查模式仍会准备运行所需的 Python，但不安装项目依赖或初始化配置，也不检查完整的沙箱运行条件。

重复运行会补齐项目依赖，已满足的依赖和已有配置保留。沙箱运行包未变时跳过下载；自行编译的沙箱保留。前端使用 `npm install` 复用现有安装；依赖清单变化时可能同步更新锁文件。CI 使用 `npm ci` 做干净安装。

## 日常启动与更新

按 README 中的平台启动命令运行即可。当前源码入口同时启动后端和 Vite，支持 Python 与前端热重载。浏览器打开终端打印的地址；后端默认端口为 `8765`。

启动命令复用现有环境，不安装依赖、不编译沙箱。拉取更新后，重新运行准备命令即可补齐依赖与匹配的沙箱运行包；如果使用本地构建，原生源码或通信协议变化时由你重新编译。普通 Python 或前端源码修改可使用热重载。

## 模型与工作区

首次准备的终端向导收集供应商、API Key、本地服务地址（按需）、模型 ID 和 compact 阈值。API Key 隐藏输入；本地服务未启用认证时可留空。compact 阈值按模型上下文容量设置。保存后可选择发送一条短请求验证连接。

之后需要重新配置时，在仓库根目录执行：

```powershell
# Windows
.\redpanda-env\Scripts\python.exe -m redpanda.initialize --configure
```

```sh
# Linux
./redpanda-env/bin/python -m redpanda.initialize --configure
```

也可以编辑 `~/.redpanda/connections.json`，并在 Web 侧栏「模型配置」中管理模型和默认值。连接设置在下一次调用时生效；Web 可以在未配置模型时启动。完整说明见[模型配置指南](模型配置.md)。

新建工作区、选择要处理的代码目录，再创建会话开始使用。RED PANDA 的运行环境与工作区的开发环境相互独立；项目需要的 Python、Rust 或其他工具链由用户自行准备。

## 其他入口与数据位置

在仓库根目录，使用运行环境的 Python 执行对应入口：

| 入口 | 用途 |
| --- | --- |
| `web_chat.py` | Web 服务；`--port` 指定端口，`--workspace` 登记工作区 |
| `console_chat.py` | 终端交互；默认工作区为当前目录，`--workspace` 可指定 |
| `acp_chat.py` | 由支持 ACP 的客户端启动，通过 stdio 通信 |

需要由后端直接提供构建好的 Web 页面时，先运行 `npm --prefix web run build`，再用运行环境的 Python 执行 `web_chat.py`，省略 `--dev`。默认地址为 [http://127.0.0.1:8765](http://127.0.0.1:8765)。

个人配置与会话数据保存在 `~/.redpanda`，应位于任务根之外。测试独立实例时，可在准备与启动前设置独立的 `REDPANDA_HOME`；`REDPANDA_CONFIG` 可单独指定模型候选配置文件。详细说明见[模型配置](模型配置.md)。
