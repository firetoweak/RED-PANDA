# 运行指南

首次安装与启动从[项目 README](../README.md#快速开始)开始。这里说明运行参数、模型配置和其他入口；开发环境由开发者自行选择，见[开发指南](开发指南.md)。

## 运行环境

准备脚本自动下载运行所需的 Python，创建 `redpanda-env`，补齐应用工具、安装依赖、构建网页并初始化配置。已有可用的 Git、ripgrep、fd、Node.js 与 npm 会复用；缺少的便携工具保存在项目 `.tools/runtime/`，只加入应用进程及子进程的 PATH，不修改系统设置。这个环境只用于运行 RED PANDA，不代替工作区的开发工具链。

准备分四步：准备应用命令行工具、安装 Python 依赖、安装前端依赖并构建网页、初始化配置。Windows 缺少 Git 时使用便携 Git；Linux 引导需要 curl，缺少 Git 时通过 apt-get / dnf 安装，可能需要 sudo。准备不安装驱动或其他系统组件，也不需要原生编译工具。

浏览器能力也是默认环境的一部分：准备脚本安装固定版本的 Chrome for Testing、Chrome DevTools MCP 与 Playwright。Bot 从能力目录按需加载 `mcp:builtin-chrome-devtools` 或 `mcp:builtin-playwright`，无需安装审批；具体工具从下一次决策开始可用。两项能力使用应用专用 Chrome 的独立无头会话，不读取人的日常 Chrome 配置，关闭后不保留登录状态。它们随产品更新，与用户另行安装的 MCP 分开管理；只读子 Agent 不提供这两项能力。

### 准备选项

| 准备选项 | Windows | Linux |
| --- | --- | --- |
| 安装后在终端配置模型（默认在网页配置） | `-Configure` | `--configure` |
| 只检查项目所需系统工具 | `-Check` | `--check` |

参数传给 `scripts/setup.ps1` / `scripts/setup.sh`。检查模式仍会准备运行所需的 Python，但不安装项目依赖或初始化配置。

重复运行会补齐项目依赖并重新构建网页，已有配置保留。前端按锁文件使用 `npm ci` 安装，不改写锁文件。

## 日常启动与更新

按 README 中的 `scripts/start.ps1` / `scripts/start.sh` 启动，后端直接提供构建好的网页。浏览器打开终端打印的地址；默认端口为 `8765`。修改源码时使用 `scripts/dev.ps1` / `scripts/dev.sh`，支持 Python 与前端热重载。

启动命令复用现有环境，不安装依赖。拉取更新后，重新运行准备命令即可补齐依赖并更新网页。

## 网页检索

网上检索优先使用用户已配置并启用的搜索 MCP（如 Tavily），没有或不可用时再用内置 Exa，最后使用浏览器。Exa 搜索与正文读取无需 API Key，免费服务有限流；检索 Skill 提供来源核实与浏览器使用指引。

准备脚本会发送公开查询，检查备用 Exa 的搜索和网页读取。可用 `python -m redpanda.mcp.check_web` 随时复查；本次检查不代表长期可用保证。

## 模型与工作区

默认在网页侧栏「模型配置」中填写连接和模型，安装过程不等待 API Key。也可显式选择终端向导，填写供应商、API Key、本地服务地址（按需）、模型 ID 和 compact 阈值。API Key 隐藏输入；保存后可选择发送一条短请求验证连接。

之后需要重新配置时，在仓库根目录执行：

```powershell
# Windows
.\redpanda-env\Scripts\python.exe -m redpanda.initialize --configure
```

```sh
# Linux
./redpanda-env/bin/python -m redpanda.initialize --configure
```

也可以编辑 `~/.redpanda/connections.json`，并在 Web 侧栏「模型配置」中管理模型和默认值。连接设置在下一次调用时生效；Web 可以在未配置模型时启动。完整说明见[模型配置指南](模型配置.md)。

新建工作区、选择要处理的代码目录，再在名册里新建 Agent 开始使用。工作区必须是已有首个提交的 Git 仓库；每个 Agent 在自己的分支和工作树里工作，不碰你检出的目录，成果落地到这个项目的集成分支，何时合进你自己的分支由你决定。RED PANDA 的运行环境与工作区的开发环境相互独立；项目需要的 Python、Rust 或其他工具链由用户自行准备。

## 其他入口与数据位置

在仓库根目录，使用运行环境的 Python 执行对应入口：

| 入口 | 用途 |
| --- | --- |
| `web_chat.py` | Web 服务；`--port` 指定端口，`--workspace` 登记工作区 |
| `console_chat.py` | 即开即用的终端单会话；默认工作区为当前目录，`--workspace` 可指定；关闭后不保留会话 |

当前 Web 用于本机个人使用，没有登录鉴权或多用户权限隔离。工具批准只控制操作是否执行，不能用它代替登录保护；当前不支持直接把这个入口作为多人或不可信网络服务使用。

个人配置与会话数据保存在 `~/.redpanda`，应位于任务根之外。同一个数据目录同时只能运行一个 Web，第二个启动会报错并说明被哪个进程占用。测试独立实例时，可在准备与启动前设置独立的 `REDPANDA_HOME`；`REDPANDA_CONFIG` 可单独指定模型候选配置文件。详细说明见[模型配置](模型配置.md)。

终端入口使用自己的数据目录 `~/.redpanda-tui`（`--home` 可指定），不读取 `REDPANDA_HOME` / `REDPANDA_CONFIG`，与 Web 的数据互不相干；首次启动在终端里配置模型。同一目录同时只能开一个终端入口，每次启动都是全新会话。终端入口启动时会清空该目录里的会话与状态，因此 `--home` 不能指向 Web 用过、已有长期 Agent 的数据目录，否则会拒绝启动。
