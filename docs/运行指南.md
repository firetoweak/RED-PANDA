# 运行指南

首次安装与启动从[项目 README](../README.md#快速开始)开始。这里说明运行参数、模型配置和其他入口；开发环境由开发者自行选择，见[开发指南](开发指南.md)。

## 运行环境

准备脚本自动下载运行所需的 Python，创建 `redpanda-env`，补齐应用工具、安装依赖、构建网页并初始化配置。已有可用的 Git、ripgrep、fd、Node.js 与 npm 会复用；缺少的便携工具保存在项目 `.tools/runtime/`，只加入应用进程及子进程的 PATH，不修改系统设置。这个环境只用于运行 RED PANDA，不代替工作区的开发工具链。

准备脚本自动下载固定版本的已编译原生文件服务。Windows 按需安装便携 Git 与 WinFsp 驱动；Linux 引导需要 curl，缺少 Git 或 FUSE 时通过 apt-get / dnf 安装，可能需要 sudo。设备权限由管理员管理，要求见[文件服务运行说明](../native/filesystem/README.md)。普通安装不检查或安装 Rust、LLVM、SDK，也不编译原生程序。

### 准备选项

| 准备选项 | Windows | Linux |
| --- | --- | --- |
| 安装后在终端配置模型（默认在网页配置） | `-Configure` | `--configure` |
| 只检查项目所需系统工具 | `-Check` | `--check` |

参数传给 `scripts/setup.ps1` / `scripts/setup.sh`。检查模式仍会准备运行所需的 Python，但不安装项目依赖或初始化配置，也不检查完整的文件服务运行条件。

重复运行会补齐项目依赖并重新构建网页，已有配置保留。文件服务运行包未变时跳过下载；自行编译的文件服务保留。前端按锁文件使用 `npm ci` 安装，不改写锁文件。

## 日常启动与更新

按 README 中的 `scripts/start.ps1` / `scripts/start.sh` 启动，后端直接提供构建好的网页。浏览器打开终端打印的地址；默认端口为 `8765`。修改源码时使用 `scripts/dev.ps1` / `scripts/dev.sh`，支持 Python 与前端热重载。

启动命令复用现有环境，不安装依赖、不编译原生文件服务。拉取更新后，重新运行准备命令即可补齐依赖、更新网页与匹配的文件服务运行包；如果使用本地构建，原生源码或通信协议变化时由你重新编译。

## 模型与工作区

默认在网页侧栏「模型配置」中填写连接和模型，安装过程不等待 API Key。也可显式选择终端向导，填写供应商、API Key、本地服务地址（按需）、模型 ID 和 compact 阈值。API Key 隐藏输入；保存后可选择发送一条短请求验证连接。

之后需要重新配置时，在仓库根目录执行：

```powershell
# Windows
.\redpanda-env\Scripts\python.exe -m redpanda.initialize --configure
```

```sh
# Linux
./redpanda-env/bin/python -m redpanda.initialize --configure
```

也可以编辑 `~/.redpanda/connections.json`，并在 Web 侧栏「模型配置」中管理模型和默认值。连接设置在下一次调用时生效；Web 可以在未配置模型时启动。完整说明见[模型配置指南](模型配置.md)。

新建工作区、选择要处理的代码目录，再创建会话开始使用。RED PANDA 的运行环境与工作区的开发环境相互独立；项目需要的 Python、Rust 或其他工具链由用户自行准备。

## 其他入口与数据位置

在仓库根目录，使用运行环境的 Python 执行对应入口：

| 入口 | 用途 |
| --- | --- |
| `web_chat.py` | Web 服务；`--port` 指定端口，`--workspace` 登记工作区 |
| `console_chat.py` | 即开即用的终端单会话；默认工作区为当前目录，`--workspace` 可指定；关闭后不保留会话 |

需要由后端直接提供构建好的 Web 页面时，先运行 `npm --prefix web run build`，再用运行环境的 Python 执行 `web_chat.py`，省略 `--dev`。默认地址为 [http://127.0.0.1:8765](http://127.0.0.1:8765)。

当前 Web 用于本机个人使用，没有登录鉴权或多用户权限隔离。工具批准只控制操作是否执行，不能用它代替登录保护；当前不支持直接把这个入口作为多人或不可信网络服务使用。

个人配置与会话数据保存在 `~/.redpanda`，应位于任务根之外。同一个数据目录同时只能运行一个 Web，第二个启动会报错并说明被哪个进程占用。测试独立实例时，可在准备与启动前设置独立的 `REDPANDA_HOME`；`REDPANDA_CONFIG` 可单独指定模型候选配置文件。详细说明见[模型配置](模型配置.md)。

终端入口使用自己的数据目录 `~/.redpanda-tui`（`--home` 可指定），不读取 `REDPANDA_HOME` / `REDPANDA_CONFIG`，与 Web 的数据互不相干；首次启动在终端里配置模型。同一目录同时只能开一个终端入口，每次启动都是全新会话。
