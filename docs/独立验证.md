# 独立验证接入指南

konden 通过 MCP 将原生编码会话与长期 Bot 团队连接起来。用户继续在自己的编码工具里开发，验证团队从需求、真实用户行为与边界条件出发独立取证，将结果交回原会话，修复后继续复验。安装与启动见[快速开始](../README.md#快速开始)，产品目标与边界见[产品定位](../PRODUCT.md)。

## 连接编码工具

先在 Web 创建负责验证的 Bot，并向它说明分工。打开「设置」→「外部验证接入」，生成并复制连接配置，添加到你使用的原生编码工具。目前用于本机连接。

无需给外部智能体取名或选择固定交接人。凭据只在生成时显示，关闭设置前请保存；遗失后撤销并重新生成。

## 从交付到复验

编码端首次调用 `get_context` 自动领取当前聊天的 `identity`、查看同事分工。随后用 `request_verification` 交付需求和明确版本，并按分工选择 `recipient`。交付中应包含：

| 内容 | 要求 |
| --- | --- |
| 验收需求 | 在 `text` 中说明需要验证的可观察行为与预期结果 |
| 成果引用 | `reference` 为 PR 或可获取该版本的仓库、成果引用 |
| 确切版本 | `revision` 为完整提交号 |

取得 `request_id` 后，保留它和 `identity`，在原编码会话中用 `read_feedback` 等待，并按 `next_cursor` 续读。空结果和进度消息都不表示验证通过，应继续等待。验证同事提出问题时，用 `previous_request_id` 关联原请求，补充所需信息。

验证 Bot 使用 `reply_external_message` 区分进度、问题和最终报告。报告应说明通过、发现问题或受阻，给出实际测试版本与证据；发现问题时提供复现步骤、预期与实际表现。开发端的自测结论或 CI 状态不能替代这次独立验证。

编码端收到问题后修复，以新版本、新 `delivery_id` 和 `previous_request_id` 请求复验。复验省略收件人时沿用原同事；网络重试保持原身份、提交标识与内容。

同一连接配置可以供多个聊天复用，各聊天分别领取身份；重连沿用原身份。

## 使用范围与撤销

接入允许团队在已有协作范围内交换验证任务与结果，外部请求不能代你批准命令或读取无关私聊。共用凭据下的聊天身份用于分流，不是权限隔离。

全局设置可撤销该连接配置，所有使用它的聊天立即失去收发能力，既有验证记录继续显示在 Bot 时间线。

客户端需在当前会话主动等待和处理反馈；本入口不负责在客户端结束后自动唤醒它。请求已接纳或报告已生成，只说明对应步骤完成；编码端需要取得反馈、处理问题并交付复验版本，才能接续这次协作。
