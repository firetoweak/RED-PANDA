## 二、确定的修复契约

### A. 本机附件选择与供应商密钥

供应商 API 密钥由用户手动配置到 `connections.json`，仅由后端用于供应商调用。Web 模型配置不返回、不编辑供应商密钥。本次不增加 Web 登录、访问口令或账号系统。

浏览器不得通过提交任意服务器绝对路径挂入附件。后端完成本机文件选择与挂入，只向浏览器返回附件引用或取消结果。删除旧的任意路径入口及其前端重试路径，不保留兼容接口。拖入文件继续上传浏览器提供的字节。

用户显式选择或上传的附件按普通材料处理，不识别、拦截或脱敏附件中的密钥，不建立敏感文件黑名单；显式选择 `connections.json` 本身不在禁止范围内。

验收：正常选择、取消、挂入失败后的明确提示与再次操作、拖入上传均可用；构造任意服务器路径不能通过旧入口或替代入口下载文件；供应商调用正常，Web 配置响应和事件不包含供应商密钥。不能把这项修复描述为整个未鉴权 Web 已有访问控制。

### B. 文件回滚结果与语义处理

Sandbox 负责机械回退并报告实际结果，不判断用户意图。文件同时被人和模型修改，或一方创建后由另一方修改时，不能把机械操作成功等同于语义恢复成功。

两类消费者都必须获得结果：

- 用户：会话回退结果与文件处理结果分别展示；显示涉及文件及实际变更、保留、覆盖、删除、未能处理和原因。部分恢复或失败必须醒目可见，不能只留下内部记录。
- 模型：获得可观察的文件处理结果；明确引导读取当前内容、核对已有修改证据，按用户目标使用普通文件工具做语义修改，并遵守已有写入授权。

不重做 preserve / original 算法，不自动选择更强的策略，不自动补偿，也不反复重试同一次失败。模型可见说明只包含实际结果、限制和下一步动作，不包含内部锁、存储、调度等机制。

文件处理失败时，保留已经创建的新会话并保持暂停，明确告知“会话已回退，文件未完全恢复”。不自动删除新会话或再次改动文件。创建会话的成功响应不能被 Web 当作文件全部恢复的证明。

验收矩阵至少包括：纯模型修改；人和模型先后修改同一文件；双方修改重叠或不重叠；长度变化导致拒绝；模型创建后人修改；人创建后模型修改。分别核对适用的 preserve / original、模型主动回退与用户手动回退，比较执行前后真实文件内容和两类消费者得到的说明。失败场景必须同时验证新会话存在、暂停、文件真实结果可见，无自动纠错。

### C. 中断父会话与子任务

用户中断当前轮次意味着停止父会话本轮推进，并收回尚未结束的子任务。先关闭父会话本轮继续推进，再复用现有 Host 收回能力；相关任务停止并收尾后，才能报告中断完成。

收回产生的回传不能重新唤醒已中断的父轮次。后续独立用户输入仍按原规则处理。某个子任务停止失败必须明确暴露，不能显示全部中断成功。

保留子任务过程和已有成果供查看，不自动撤销文件变化、不自动合入，也不借用归档流程删除子任务工作副本。此项属于 Host 编排，不给 Runtime 增加通用父子取消框架，不改变普通暂停的范围。

验收：多个子任务仍活跃时中断父会话，确认相关执行已停止、无持续业务事件增长、父轮次未被回传唤醒、过程可查看。同时验证活跃子任务期间回滚父会话能够正常收尾；不把尚未复现的回滚等待疑点提前记为修复通过。

### D. 已知入口错误

| 输入或操作 | 响应语义 |
| --- | --- |
| 参数格式错误、无内容消息 | 422，指出不合法的输入 |
| 连接已失效或无效 | 409，提示重新建立连接 |
| 授权目标不存在 | 404 |
| 已授权、已拒绝或当前不可授权 | 409，无重复副作用 |
| 本机选择窗口不可用 | 503，说明当前无法选择 |

由入口识别明确的错误类型。禁止把全部 ValueError 或未知异常转换为普通 4xx；内部契约违规、持久化损坏和未知异常继续原样暴露。Web 展示后端的具体原因。

验收：输入和附件入口的失效连接、空消息、重复授权和拒绝、缺失授权目标；核对状态码、提示与副作用次数。另保留未知内部错误不会被误转换的边界验证。

### E. 模型失败可见与再试

`runnable` 表示仍有待处理输入，不代表模型请求正在执行。不为了消除“卡住”外观而伪造 Runtime 完成状态。

已识别的模型请求失败停止后，Web 明确显示已停止及失败原因；页面刷新后仍可查询当前失败。错误不是助手回复，也不新增持久错误历史系统。刷新恢复针对同一 Host 生命周期，不扩大为服务重启后的完整错误恢复。

沿用现有“再试”，继续原待处理输入，不新增用户消息，不重复已完成工具。已有有限模型请求重试耗尽后等待用户；认证失败提示检查后端配置，未知异常原样暴露。

验收：可控注入认证失败、限流、供应商错误、流式中断，确认失败停止、刷新保留原因、再试仍处理原输入、已完成工具执行次数不增加。未实测的 Retry-After 间隔另列验证待办。

### F. 计划展示

计划是模型上次提交的进度记录，不是执行器的活动状态。Web 标明“模型记录的计划进度”，实际运行状态单独显示；中断完成后显示执行已停止，计划原样保留。

后续继续任务时由模型更新计划。系统不自动把事项改为完成、失败或待办；允许多个事项同时标记进行中，不引入单事项状态机。

验收：中断前后计划内容保持一致，停止状态明确；模型下次成功更新后显示新版本，多个进行中可正常展示。

### G. 附件下载的分支范围

来源会话、历史和原件继续保留，不做垃圾回收。新会话可下载自身挂入的附件及实际继承历史所引用的附件；来源会话中未继承的附件不能仅凭 ID 通过新会话下载。

编辑消息时显式沿用的附件仍可使用，即使原消息不在继承前缀内。发送前的本会话附件预览保留；模型材料仍只按已发送事实中的引用提供，不能因可预览而提前进入模型材料。

验收示例：第一轮引用 A、第二轮引用 B，回到第一轮之后的新分支正常展示 A。新分支 UI 本来没有 B 的入口，因此另用旧会话已知 B 的 ID 构造新分支下载请求，预期 404；旧会话仍能下载 B。同时验证多次分支继承、显式沿用附件和发送前预览。

这是接口范围校验，不是“新会话界面出现了 B”，也不等于在未鉴权 Web 上建立用户间权限隔离。

### H. 本机文件／目录选择器

界面明确说明选择窗口在运行后端的电脑上打开。已知桌面不可用、选择窗口无法创建等情况返回 503，Web 显示原因；未知异常继续暴露。

等待用户选择不设置固定超时。已有取消后的进程清理需验证有效，结束或取消后按钮恢复可用。不新增远程文件浏览器，不把等待四分钟本身判为故障。

验收：当前 Windows 环境实际选择文件与目录、取消、再次打开，以及已知不可用错误的边界验证。Linux 图形环境相关行为没有实测前保持未验，不把错误注入测试记为 Linux 实机通过。

### I. 回滚时停止来源压缩

回滚替代来源会话时，复用现有压缩停止能力，停止其未完成的后台压缩，取消对应的本地模型请求，并等待资源释放。取消中的结果不得继续触发来源业务推进，也不得发布新压缩窗口。

已经提交的压缩历史保留；新分支沿用固定历史继承规则，不接收来源之后的结果。不扩大为普通暂停就取消压缩。

验收：用可控的长请求制造压缩与回滚交叠，确认压缩执行与对应本地请求结束、无迟到发布、无来源续跑、新会话历史正确；同时核对压缩刚完成与回滚竞争的结果。已在供应商端发生的消耗不能撤销。

### T. 计时与超时边界

计时用于观察真实耗时；超时是具体操作的资源限制，两者分开。沿用局部操作边界，不给整个 Agent 任务增加总超时，不建设通用超时框架。

| 类别 | 计时边界 | 超时归属 |
| --- | --- | --- |
| 模型请求 | 每次请求发起至完整接收、失败或取消；流式首字到达不算结束 | 模型客户端管理自己的请求超时，工具与系统处理不消耗这项额度 |
| 工具执行 | 实际开始执行至结果返回或执行终止；授权等待单列 | 模型在工具参数允许范围内设置期限，工具负责到期收尾，不叠加统一工具期限 |
| 系统内部处理 | 具体操作开始至结束或异常，按实际操作记录 | 此阶段只做计时，不设置系统内部处理超时；观测层完善后另行讨论 |
| 等待用户 | 开始等待至用户选择、授权或取消 | 记录等待时间，不自动超时 |

重试请求分别计时，退避等待另记，有限重试规则不变。外层处理不能重复计入内层耗时。并行工具各自记录，不能相加冒充用户经过时间；用户提交到最终回复的总经过时间继续保留。

实现时核对现有固定等待期限的实际归属，避免把内部等待误归入模型或工具额度；不能借本次修复新增系统内部超时策略。先复用已有耗时记录，补必要缺口，不启动完整观测平台建设。

验收：构造“模型—等待授权—工具—系统处理—模型”的路径，核对各段起止、等待不消耗执行期限、工具期限来自模型参数；验证流式完整响应、有限重试、取消与并行耗时的含义。计时采用单调时钟，不用展示用的墙上时间裁决操作期限。
