# 主动跟进、后台更新与个人记忆调研

2026-10-27 调研记录。围绕 Dot、Muse 的主动消息、后台任务更新与记忆，对照 konden 在 `60958be` 的行为；只收敛调查结论与后续方向，不代表新增能力已落地。现行保证见[交互与响应](../架构/CodingBot/交互与响应.md)、[自动化](../架构/运行/自动化.md)和[共同记忆](../架构/上下文/共同记忆.md)。

## 判断

konden 已有到点唤醒、后台执行、结果回流和长期身份。下一步最值得补的是**压缩后仍知道欠谁什么、正在等什么，以及什么时候值得再找人**。不必先建设另一个后台任务框架，也不必先上自动提炼和向量库。

主动性应分开看：已委托工作的进展、约定观察后的跟进、没有具体委托时主动提出建议。前两项直接服务当前独立验证场景；第三项不能仅因技术上能定时运行，就扩成无边界的资料巡查或个人生活助理。

## 三项能力分别说明了什么

### 主动联系：跟进已有职责与自行找事分开

Dot 官方说明同时描述已分配工作和主动研究；主动研究只读，发现先回到 Dot，再决定是否建议或行动。它还将当前对话、检索到的历史和持续笔记区分开来。这能支持职责分层，不能推出某种隐藏的记忆算法。[来源](https://learn.chatgpt.com/docs/dots/tasks-and-memory#proactive-research)

Muse 样本也将[具体的定时观察](https://github.com/win4r/MuseAI-Skills/blob/38bbb45a2c5a0f70de975f6387385770b9ad8aac/home/hatch/docs/scheduling-and-watching.md)与[主动推送](https://github.com/win4r/MuseAI-Skills/blob/38bbb45a2c5a0f70de975f6387385770b9ad8aac/home/hatch/docs/calls-texts-notifications.md#proactive-editions)分开：前者按安排检查，后者选择值得打扰人的事项；具体提醒不能靠后者碰巧选中。[偏好模板](https://github.com/win4r/MuseAI-Skills/blob/38bbb45a2c5a0f70de975f6387385770b9ad8aac/home/hatch/PROACTIVE_PREFERENCES.md)分别记录想听什么、不想听什么、时间与表达方式。

对 konden 的启发是：**保持行动依据与汇报条件可追溯**。完成通知负责把结果带回，模型负责判断它是否改变当前工作、是否需要通知谁。人的“等这个 PR 修好再来找我”应成为可取回的协作约定，不变成系统对正文的条件解析。检查间隔不能被描述成实时监听，消息已接纳也不能被描述成对方已处理。

### 后台更新：执行结果与交付结果分开

Muse 样本的[后台维护说明](https://github.com/win4r/MuseAI-Skills/blob/38bbb45a2c5a0f70de975f6387385770b9ad8aac/home/hatch/docs/self_improvement.md#tracing-what-happened-to-the-work)要求沿记录区分排队、运行、交接和送达，并保留证据空缺。它没有把一次成功运行当作用户已收到结果的证明。Dot 的[控制说明](https://learn.chatgpt.com/docs/dots/controls#stop-work)同样区分停止当前工作、委派与后续安排。

这与 konden 现有边界相容。命令成功退出不能单独证明业务目标达成，子 Agent 回报提供一份待验收材料，Bot 回复给人或给协作者则是另一项事实。协调者仍要对照约定版本验收，再决定交付、补问、修复或继续等待。外部编码端取得反馈并处理，才有机会形成产品定位中的闭环；仅把报告放进其收件处，不证明已唤醒或已修复。

### 记忆：工作时写下与后台整理互补

Muse 样本的[维护说明](https://github.com/win4r/MuseAI-Skills/blob/38bbb45a2c5a0f70de975f6387385770b9ad8aac/home/hatch/docs/self_improvement.md)明确保留会话内主动记笔记，后台整理并不取代它。Rohan 的[环境观察](https://rohanadwankar.github.io/posts/sandbox2.html#memory)进一步描述了笔记正文、来源坐标与检索索引的分工。这支持先明确内容与来源，再按规模引入检索的判断；不证明向量检索是所有长期 Agent 的必要起点。

对 konden，来源需要区分两层：某次写入证明“Bot 记过这件事”，被引用的消息、报告或产物才是内容的依据。另一位 Bot 的说法不能因被提炼进笔记就升级成已核验事实，笔记也不能变成新的授权。

Meta 的[官方说明](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse#our-policy-around-data)明确提出用户可以检查和编辑记忆文件。对 konden，这支持把可查看与可纠正作为个人笔记的方向，而非只能从 Bot 的回答猜它记住了什么；具体界面仍按使用需要设计。

更正与删除也不能混成一件事。Muse 样本的[遗忘流程](https://github.com/win4r/MuseAI-Skills/blob/38bbb45a2c5a0f70de975f6387385770b9ad8aac/opt/hatch/skills/forget/SKILL.md)涉及笔记、派生内容与未来活动，说明只改一段正文未必足以阻止旧信息回来。konden 应明确“停止作为当前依据”与“删除原始历史”的差别；未来自动提炼必须尊重已发生的纠正，不能从旧材料重新恢复已撤回的结论。

## 对照 konden 的实际缺口

| 当前基础 | 仍需验证的问题 | 最小方向 |
|---|---|---|
| 一次性唤醒、例行任务与结果回流 | 长期职责改变后，旧安排是否仍有必要 | 模型结合最新要求维护安排；不新增任务语义调度器 |
| 长命令与子 Agent 在后台执行 | 结果回来时是否沿用过时目标，或把已报告内容再报一次 | 先取回当前约定和待交付事项，再判断结果；不靠持续轮询 |
| 普通回复直接给人，协作消息显式发送 | 无变化、重复或过时的后台结果是否制造低价值气泡 | 记录真实噪音，再单独设计可追溯的安静收尾；不能只在 Prompt 里承诺不打扰 |
| 共同短笔记和当前工作计划可跨压缩重现 | 多个并行职责、等待条件与临时规则是否在替换计划后丢失 | Agent 自己维护个人笔记，任务计划继续表达当前任务 |

这一对照来自静态阅读 [Prompt](../../konden/assistant/context/prompt.py)、[工作计划](../../konden/assistant/work_plan.py)、[共同记忆](../../konden/assistant/shared_memory.py)及相应架构文档。当前 Prompt 对例行运行和重复后台结果仍要求简短收尾，普通文字会给人看；“只在有意义变化时通知”尚不能当作现行保证。没有据此声称已复现漏报、噪音频率或压缩损失。

## 收敛到后续方向

先用个人笔记承接跨任务职责：谁在等什么、对应哪个交付版本、已经取得什么证据、哪些要求后来变了。内容由模型维护，系统提供持久位置与明确取回入口；它不判定完成，不把所有笔记塞进共同记忆，也不把单个任务计划扩成团队任务数据库。稳定偏好与待交付事项在内容上应能分辨，先不固化字段或建新产品层级。

主动跟进继续组合现有原语。已有完成通知的后台命令与子 Agent 不靠反复轮询等待结果；等待同事报告是否需要稍后补查，由模型按职责决定。确有下一次观察需要时才用一次性唤醒，持续职责才用例行任务。能否继续由最新要求和实际证据决定，不由唤醒次数或工作时长决定。

安静收尾值得验证，但需要独立的交互决定：模型如何明确表示这次无需通知，处理记录如何保留，异常和待人决策如何仍然可见。它不应恢复强制回答工具，也不应靠前端隐藏已经交付的回复，或让 Runtime 阅读正文判断价值。本轮不改变普通回复直接给人的规则与决策产出不变量。

只有真实使用证明在线笔记仍会漏记，才进一步设计自动提炼。届时优先处理新增材料，保留来源与纠正，索引可从正文重建；先观察回忆命中、错误承接和成本，再决定检索方式。不照搬固定小时任务、人格文件全集、生活关系档案或多层自动反思流水线。

这些方向分别归入 [Coding Bot 后续方向](../架构/CodingBot/方向.md#主动跟进与后台更新)和[个人记忆](../架构/未开始/记忆.md)，不另立实施计划。

## 能改变判断的验证

用一次真实的 PR 验证往返观察：派发旧版本后用户更改规则，协调者处理另一项工作并经历压缩，旧结果随后回来。核对它是否记得交付对象和版本、按新规则处置旧报告、继续复验并清理已无必要的观察安排。记录人工补背景与转述次数、重复派单、无变化汇报和真正漏报；不以 Bot 数量或聊天次数衡量价值。

个人笔记还应经受更正后的再次压缩：旧结论是否仍被当作当前依据，私下信息是否被误放入共同记忆。恢复只核对已经保存的观察与处理记录；结果未知时仍保持未知，不凭笔记补写成功，也不自动重跑副作用。

本轮只查阅公开文本和仓库材料、对照 konden 代码与文档；没有登录测试 Dot／Muse，没有运行其二进制或复现 REA 操作，也没有执行 konden 真模型场景。线上触发频率、送达可靠性、记忆准确率和上述使用收益均未验证。
