# Raft 边界测试借鉴

2026-10-23 学习记录。供 v4 之后按真实需求选用，不是实施计划，也不代表 RED PANDA 已具备这些机制或测试。当前行为以代码和架构准绳为准。

依据为 Raft 公开快照 [`db5e399`](https://github.com/botiverse/raft-source/tree/db5e399f017d584e49597e3a28757645d6807893) 中抽读的代表性测试；本轮没有运行 Raft，不据此评价实际故障率或完整覆盖率。

## 方法比数量更有价值

**小范围穷举和固定种子生成互补。** Agent 活动测试穷举五个事件的 120 种排列，再以固定种子生成 250 组含重复、双来源和多代次的场景。只比较契约要求一致的当前状态，不要求本来允许保留到达细节的日志也完全相同。见[属性测试](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/packages/web/tests/agentActivityEventsReducer.test.ts#L995)。

**预期答案独立于被测实现。** 线程回复测试枚举 22,461 种有限交错，在不同位置插入权威快照，之后每一步都核对独立服务端样例。它明确限定同代次、只新增回复、不涵盖编辑删除和无界事件流。不能把这个数量当成完整系统覆盖率。见[有限穷举](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/packages/web/tests/threadRepliesSameWatermarkProperty.test.ts#L100)。

**确认故障窗口真的被触发。** 分配竞争测试会等数据库连接实际进入锁等待，再释放竞争；只写两个并发调用不能证明发生过竞争。I/O 错误注入、重建组件与真实强杀进程分别提供不同强度的证据，不互相冒充。

**辨别模型测试与生产链路。** 生命周期属性测试明确是独立契约模型，生产事件接入另有后续事项；它能说明目标规则与反例，不能单独证明生产实现已遵守规则。见[文件说明](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/packages/server/src/services/agentLifecycleReducer.property.test.ts#L3)。

## RED PANDA 的采用边界

当前只选择已有 Web 交互中的外部时序：旧会话快照晚到、切换 Bot／群期间旧请求返回，以及重连快照与流式输出、最终结果交错。以真实 API 缓存、事件桥和页面验证现有契约，不为测试引入通用同步核心、代次协议或新的运行状态。

v4 后再按届时存在的业务入口与故障证据选用上表。HTTP 与 SSE 的跨通道顺序可以改变；同一 SSE 连接内仍遵守服务端发送顺序，不能人为打乱有序传输后要求系统承担不存在的契约。有限排列足以说明问题时先用有限排列，不为使用属性测试库引入依赖。已有成熟机制继续复用，测试不倒推产品需求或额外防御分支。
