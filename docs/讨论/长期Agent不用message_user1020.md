# 长期 Agent 不用 message_user 回答人

2026-10-20 观察与实验记录。保留当时现象、测量和待研究判断，不作为架构准绳。后续决定允许普通回复直接给人看，保留显式同事与群消息边界；当前规则见 [CodingBot 总览](../架构/CodingBot/总览.md#结尾文字的去向)。下文实验仍按当时版本记录。

## 背景

[firetoweak/RED-PANDA#112](https://github.com/firetoweak/RED-PANDA/pull/112) 把长期 Agent 的去向改成显式：给人用 `message_user`，每一轮的结尾文字一律是工作记录（[CodingBot 总览 · 结尾文字的去向](../架构/CodingBot/总览.md#结尾文字的去向)）。理由是按「这一轮由什么开始」推断去向，会在合并的一帧里把给人的回答藏进工作记录，也要求模型理解它看不见的内部推导。当时接受的代价是：模型漏发 `message_user` 属于行动遗漏，靠契约与实测改进，系统不替它补。

## 现象

合入后的真实应用验证（deepseek/deepseek-flash）：人在 Web 里直接问长期 Agent，16 次里只有 3 次用了 `message_user`。其余回答进了折叠的工作记录，人只看到第一行，也没有「复制回复」。是否使用和会话历史强相关：一开始没用的 Agent，后面也一直不用。人明确要求时 3/3 会用。

验证地图 `web-session-chat.md` 的冒烟仍按旧判据期待「请只回复 PING_OK」出现在回复里，现在判为不通过。

## 本地复现

用真实 Host 装配（`bootstrap_assistant`、隔离数据根、本机 deepseek-flash 配置），在临时项目里新建 4 个长期 Agent，每个依次问若干普通技术问题，统计每个问题之后是否有 `message_user` 调用。评测脚本是一次性的，留在本机，未归档。

| 场景 | 代码 | 结果 |
|---|---|---|
| 4 个问题，无引导 | main | 12/16；另一轮 16/16，波动大 |
| 先问「请只回复 PING_OK」，再 4 个问题 | main | 9/20、10/20 |
| 同上 | 加两条说明（见下） | 20/20、20/20 |
| 先在 main 上用 PING 开场积累 5 轮纯文字回答，再换代码问 4 个新问题 | 加两条说明，system 角色 | 8/16：已用的照用，已不用的 0/4 |
| 同一批 Agent 继续 | 说明改成 user 角色 | 12/16：救回一个，另一个仍 0/4 |

复现了「第一轮怎么回答，之后就一直照做」：PING_OK 这类「只回复某某」的开场让模型用纯文字作答，之后的问题照这个模式继续。

试过的两条说明，都只描述可观察的行为，由事件确定性地生成：

- 每条人的消息旁边：「这是人发给你的消息。人只看得到你用 message_user 发给他的话；回答或汇报都用 message_user，你最后的文字回复他看不到。」
- Agent 每段文字之后：「你上面这段文字只留在你的工作记录里，人没有看到。」

卡住的 Agent 在两条说明都在上下文里的情况下仍用纯文字回答，正文还写着「这个问题前面已经答过……需要细节可以回头翻」——它相信人看到了此前的回答。

## 待研究判断

**说明能纠正冷启动，纠正不了模型自己的历史。** 新会话里两条说明足以让 deepseek-flash 稳定使用 `message_user`；会话一旦积累了几轮「纯文字作答」，模型更相信自己的历史而不是旁边的说明。

**根子可能不在提示词，而在模型看到的世界与实际行为不一致。** 长期 Agent 的结尾文字原先确实交给人，经一个不出现在投影里的内部交付命令完成；#112 改了去向，模型的历史和协议形态没有变：它以 assistant 角色说出的话，看起来就是对人的回答。靠旁注去否认模型自己最强的信号，只能部分生效。

**几个方向，均未决定：**

1. **让纯文字在协议上就不是「回答」。** 例如长期 Agent 的结尾文字在投影里不再以普通 assistant 回复出现，或者长期 Agent 只能经工具结束一轮，从而让「说了人就看到」这个错觉没有来源。要回答：「一次决策必须有产出」的 Runtime 契约是否、如何为长期 Agent 调整；投影改写是否破坏前缀缓存与 Compact；它是否仍只表达可观察行为。
2. **保留显式方案，接受说明 + 历史的现状。** 新 Agent 基本可用，已有 Agent 可能长期卡住；需要回答已有会话怎么处理，以及更弱的模型会怎样。
3. **回到按来源决定去向**（人开始的一轮结尾交给人）。#112 已经说明它的问题：合并帧里会藏起给人的回答，提示词要求模型理解看不见的推导。若回到它，需要先解决这两点。
4. **按模型能力区分。** 未测 deepseek-v4-pro 等更强模型；若差异很大，可能是模型选择问题而不是架构问题。只凭一个模型的数据不足以下结论。

**不能做的：** 不能由 Runtime 根据回复文字猜测「这是在回答人」并替模型投递；不能为提高使用率在模型可见文字里解释内部交付机制。

## 未覆盖

- 只测了 deepseek-flash；样本小（每组 16～20 个问题），波动明显。
- 只测了人直接提问；同事私信、群、例行任务开始的一轮里 Agent 是否该告诉人、是否做到，未测。
- 两条说明的试验改动未合入，保存在本地。
- 工作记录折叠后只显示第一行、没有复制，是展示层的独立问题，未处理。
