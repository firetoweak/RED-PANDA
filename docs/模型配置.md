# 模型配置

首次启动 HelperMe 后，编辑提示位置的 `config.json`。选择下面一种配置，用整个代码块替换配置文件中 `model` 的值，再把“填入……”内容换成真实值。

例如配置文件原来是：

```json
{
  "model": {},
  "runtime": {},
  "channels": {}
}
```

只替换 `model` 后面的对象，不删除 `runtime` 和 `channels`。HelperMe 在导入 LiteLLM 前固定启用包内模型资料表，并使用 LiteLLM 随包安装的 tokenizer 资源；这不是用户可调配置。

HelperMe 每次调用模型都会提供工具。所选模型及其接口必须支持 OpenAI 风格的工具调用，否则即使连接成功也不能正常运行 Agent。

使用 OpenAI、DeepSeek、Anthropic、Gemini、OpenRouter 等 LiteLLM 已知的官方 Provider 时，不需要填写 URL，LiteLLM 已经知道官方接口地址。只有 Azure、自建 vLLM、Ollama、反向代理和第三方 OpenAI-compatible 接口需要填写 `api_base`。

`active` 是你自己定义的名称，可以任意填写；只需与要使用的 `model_list[].model_name` 保持一致。`litellm_params.model` 才是实际调用的模型名，必须按对应服务方的要求填写。

## DeepSeek 官方 API

### DeepSeek V4 Pro

填写 DeepSeek API Key 后即可使用：

```json
{
  "active": "deepseek-v4-pro",
  "router": {
    "model_list": [
      {
        "model_name": "deepseek-v4-pro",
        "litellm_params": {
          "model": "deepseek/deepseek-v4-pro",
          "api_key": "填入 DeepSeek API Key",
          "reasoning_effort": "high"
        }
      }
    ]
  }
}
```

{
  "active": "deepseek-v4-flash",

    "model_list": [
      {
        "model_name": "deepseek-v4-flash",

## OpenAI

填写 OpenAI API Key；需要其他模型时，修改 `litellm_params.model` 中的实际模型名。

```json
{
  "active": "gpt-5.6-luna",
  "router": {
    "model_list": [
      {
        "model_name": "gpt-5.6-luna",
        "litellm_params": {
          "model": "openai/gpt-5.6-luna",
          "api_key": "填入 OpenAI API Key"
        }
      }
    ]
  }
}
```

可用模型见 [LiteLLM OpenAI 文档](https://docs.litellm.ai/docs/providers/openai)。

## Azure OpenAI

`litellm_params.model` 中填写 Azure 的部署名，不是基础模型名：

```json
{
  "active": "azure-main",
  "router": {
    "model_list": [
      {
        "model_name": "azure-main",
        "litellm_params": {
          "model": "azure/填入 Azure 部署名",
          "api_base": "https://填入资源名.openai.azure.com/",
          "api_version": "填入 Azure API Version",
          "api_key": "填入 Azure API Key"
        }
      }
    ]
  }
}
```

参数由具体 Azure 部署决定，见 [LiteLLM Azure OpenAI 文档](https://docs.litellm.ai/docs/providers/azure)。

## OpenRouter

把 `<厂商>/<模型名>` 换成 OpenRouter 模型列表中的完整标识，例如 `anthropic/claude-sonnet-5`：

```json
{
  "active": "openrouter-main",
  "router": {
    "model_list": [
      {
        "model_name": "openrouter-main",
        "litellm_params": {
          "model": "openrouter/<厂商>/<模型名>",
          "api_key": "填入 OpenRouter API Key"
        }
      }
    ]
  }
}
```

完整模型名见 [LiteLLM OpenRouter 文档](https://docs.litellm.ai/docs/providers/openrouter)。

## 第三方 OpenAI 兼容接口

适用于提供 `/v1/chat/completions` 的云服务、反向代理或模型平台。模型名必须是该接口实际接受的名字：

`litellm_params.model` 必须写成 `openai/接口模型名`。

```json
{
  "active": "compatible-main",
  "router": {
    "model_list": [
      {
        "model_name": "compatible-main",
        "litellm_params": {
          "model": "openai/填入接口模型名",
          "api_base": "https://填入接口地址/v1",
          "api_key": "填入接口 API Key"
        }
      }
    ]
  }
}
```

即使接口没有鉴权，`openai/` 路由也需要非空 `api_key`，可填写接口约定的占位值，例如 `EMPTY`。接口地址是否包含 `/v1` 以服务方文档为准。详见 [LiteLLM OpenAI-Compatible 文档](https://docs.litellm.ai/docs/providers/openai_compatible)。

## 私有 vLLM

先启动 vLLM 的 OpenAI-compatible HTTP 服务。下面假设它监听 `127.0.0.1:8000`，服务模型名为 `Qwen/Qwen3-32B`，没有启用 API Key：

`litellm_params.model` 中 `hosted_vllm/` 后面的部分是 vLLM 服务实际提供的模型名。

```json
{
  "active": "local-qwen",
  "router": {
    "model_list": [
      {
        "model_name": "local-qwen",
        "litellm_params": {
          "model": "hosted_vllm/Qwen/Qwen3-32B",
          "api_base": "http://127.0.0.1:8000/v1"
        }
      }
    ]
  }
}
```

如果启动 vLLM 时使用：

```powershell
vllm serve Qwen/Qwen3-32B --served-model-name helperme-local --api-key your-token
```

则使用：

```json
{
  "active": "local-qwen",
  "router": {
    "model_list": [
      {
        "model_name": "local-qwen",
        "litellm_params": {
          "model": "hosted_vllm/helperme-local",
          "api_base": "http://127.0.0.1:8000/v1",
          "api_key": "your-token"
        }
      }
    ]
  }
}
```

使用工具前，还要按模型要求配置 vLLM 的工具调用解析器。LiteLLM 当前推荐 HTTP 部署使用 `hosted_vllm/`；不要使用已废弃的进程内 `vllm/` 路由。详见 [LiteLLM vLLM 文档](https://docs.litellm.ai/docs/providers/vllm) 和 [vLLM OpenAI-compatible Server](https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/)。

## Ollama

下面假设已经执行 `ollama pull llama3.1`，并使用默认地址：

`litellm_params.model` 中 `ollama_chat/` 后面的部分是 Ollama 中实际存在的模型名。

```json
{
  "active": "local-ollama",
  "router": {
    "model_list": [
      {
        "model_name": "local-ollama",
        "litellm_params": {
          "model": "ollama_chat/llama3.1",
          "api_base": "http://127.0.0.1:11434"
        },
        "model_info": {
          "supports_function_calling": true
        }
      }
    ]
  }
}
```

模型必须支持工具调用，详见 [LiteLLM Ollama 文档](https://docs.litellm.ai/docs/providers/ollama)。

## 其他厂商

在 [LiteLLM Provider 列表](https://docs.litellm.ai/docs/providers) 找到厂商，取得它要求的 `model` 前缀和参数，然后放入以下模板：

```json
{
  "active": "my-model",
  "router": {
    "model_list": [
      {
        "model_name": "my-model",
        "litellm_params": {
          "model": "填入 LiteLLM 文档中的模型名",
          "api_key": "填入 API Key"
        }
      }
    ]
  }
}
```

Provider 文档若还要求 `api_base`、`api_version`、区域或项目名，也原样加入 `litellm_params`。

## 同时检查上下文长度

`runtime.compact_threshold_tokens` 是必填的正整数，初始配置填入 `200000`。它表示触发后台 compact 的实际输入 token 数，包含缓存命中；不是模型总容量，也不使用百分比。请根据所用模型为新增消息和工具结果留出余量。HelperMe 不做本地 token 预估或总量拦截，实际超限由模型接口报错。

不要把含有真实 API Key 的 `config.json` 提交到版本库。
