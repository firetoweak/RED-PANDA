# 模型配置

HelperMe 直接连接所选模型 Provider 的 OpenAI 兼容接口，不经过外部网关。首次部署按 [README](../README.md) 的三步进行。

HelperMe 首次运行会用默认值创建 `~/.helperme/config.json` 并继续启动，不需要先手写配置。`model.active` 写作 `provider/model`：斜杠前是 Provider，斜杠后原样作为该 Provider 的模型名。切换模型就是改这一个字符串。当前支持的 Provider：

| Provider | 示例 `model.active` | 项目 `.env` 中需要的设置 |
| --- | --- | --- |
| `deepseek` | `deepseek/deepseek-v4-pro` | `DEEPSEEK_API_KEY` |
| `qwen`（阿里云百炼，国内） | `qwen/qwen-plus` | `QWEN_API_KEY` |
| `vllm`（本地部署） | `vllm/Qwen/Qwen3-8B` | `VLLM_BASE_URL`；启动 vLLM 时用了 `--api-key` 才需要 `VLLM_API_KEY` |

安装脚本会从 [.env.example](../.env.example) 创建 `.env`。只需要填当前所选 Provider 的设置；缺少时 HelperMe 启动即报错。vLLM 的模型名是 vLLM 启动时对外提供的模型名，本身可以带斜杠。

HelperMe 配置只有 `model.active` 和 `runtime.compact_threshold_tokens` 两项，不包含接口地址、密钥或推理参数。不要提交项目 `.env` 中的密钥。

`runtime.compact_threshold_tokens` 是触发后台 compact 的输入 token 数，包含缓存命中；不是模型总容量。请为新增消息和工具结果留出上下文余量；换到上下文更小的模型时要一起调低。HelperMe 不做本地 token 预估或总量拦截，实际超限由模型接口报错。
