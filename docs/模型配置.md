# 模型配置

RED PANDA 直接连接内置供应商的 OpenAI 兼容 Chat Completions 接口。模型标识为 `provider/model`，按第一个斜杠拆分，后面的模型 ID 原样发给服务。请填写自己的服务实际支持的模型 ID；一个供应商可以配置多个候选模型。

## 终端配置向导

首次运行源码准备命令时，未填写默认模型或连接设置且终端可交互，会自动进入向导。已有完整默认设置时保留配置。之后可使用项目 Python 单独运行向导：

```powershell
# Windows，在仓库根目录执行
.\redpanda-env\Scripts\python.exe -m redpanda.initialize --configure
```

```sh
# Linux，在仓库根目录执行
./redpanda-env/bin/python -m redpanda.initialize --configure
```

向导收集供应商、隐藏输入的 API Key、本地服务地址（按需）、模型 ID 与 compact 阈值；支持的模型还可以设置推理程度。新模型必须显式填写大于 0 的 compact 阈值，按模型上下文容量留出余量。修改已有模型时回车保留当前值，密钥不会显示。

保存会保留其他供应商和候选模型，将选定模型设为新会话默认值。之后可选择发送一条短请求测试连接；测试失败保留已保存配置并显示原因。非交互环境不会等待输入，可手工编辑下面的文件，或稍后单独运行向导。

首次生成的模型配置为 `{"model": {"default": null, "candidates": []}}`，不预选供应商。模型尚未配置时仍可进入 Web 页面。

## 个人连接文件

安装或首次启动会在 `~/.redpanda` 创建 `connections.json` 和 `config.json`。设置 `REDPANDA_HOME` 可更换整个个人数据目录；`REDPANDA_CONFIG` 只指定候选模型配置文件的位置。代码目录不再创建或读取 `.env`，API Key 环境变量也不再作为模型凭据来源。

`connections.json` 包含全部内置供应商。下面是创建时的结构：

```json
{
  "deepseek": { "api_key": "" },
  "openai": { "api_key": "" },
  "qwen": { "api_key": "" },
  "stepfun": { "api_key": "" },
  "bigmodel": { "api_key": "" },
  "vllm": { "api_key": "", "base_url": "http://127.0.0.1:8000/v1" },
  "ollama": { "api_key": "", "base_url": "http://127.0.0.1:11434/v1" }
}
```

远程供应商填写自己的密钥。Qwen 使用阿里云百炼国内地址，StepFun 为阶跃星辰，BigModel 为智谱通用 API；这些远程接口地址由内置 Provider 表确定。vLLM 与 Ollama 使用本地服务地址，地址包含 `/v1`；未启用认证时密钥留空。Ollama 的模型名保留本地名称中的标签，例如 `qwen3:8b`。vLLM 模型名可以带斜杠。

保存连接文件后，**下一次模型调用使用新连接，无需重启**。正在进行的请求继续用原连接完成。Web 的「已配置」只表示填写了必要设置，不代表服务在线或密钥有效；页面不接收或回显密钥。连接未配置时仍能进入 Web 配置页。

## Web 配置与会话切换

每个已保存的候选模型都有「测试」按钮，会使用最新连接配置发送一条简短请求，并显示测试结果、耗时和失败原因。测试独立于会话，不改变默认模型或会话选择；新添加或改名的模型需先保存。

侧栏「模型配置」页面可添加、编辑、删除候选模型，并指定新会话默认值。添加时选择供应商、填写模型 ID 和 compact 触发值，最后保存配置。它们保存在 `config.json`，下面是配置后的示例：

```json
{
  "model": {
    "default": "deepseek/deepseek-v4-pro",
    "candidates": [
      {
        "model": "deepseek/deepseek-v4-pro",
        "compact_threshold_tokens": 200000
      }
    ]
  }
}
```

可按账号提供的模型 ID 添加同一供应商的 Pro、Flash 等模型。会话输入区的「会话模型」下拉只允许选择已配置连接的候选模型，选择独立保存为会话元数据。正在执行的 Step 完成后，下一次决策使用新选择；完整历史与工具结果保留。分支及子会话继承创建时父会话的选择，随后各自独立。

修改默认值只影响新建会话。删除模型前先保存新的默认值，并切换仍选用它的会话；页面会显示无法删除的原因。手工编辑配置同样需要保持这些引用完整，损坏或非法持久配置会直接报错，不回退到旧配置。

`compact_threshold_tokens` 属于各候选模型，是触发上下文整理的输入 token 数，包含缓存命中，不是模型总容量。请按模型容量留出新消息和工具结果的余量。切换模型不会自动丢弃或裁剪历史；上下文超限等上游错误走现有失败展示。

`stepfun/step-5-preview` 可在模型编辑中选择推理程度：低（`low`）、中（`medium`）、高（`high`）或供应商默认。选择后，候选配置保存可选字段 `reasoning_effort`；供应商默认省略该字段，请求也不指定程度。目前只为这个型号开放设置。依据见 [StepFun 官方模型说明](https://platform.stepfun.ai/docs/en/guides/models/step-5-preview)。

保存后，下一次决策使用新程度；在途请求和已启动的上下文整理任务保留启动时的设置。「测试」按钮也使用已保存的推理程度，修改后先保存再测试。

旧部署需一次性把 `model.active` 与全局 compact 阈值转成上述候选结构，把代码目录的模型凭据转入个人连接文件，并给已有会话保存原模型选择。产品启动只读取新格式，不保留旧配置兼容路径。

## 可选 Jev 进展检查

Jev 独立于会话的 Chat Completions 模型，使用 TypeSafe 的 Choice 接口。配置保存在个人目录的 `jev.json`，与 `connections.json` 同级；缺少此文件、关闭或密钥为空时只使用机械重复提醒。保存后后续检查读取新配置，不改变在途检查。

下面是关闭状态的完整示例：

```json
{
  "enabled": false,
  "api_key": "",
  "model": "jev-1.13.0",
  "interval_steps": 8,
  "recent_steps": 12,
  "state_max_tokens": 4096,
  "timeout_seconds": 3.0,
  "remind_confidence": 1.0,
  "pause_confidence": 1.0
}
```

启用时填写自己的密钥并设置 `enabled=true`。字段必须完整，非法配置会明确报错。模型必须固定版本，不接受 `jev-latest`、`jev-preview`；提醒和暂停阈值需要用真实中文任务分别校准，示例值没有经过质量校准，不是推荐阈值。

`interval_steps` 是两次增强检查间的已提交决策数量，`recent_steps` 限制近期操作范围。`state_max_tokens` 是按本地分词器估计的状态预算，允许 1024–8000；完整批次超出预算时省略较旧批次并标明省略。`timeout_seconds` 限定一次增强请求的等待时间。超时、已知调用失败、非法响应或置信度不足时使用机械判定，不阻塞正常执行。

Jev 可以选择继续、提醒或暂停。暂停复用现有中断操作，会取消当前模型调用并打断支持中断的在途命令；已经发生的副作用不会自动撤销。主会话显示系统警告，子会话向父模型投递固定通知。英文判决题固定，状态保留原文；题目、模型版本或状态裁剪方式变化后须重新验证校准结果。
