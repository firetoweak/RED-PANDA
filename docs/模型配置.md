# 模型配置

HelperMe 通过本机 HTTP 使用随项目安装、独立运行的 Ferro。Provider 凭据和路由由 Ferro 管理；HelperMe 选择 Ferro 提供的模型。

首次部署按 [README](../README.md) 的三步进行。安装脚本只写入 `FERRO_MASTER_KEY`；当前 `ferro/config.yaml` 的 target 是 `deepseek`，启动前要在项目 `.env` 里写上 `DEEPSEEK_API_KEY`。Ferro 只在启动时读取它。启动 Ferro 后，可运行下面的命令查看可用模型：

```sh
./helperme-env/bin/python -m helperme.ferro_gateway models
```

Windows 使用 `helperme-env\Scripts\python.exe` 代替 `helperme-env/bin/python`。

HelperMe 首次运行会创建 `~/.helperme/config.json`。`model.active` 保存当前选择的模型 ID，必须与 Ferro 提供的某一项完全一致。切换模型时，将它改为列表中的另一个 ID。若模型未出现在列表中，先确认 Ferro 的 Provider target 与模型配置。

HelperMe 配置只保留模型选择，不包含 Provider、Ferro 连接凭据或推理参数。完整结构见 [config.example.json](../config.example.json)。不要提交项目 `.env` 中的密钥。

Ferro 侧不要配置 `mcp_servers` 来执行 HelperMe 工具。HelperMe 会发送自己的工具集并负责工具执行。

`runtime.compact_threshold_tokens` 是触发后台 compact 的输入 token 数，包含缓存命中；不是模型总容量。请为新增消息和工具结果留出上下文余量。HelperMe 不做本地 token 预估或总量拦截，实际超限由模型接口报错。
