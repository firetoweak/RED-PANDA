# 模型配置

konden 直接连接内置供应商；`openai` 与 `openai-codex` 使用 Responses API，其他供应商使用 Chat Completions。`openai` 沿用 API Key，无需更换密钥或修改连接配置。模型标识为 `provider/model`，按第一个斜杠拆分，后面的模型 ID 原样发给服务。请填写自己的服务实际支持的模型 ID；一个供应商可以配置多个候选模型。

## 终端配置向导

首次运行源码准备命令时，未填写默认模型或连接设置且终端可交互，会自动进入向导。已有完整默认设置时保留配置。之后可使用项目 Python 单独运行向导：

```powershell
# Windows，在仓库根目录执行
.\konden-env\Scripts\python.exe -m konden.initialize --configure
```

```sh
# Linux，在仓库根目录执行
./konden-env/bin/python -m konden.initialize --configure
```

向导收集供应商、隐藏输入的 API Key、本地服务地址（按需）、模型 ID 与 compact 阈值；支持的模型还可以设置推理程度。新模型必须显式填写大于 0 的 compact 阈值，按模型上下文容量留出余量。修改已有模型时回车保留当前值，密钥不会显示。

保存会保留其他供应商和候选模型，将选定模型设为新会话默认值。之后可选择发送一条短请求测试连接；测试失败保留已保存配置并显示原因。


## 个人连接文件

安装或首次启动会在 `~/.konden` 创建 `connections.json` 和 `config.json`。设置 `KONDEN_HOME` 可更换整个个人数据目录；`KONDEN_CONFIG` 只指定候选模型配置文件的位置。普通供应商的密钥保存在 `connections.json`；Codex 连接只保存凭据文件的引用。

`connections.json` 包含全部内置供应商。下面是创建时的结构：

```json
{
  "deepseek": { "api_key": "" },
  "openai": { "api_key": "" },
  "openai-codex": { "auth_file": "" },
  "qwen": { "api_key": "" },
  "stepfun": { "api_key": "" },
  "bigmodel": { "api_key": "" },
  "vllm": { "api_key": "", "base_url": "http://127.0.0.1:8000/v1" },
  "ollama": { "api_key": "", "base_url": "http://127.0.0.1:11434/v1" }
}
```

远程供应商填写自己的密钥。Qwen 使用阿里云百炼国内地址，StepFun 为阶跃星辰，BigModel 为智谱通用 API；这些远程接口地址由内置 Provider 表确定。vLLM 与 Ollama 使用本地服务地址，地址包含 `/v1`；未启用认证时密钥留空。Ollama 的模型名保留本地名称中的标签，例如 `qwen3:8b`。vLLM 模型名可以带斜杠。

所选型号需要支持工具调用，`openai` 还需要支持 Responses API。本地服务能连通不代表所选模型支持工具；vLLM 需要启用自动工具选择并配置匹配的工具解析器，见[官方工具调用说明](https://docs.vllm.ai/en/stable/features/tool_calling/)。页面的「测试」只验证一条简短请求，实际工具能力需通过工具回合核验。

### 复用 Codex 登录额度

`openai-codex` 使用 ChatGPT 账号的 Codex 额度。下面的命令负责复用已有登录或直接完成 OAuth 授权，并输出 `auth_file` 的实际路径；首次授权和后续续期都不需要安装 Codex CLI。

#### 一条命令导出连接配置

在仓库根目录运行项目 Python；已激活项目环境时，可直接执行 `python -m thinllm auth codex`。

```powershell
# Windows
.\konden-env\Scripts\python.exe -m thinllm auth codex
```

```sh
# macOS / Linux
./konden-env/bin/python -m thinllm auth codex
```

命令优先使用 thinllm 已保存的授权；没有时只读复用已有 Codex ChatGPT 登录文件。两者都没有可用登录时，命令直接打开浏览器完成 OAuth 授权，把新凭据独立保存到 `~/.thinllm/codex.json`（Windows 为 `%USERPROFILE%\.thinllm\codex.json`），不改写 Codex 的登录文件或配置。

浏览器会回到本机 `localhost:1455` 完成授权。如果浏览器没有自动打开，可手工打开终端显示的链接；本地回调不可用或超时后，按提示粘贴地址栏里的完整回调 URL（包含 `code` 和 `state`），不要只粘贴授权码。授权必须由用户在浏览器中完成。

成功后，控制台输出可直接粘贴的 JSON，例如：

```json
{
  "openai-codex": {
    "auth_file": "C:/Users/alice/.thinllm/codex.json"
  }
}
```

把输出的 `openai-codex` 项合并到个人 `connections.json`，保留其他供应商项；再在 Web「添加模型」中选择供应商 `openai-codex`，从下拉列表选择模型，保存后点击「测试」。命令会输出这台机器上的实际完整路径，不用自己查找文件或修改示例用户名。`openai` 供应商继续使用 API Key。

命令的标准输出只包含配置 JSON，登录提示写到标准错误；它不打印 token，不自动修改 konden 配置。登录失败或取消时，不输出配置，也不替换已有凭据。已有登录可以在脚本中导出；需要授权时请在交互终端运行。复用已有 Codex 登录时，输出路径会指向它原来的 `auth.json`。

需要重新登录时，在同一命令后加 `--login`：

```sh
python -m thinllm auth codex --login
```

`--login` 总是为 thinllm 重新授权，不覆盖已有 Codex 登录。完成后把新输出的 `openai-codex` 项更新到 `connections.json`；原先显式指向共享 Codex 文件的配置不会自动切换。

`auth_file` 留空时按同样顺序查找：先 `~/.thinllm/codex.json`，再 `CODEX_HOME/auth.json` 或默认的 `~/.codex/auth.json`。显式填写路径则只使用该文件。Codex `keyring` 中的登录不直接读取，可用 `--login` 获取 thinllm 的独立授权。凭据文件含敏感信息，不要提交到 Git 或发给他人。

thinllm 自己保存的授权会在请求前按需自动续期，无需再次打开浏览器；导出命令也会续期临近到期的独立凭据。查看 Web 配置状态不会触发续期。已有 Codex 登录始终只读复用，由 Codex 自己维护；若共享凭据过期，或独立授权已撤销、无法续期，运行 `python -m thinllm auth codex --login` 并更新连接配置即可。续期的网络故障可以重试，原文件保持不变；损坏的文件直接报错，不会悄悄换用其他登录。Web 的已配置状态只说明凭据存在，实际账号权限、额度和模型可用性以连接测试为准。

浏览器授权使用 [oauth-cli-kit](https://github.com/pinhua33/oauth-cli-kit)；共享登录文件说明见 [Codex 官方认证文档](https://learn.chatgpt.com/docs/auth)。

#### 在 Web 中选择 Codex 模型

「添加模型」或「编辑模型」选中 `openai-codex` 后，会用当前连接的登录读取账号模型目录，只展示服务标记为可选择的型号。可按显示名称或模型 ID 搜索；保存时使用目录中的原始 ID，不需要手工填写或调整大小写。其他供应商仍按原来的方式填写模型 ID。

选择型号后自动显示该型号的上下文容量、支持的推理档位与默认档位。信息以当前账号目录为准；供应商未提供的值会明确提示。这里的推理档位是能力展示，不会自动改变调用参数；当前可配置的推理程度仍见下方 StepFun 说明。compact 触发值保持独立，可按任务需要调整，不会被上下文容量覆盖。

每次打开 Codex 型号选择都会重新读取目录。加载失败会展示原因，可点击「重新加载」；失败或空列表时不能加入型号。已有型号若不再出现在账号目录，编辑时会提示重新选择，不会静默替换。目录返回的候选不代表剩余额度或实际调用必定可用，保存后仍应点击「测试」。目录查询与模型调用共用凭据，thinllm 独立授权可以按需续期，共享 Codex 登录继续只读。

脚本也可复用同一查询能力，输出不包含 token 或模型系统提示：

```python
import asyncio
import json
from thinllm import list_codex_models

models = asyncio.run(list_codex_models({"auth_file": ""}))
print(json.dumps(models, ensure_ascii=False, indent=2))
```

保存连接文件后，**下一次模型调用使用新连接，无需重启**。正在进行的请求继续用原连接完成。Web 的「已配置」只表示填写了必要设置，不代表服务在线或密钥有效；页面不接收或回显密钥。连接未配置时仍能进入 Web 配置页。

## Web 配置与会话切换

每个已保存的候选模型都有「测试」按钮，会使用最新连接配置发送一条简短请求，并显示测试结果、耗时和失败原因。测试独立于会话，不改变默认模型或会话选择；新添加或改名的模型需先保存。

侧栏底部「设置 → 模型配置」抽屉可添加、编辑、删除候选模型，并指定新会话默认值。添加时选择供应商、填写模型 ID 和 compact 触发值，最后保存配置。关闭或切换设置会保留当前页面内的未保存修改。它们保存在 `config.json`，下面是配置后的示例：

```json
{
  "model": {
    "default": "deepseek/deepseek-v4-pro",
    "candidates": [
      {
        "model": "deepseek/deepseek-v4-pro",
        "compact_threshold_tokens": 200000
      }
    ]
  }
}
```

可按账号提供的模型 ID 添加同一供应商的 Pro、Flash 等模型。会话输入区的「会话模型」下拉只允许选择已配置连接的候选模型，选择独立保存为会话元数据。正在执行的 Step 完成后，下一次决策使用新选择；完整历史与工具结果保留。子会话继承创建时父会话的选择，随后各自独立。

修改默认值只影响新建会话。删除模型前先保存新的默认值，并切换仍选用它的会话；页面会显示无法删除的原因。手工编辑配置同样需要保持这些引用完整，损坏或非法持久配置会直接报错，不回退到旧配置。

`compact_threshold_tokens` 属于各候选模型，是触发上下文整理的输入 token 数，包含缓存命中，不是模型总容量。请按模型容量留出新消息和工具结果的余量。切换模型不会自动丢弃或裁剪历史；上下文超限等上游错误走现有失败展示。

`stepfun/step-5-preview` 可在模型编辑中选择推理程度：低（`low`）、中（`medium`）、高（`high`）或供应商默认。选择后，候选配置保存可选字段 `reasoning_effort`；供应商默认省略该字段，请求也不指定程度。目前只为这个型号开放设置。依据见 [StepFun 官方模型说明](https://platform.stepfun.ai/docs/en/guides/models/step-5-preview)。

保存后，下一次决策使用新程度；在途请求和已启动的上下文整理任务保留启动时的设置。「测试」按钮也使用已保存的推理程度，修改后先保存再测试。
