# 模型交互可靠性

2026-10-14、20、21 日的记录显示：模型理解要求、表达意图与实际产出约定的工具或正文，是不同的证据。下面三类观察来自不同任务与模型，不能合成一个成功率。

## 回答工具与实际可见性

当时给人回答必须调用 `message_user`，普通结尾只作为折叠工作记录。deepseek-flash 在一次真实应用观察的 16 次直接提问中只调用了 3 次回答工具；它仍可能认为普通正文已经回答了人。

隔离复现发现，说明可以改善新会话，却不能稳定纠正已经积累的回答习惯：

| 条件 | 回答工具调用 |
|---|---|
| 新会话先要求只回复 PING_OK，再追加可观察行为说明 | 两次均为 20/20 |
| 已积累五轮纯文字回答，再在系统角色追加说明 | 8/16 |
| 同一批继续，将说明放到用户角色 | 12/16，仍有一个 Bot 完全不用 |

最后一行是同批续跑，不是独立的角色优劣对照。其他新会话运行也有明显波动，不能把某次全成功当作稳定保证。

当时的选择是让普通回复与人的实际可见性一致，减少协议形态与交互含义的错位，取舍见[交互与响应](../架构/多智能体/交互与响应.md#普通回复给人协作消息显式发送)。原试验只测了该模型和人直接提问，没有验证其他来源开始的工作。

## 协作约定与空结尾

另一组 deepseek-flash 实验创建三位无项目 Bot，依次说明分工、请求同事查已知或未知信息，再在群里讨论。对照组与加入协作约定的组各运行两次：

| 准备阶段 | 对照两次 | 加入约定后两次 |
|---|---|---|
| 工具调用 | 64、55 | 11、10 |
| Bot 间私信 | 16、9 | 0、0 |

约定减少了没有任务依据的寒暄、分工讨论和环境探查。一次对照中，Bot 把关于群记录的提示读成自己应已在某个群里，转而查找配置与数据库；修正措辞后，这类自发工作基本消失。给人的回复更短，但条数没有稳定下降。

随后允许长期 Bot 用空响应结束无需回答的一轮，追加两次运行。两次均没有实际空结尾；有的 Bot 在思考中明确判断“应该沉默”，最后仍输出一句说明。这个试验只说明该模型在这些场景下不能可靠地产出空结尾，不证明更强模型也做不到。

四次原协作运行没有出现把同事回答只写成普通回复的情况。不能因此认定显式工具一概可靠：回答人、回复同事与保持沉默是不同任务，例行任务场景也未测。

## 承诺不等于执行

2026-10-14，stepfun/step-5-preview 被要求连续安装两个 Skill。第一个成功后，模型说马上安装第二个，随后没有提交工具调用。

事实核对确认：安装结果已请求下一次决策，模型也已执行该决策，安装工具仍可见，返回却只有行动承诺。因此本例是“得到执行机会但未调用”，不支持“没有唤醒”或“工具不可用”的解释。

模拟模型与确定性测试能够连续走通两次安装，但这不证明真实模型必然持续执行。该记录只有一个样本，不能确定频率或归因；持续任务静默停下的问题也没有被前两组实验解决。

这些观察支持分别检查输入是否送达、能力是否可见、模型是否实际行动，以及人是否真的看到输出。不能从承诺文字补猜任务状态，也不能让 Runtime 据此替模型选动作或无条件重复唤醒。
