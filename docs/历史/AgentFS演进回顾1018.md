# AgentFS 演进回顾

> 2026-10-18 讨论记录：Agent 文件系统从「改了能回退」一路演进到进程内文件访问介入的过程、推动它的前提，以及转向 coding bot 后这些前提为何不再成立。不是准绳；当时的文件契约文档已随代码移除，现行执行方式见[执行环境](../架构/能力/执行环境.md)，文件成果的当前边界见 [Bot 与协作](../架构/CodingBot/总览.md#git-历史落地与同步)。

## 初衷

只有一句话：Agent 修改文件之后能回退。

## 六步

每一步都在解决上一步带来的问题，每一步单看都合理。

| 步 | 做了什么 | 为什么 |
|---|---|---|
| 1 | Git 版本控制 | 最初只是希望 Agent 修改文件后能回退 |
| 2 | 撞上性能问题 | 多 Session 串行、子工作树复制、反复扫描和哈希，Git 方案难以扩展，见[版本操作分层](版本操作分层1009.md) |
| 3 | VFS + 写时复制 | 减少复制和快照成本 |
| 4 | WinFsp 挂载 | 让普通程序也能访问虚拟文件 |
| 5 | Detours + 路径命名空间 | 兼容宿主绝对路径和正常 Windows 工具链，开始介入进程内部的文件访问 |
| 6 | 进程和系统兼容 | 继续处理 DLL 初始化、进程继承、文件身份、系统服务等问题 |

需求从头到尾没有变，每一级方案的代价却比上一级大，最后从文件版本走进了操作系统虚拟化的深水区。

## 推着它往下走的前提

四个前提同时成立，才逼出了这条路：

1. **Agent 直接修改人正在使用的那个真实目录。**
2. **多个会话共用这一个目录。**
3. **每一步、包括任意命令的副作用，都要能回退。**
4. **普通工具在真实路径上照常工作。**

前两条决定了隔离只能是虚拟的：大家都在同一个目录里，只能在文件系统层把彼此分开。隔离一旦是虚拟的，第 4 条就一级级把方案往下推——先挂载，再路径命名空间，再进程介入。

## coding bot 撤掉了最根本的两个前提

转向 coding bot 后，每个 Agent 有自己的 git worktree 与分支，不碰人检出的工作目录：

- **隔离是物理的。** worktree 是真实目录、真实路径，普通工具链原生可用。VFS 挂载、路径命名空间与进程介入（第 3 到第 6 步）失去了存在的理由。
- **第 2 步的性能问题大部分也不在了：**
  - 串行：每个 Agent 有独立的 worktree 与 index，各自提交，不排同一条队；
  - 整树哈希：在真实仓库里，git 的 index 缓存文件状态，只重新哈希变过的文件；
  - 复制：长期 Agent 的 worktree 只在创建时检出一次；SubAgent 每次委派仍有一次检出成本，当初也已接受。

所以这次回到 git，不是退回第 1 步，而是**在不同的前提下站到了第 1 步**。仍须实测的是第 2 步当年咬人的那一点：大仓库、Windows 下每步自动提交的实际耗时，尤其是未跟踪文件的扫描。

## 教训

**需求不变而每一级方案的代价越来越大时，该回头检查前提，而不是继续往下加一层。**

以后遇到 git 覆盖不到的回退需求（被忽略文件、被删的未跟踪文件、文件属性等），最自然的反应是把 Agent 文件系统接回来——那就是重新爬一遍这架梯子。更好的顺序是先问能不能改前提，例如明确被忽略文件不在撤销承诺之内，或把保护交给进程沙箱。

## 它仍然有价值的地方

与它的上游 [tursodatabase/agentfs](https://github.com/tursodatabase/agentfs)、[Factory-AI/vfs](https://github.com/Factory-AI/vfs) 相比，当时（2026-10）的差异化有三点：

- **Windows**：两个上游都不支持，Factory 明确删除了 Windows 目标；
- **写回真实工作区并核对冲突**：上游的思路是把 Agent 关进沙箱、不碰宿主目录；这里是候选执行、封存后串行发布到人正在用的目录，发布时不覆盖人的修改；
- **撤销时保留人的后续修改**：只撤销仍等于助手结果的位置。

转向 coding bot 之初，曾设想由 TUI 继续使用它：TUI 是直接修改人真实目录的标准单会话 coding agent，前提 1 在那里依然成立；Web 上的 Agent 改用 worktree 与 git。后来 TUI 也放弃了它，见下文结论。

若将来独立，定位会是「给任意 coding agent 用、能在 Windows 上跑的可审计工作区」，以 MCP 服务器加 CLI 作为插件接口；先低成本验证需求，再投入产品化。

## 结论

2026-10-18 已从主仓库整体移除，TUI 也改为直接作用于真实目录。代码保存在主仓库标签 `agentfs-final`（提交 174dcb6）与私有存档仓库 `firetoweak/agentfs`（带历史）。
