# 边界测试方法

2026-10-23 抽读外部 Raft 项目测试代码时整理的方法，补入 2026-09-22 本项目回归的证据教训。没有运行 Raft，只阅读了代表性测试，不据此评价其故障率或完整覆盖。

## 选择有实际后果的交错

| 代表性场景 | 要核对的契约 |
|---|---|
| 同一发送的确认与实时回声换序或重复 | 同一身份只呈现一次；不同身份即使正文相同也保留两条 |
| 切换页面后旧请求或旧错误晚到 | 旧结果不覆盖新页面，旧失败不清除当前请求的状态 |
| 重连补拉与实时流重叠 | 补齐遗漏并消除重复，最终视图与正式数据一致 |

这些例子帮助寻找真实的跨通道顺序，不要求把有序传输任意打乱。例如同一 SSE 连接仍遵守服务端发送顺序，不能为测试制造不存在的产品契约。[旧请求交错示例](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/packages/web/tests/messageWindowGapRecovery.test.ts#L2177)

## 预期答案与故障窗口都要独立

有限排列适合检查小范围交错，固定种子生成可补重复、双来源等组合。只比较契约要求相同的状态，不强迫允许保留到达细节的日志也完全一致；预期答案独立于被测归约器，不能复制实现算出“正确结果”。[有限穷举与独立预期](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/packages/web/tests/threadRepliesSameWatermarkProperty.test.ts#L100)

两个并发调用不证明发生过竞争。需要用明确的等待点确认关键窗口已打开，再释放另一方；错误实现应稳定失败。外部项目的一个数据库用例先确认连接进入锁等待，再继续竞争，证据强于碰运气反复运行。[竞争窗口示例](https://github.com/botiverse/raft-source/blob/db5e399f017d584e49597e3a28757645d6807893/packages/server/src/services/taskService.assignment.realPg.test.ts#L69)

同一原则适用于确认丢失和写入中断：在业务实际承诺的幂等边界核对原身份重试、完整状态与未知结果，不从通用运行机制推导外部副作用恰好一次。

## 观察、根因与验证强度分开

2026-09-22，浏览器在服务重启后点击拒绝未响应，初报确定缺陷，之后因证据不足撤回定级。组件重连与真实 Host/Worker 的拒绝回归分别通过，但浏览器连接已失败，不能据这些结果宣布完整 E2E 通过或根因已找到。

同样，独立契约模型通过不证明生产链路已接入；I/O 错误注入、进程强杀和真实浏览器各证明不同边界。写报告时分别说明观察到什么、已确认的原因和未复验的范围。

本项目已有的 Web 时序验收入口见[实时响应时序基线](../../.claude/skills/verify-konden/features/realtime-events.md#driving-it-with-the-browser)。按真实故障选择有限场景，不为采用测试方法先建通用同步核心、额外协议或产品状态。
