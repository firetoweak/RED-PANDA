# 转向 Coding Bot 的系统审视（2026-10-19）

> 讨论记录，不是准绳。当前方向见 [Coding Bot](../架构/CodingBot/方向.md)，调整顺序已写进其中的 E 线；实际行为以代码与测试为准。

## 起因

项目原先的目的地是「可追溯、可回滚的单会话可控 coding agent」：Step 级文件回退、Agent 文件系统、编辑消息开分支、从某一步重开。目的地改为「几个长期在线的 Coding Bot 在同一项目上协作」之后，Agent 文件系统已经移除，Web 也去掉了分支与重开。这次审视按运行层、上下文层、能力与入口层、文档与验证资产四块，逐项判断每个机制服务旧目标、新目标还是两者通用，找出残留与错配。

## 总判断

底座没有错配。事实、Step、Command，结果未知不降级，命令授权，Compact 的执行骨架，附件按内容寻址，一次性定时，这些都是长期协作同样需要的。原先「可控」的追求留下的确定性事实，正是协作可追溯的基础。

真正变的只有「回滚」：

| 旧口径 | 新口径 |
|---|---|
| 可回滚：Step 级回退、会话分支 | Git 可撤销；回退不越过外泄点 |
| 可追溯 | 不变，而且更重要：消息来源、源头、代码版本 |
| 可控：人逐步审阅 | 人在环内：授权、收件箱、停止、合入 |

错配集中在三类：旧目标留下的死代码与兼容层；单会话假设在长期 Agent 下变成错误行为；文档仍按单会话叙述。

## 旧目标残留

- **会话分叉整条链**：分叉入口在生产代码里已经没有调用方，只剩测试撑着；Journal 的分支前缀、附件与 Artifact 的继承、SubAgent 里为分支重放冻结父身份的逻辑都只为它存在。文档还写着「已经写入的分支 Journal 仍按区间读取」，这是旧设计的兼容层。
- **Web 普通会话接口**：创建、标题、归档、列表在前端已无调用，但后端仍可用，能绕过名册建出普通会话，或把 Agent 归档掉。
- **生产目录里的测试替身**：内存 Journal 与几个只给测试用的函数。

## 单会话假设变成错误行为

- **压缩后丢身份。** 自己的名字、方向、所在群只存在于早期事实里，压缩后的新窗口不会重新呈现；交接提示按「当前任务」写，不提同事、群、派单与规矩。多次压缩后信息逐级损耗，这正是协调者跨天误判的根源。
- **重启暂停整个团队。** Host 启动时把会自己推进的会话一律暂停，而暂停的 Agent 收不到私信推进、会被群调度跳过；群级停止也会把被叫成员置为暂停。长期在线的团队重启后要人逐个继续，外部事件也叫不醒。
- **项目自带的 skill 用不了。** Skill 只从数据根安装目录加载，测试 Agent 无法按项目自己的验证 skill 执行。
- **只认人的消息。** LoopGuard 的连续判定跨越多次唤醒累计，被 CI 唤醒后每次跑同一条检查命令会被误判成循环；上下文保护窗只随人的消息推进，Agent 之间长时间往来时不脱水；同事与群消息不带接纳时间。
- **同事的未落地改动读不到。** 文件范围限于自己的 worktree，分支名对模型不可见。
- **扩展登记是全局的。** MCP、Skill、CLI 登记按数据根共享、只有进程内锁，多个 Agent Worker 并发写会丢更新；stdio MCP 的工作目录安装时固定，不随 Agent 的 worktree。
- **TUI 清空会话会删掉整个状态目录**，数据根若与 Web 相同，Agent 的工作树会一起被删。

## 文档叙事

AGENTS.md 指向已不存在的文件系统目录、漏了 CodingBot；产品定位、项目架构方向的主旨与端口表、自举开发的流程仍按单 Agent 叙述；记忆定义成「系统提炼」，与「Agent 自己维护的笔记」冲突；验证地图没有协作功能的判据，还留着已删功能与旧的无障碍名称。

## 当场定下的决定

- **重启不停团队**：等外部事实的照常等，正在推进的继续，只有人明确暂停过的保持暂停；群级停止只打断当前这一串，不置暂停。当初一律暂停是为了避免重启后在人不知情时继续花钱，现在由硬上限与命令授权兜住。
- **同事 worktree 只读可见**：「同事改到一半先去看看」是并行开发的高频需求。
- **工作计划的去留交给记忆设计**，此前不扩展。

## 未验证

- 长时间线的实际开销：名册与源头计数遍历全部 Journal、每次决策全量重放、压缩快照随时间线增长，量级都是推断，留给 E 线的实测。
- 父 Worker 被消息拉起时是否一并恢复子任务。
- 委派进行中能否压缩。
