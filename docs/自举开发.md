# 自举开发

用 RED PANDA 开发 RED PANDA：一个稳定实例改源码，源码验证通过后再升级那个实例。

本文只讲这套拓扑怎么搭、怎么转。数据根布局见[产品配置](架构/运行/产品配置.md)，会话进程模型见[多活跃会话](架构/运行/多活跃会话.md)。

## 为什么必须是两份源码

不能让同一份源码目录同时"正在运行"和"正在被改"。三条硬约束，任意一条都足以否掉单实例原地迭代：

| 约束 | 后果 |
|---|---|
| Worker 是 spawn 出的子进程，启动时重新从磁盘 import | Host 跑旧代码、新会话的 Worker 跑新代码，同一实例内新旧混用 |
| Journal 是唯一执行事实源，每 Session 一个 SQLite | 两个进程指向同一个 `runtime_sessions/` 是在并发改写事实 |
| `web_chat.py --dev` 的 uvicorn reload 监听整个项目根 | 助手每写一个文件就重启自己，打断承载本次对话的进程 |

"复制一份源码"只隔离了代码。数据根默认是 `~/.redpanda`，两个实例仍然共享 `sessions`、`runtime_sessions`、`state`、`workspaces.json`、`mcp`、`skills`。要真正分开，代码和数据根都得分。

## 拓扑

| 角色 | 位置 | 数据根 | 端口 | 定位 |
|---|---|---|---|---|
| A 开发仓库 | 主 worktree | 默认 `~/.redpanda` | 8765 | 被改、被测，允许随时坏，平时不常驻 |
| B 稳定实例 | 次 worktree，detached 在已验证 commit | `REDPANDA_HOME` 指定 | 8766 | 日常干活的助手，工作区指向 A，只在验证通过后升级 |

角色不对称是这套东西成立的前提：B 是工具，不追新；A 是产品，允许坏。B 改得到 A 的源码，改不到自己那份。

## 搭建 B

worktree 与主仓库共享同一个对象库，所以 A 的提交在 B 里直接可见，不需要 fetch。

```powershell
git worktree add --detach ..\red-panda-agent HEAD
```

`node_modules/` 和 `web/dist/` 不在版本控制里，B 要自带一份构建产物：

```powershell
cd ..\red-panda-agent\web
npm install
npm run build
cd ..
```

B 第一次启动会在新数据根下生成带占位值的初始 `config.json` 并结束启动。把 A 的配置拷过去，或按[模型配置](模型配置.md)重填一遍：

```powershell
Copy-Item ~\.redpanda\config.json D:\work\helpMe\.redpanda-agent\config.json
```

启动 B。`--workspace` 显式把 A 的源码登记为 B 的工作区——Web 入口缺省不从进程 cwd 隐式登记：

```powershell
$env:REDPANDA_HOME = "D:\work\helpMe\.redpanda-agent"
python web_chat.py --port 8766 --workspace D:\work\helpMe\helperMe
```

B 不要加 `--dev`：reload 会监听项目根，而 `web/vite.config.ts` 的 proxy 写死指向 8765。

## 日常循环

大部分改动不需要起 A 实例。pytest 本来就在子进程里跑，B 可以直接在 A 目录执行，不与任何常驻进程冲突：

```powershell
python -m pytest
```

只有改到这几类东西时，才真需要临时起一个 A 实例冒烟：Host / Worker 装配、Journal 落盘格式、Channel 协议、前端交互。此时 A 用默认数据根和 8765，与 B 天然分开；开发前端时 A 才用 `--dev`。

## 升级 B

在 B 的 worktree 里切到已验证的 commit，然后重启 B。只有 `web/` 变过才需要重新构建前端。

```powershell
cd ..\red-panda-agent
git checkout <已验证的 commit>
```

存储格式发生不兼容变更时，B 的历史会话可能读不了。独立数据根让处置方式就是删掉 `REDPANDA_HOME` 指向的目录重来，不会连累主数据根里的真实使用历史。

## 测试环境隔离

B 派生出的 pytest 进程会继承 `REDPANDA_HOME`，污染所有走 `RedPandaHome.default()` 的测试。`tests/conftest.py` 有一个 autouse fixture 统一剥掉它，测试默认看到的是未覆盖的数据根；需要验证覆盖行为的测试自行设回去。
