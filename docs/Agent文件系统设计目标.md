# Agent 文件系统设计目标

> 面向 coding agent 的可审计、可回退文件系统。它是独立能力，可以与沙箱组合，也可以在外部沙箱内运行。
> 当前契约从[Agent 文件系统总览](架构/Agent文件系统/总览.md)进入；沙箱接入方向见[进程沙箱](架构/未开始/进程沙箱.md)。

## 要解决的问题

助手改错后能够撤销自己的文件变化，保留用户修改；修改后能够核对实际效果，收尾时能够审阅仍保留的成果。并行子任务需要独立文件视图，成果由父任务验收后显式合入。

这些能力围绕文件状态及其变化证据组织，不以进程、内存或网络隔离为前提。底层 VFS 提供存储、写时复制和挂载机制，Agent 文件系统在此之上拥有审计与回退语义。

## 必须保持的边界

回退依据助手操作的实际文件变化，保留未被助手改变的位置。用户后续值的处理必须有明确语义；内容相同不能替代文件身份判断。文件工具和命令产生的任务文件变化应遵守同一契约，不能因工具入口或 Git 忽略规则不同而遗漏。审计范围以受控文件视图和实际捕获的操作为准，不承诺记录系统中的全部文件活动。

工具报告失败或命令非零退出，不代表没有文件变化。未知异常、持久化损坏与未决执行必须暴露，不能猜测结果或自动重跑。回退本身也应留下实际变化证据，能够被撤销。

Runtime 保留命令执行事实；Agent 文件系统保留文件变化证据；Assistant 关联业务事实与文件操作，解释用户意图及历史引用。文件回退改变文件现状，不能抹去命令已经执行过的事实，也不替模型判断任务是否完成。

Sandbox 独立负责执行限制，可以通过外部模块接入，也可以由整个系统所在的外部环境提供。Agent 文件系统可以在其中运行，审计与回退契约不随沙箱的创建、重建或销毁改变。需要保留的成果、审计证据和恢复依据必须独立于临时执行环境保存；具体保留与清理由文件系统和产品规则定义。

可回退不构成放开权限的理由。挂载外文件写入、网络请求、安装与系统配置等副作用，不承诺通过文件回退撤销。文件工具的范围检查与沙箱的强制访问限制各自负责自己的边界。

## 演进约束

初始化与日常边界不应遍历整个任务树；局部修改的捕获与回退成本应主要随实际涉及的数据增长。性能结论依赖测量，不能仅凭采用 VFS 就认定低延迟。

优先验证审计证据、恢复行为与命令接合是否可靠。进程启动、取消与终止属于执行能力，文件视图和变化历史属于 Agent 文件系统；新增沙箱接入只处理实际需要的执行约束，不接管文件历史。

每次只推进能够独立解释和验证的能力，保持高内聚、低耦合。不预建未知沙箱适配框架或通用副作用回滚框架；替换已有设计时删除旧路径，不保留长期双轨。
