# 开发指南

运行 RED PANDA 见[快速开始](../README.md#快速开始)与[运行指南](运行指南.md)。本文只供需要修改源码或运行测试的开发者查阅。

## 开发环境由你选择

可以使用自己管理的 Python、Node.js、IDE 和虚拟环境，不要求使用准备脚本创建的 `redpanda-env`。在自己的环境中运行或测试项目时，满足 `.python-version`、`requirements.txt` 和 `web/package.json` 中的要求即可。

修改 Python 或前端代码可以复用匹配的沙箱运行包，不需要 Rust、LLVM 或 WinFsp SDK。只有修改或自行编译 `native/sandbox/`、`native/vfs/` 的原生组件时，才按[原生开发与构建说明](../native/sandbox/BUILD.md)准备相应工具。用户工作区内其他项目的工具链同样由用户自行管理。

下面的 `python`、`npm` 均指你自己选择的开发环境。在仓库根目录执行：

```sh
python -m pip install -r requirements.txt
npm --prefix web install
python web_chat.py --dev
```

该入口使用当前 Python 环境，支持后端和前端热重载。模型配置与独立数据目录见[运行指南](运行指南.md#其他入口与数据位置)。

## 测试

日常反馈以默认测试为主，真实进程测试单独运行：

```sh
python -m pytest                 # 架构契约与进程内语义
python -m pytest -m process      # 真实进程、shell 与 MCP 传输
python -m pytest --all           # 默认测试 + 进程测试
npm --prefix web test
npm --prefix web run build
```

沙箱进程测试需要对应平台的沙箱运行包与运行组件，跳过不表示通过。底层 Rust、挂载与崩溃测试见[VFS 测试说明](../native/vfs/docs/TESTING.md)。真实模型测试需要配置可用连接并显式设置 `REDPANDA_RUN_LIVE_TESTS=1`，随后运行 `python -m pytest tests/live`；这些测试会调用实际模型服务。

## 文件行为与开发边界

Sandbox 提供受控文件操作、操作历史、恢复及子任务成果交换，职责见[Sandbox 总览](架构/Sandbox/总览.md)。Python 入口在 `redpanda/sandbox/files/`，原生服务与底层库在 `native/sandbox/` 和 `native/vfs/`。

只读文件工具与声明 `read_only` 的命令查询已发布工作区。只读声明是调用契约，误标造成的写入不在回退范围。文件修改、可能写入的命令及恢复通过原生视图执行；挂载外写入、环境安装、系统配置和网络副作用不属于文件回退范围。子任务成果使用 Git 差异和三方合并，日常 Step 不创建 Git 快照。

历史实验与验证记录从[文档索引](README.md)查阅，不作为当前使用或构建步骤。

## CI

[CI 配置](../.github/workflows/ci.yml) 在推送到 `main`、更新目标为 `main` 的 PR 或手动触发时运行。Python 在 Linux 和 Windows 上运行日常测试；Web 运行测试和构建，构建包含类型检查。

可在 PR 的 Checks 或仓库 Actions 页面查看结果与失败日志。原生源码或分发脚本变化时，[Sandbox runtime 工作流](../.github/workflows/sandbox.yml) 在 Windows 与 Linux 上构建运行包，并验证不依赖 Rust 的安装和真实挂载。手动发布方式见[运行包发布](../native/sandbox/BUILD.md#发布运行包)。真实模型、完整业务流程与性能仍需另外验证。
