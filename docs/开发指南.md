# 开发指南

运行 konden 见[快速开始](../README.md#快速开始)与[运行指南](运行指南.md)。本文只供需要修改源码或运行测试的开发者查阅。

## 分支与 worktree

远程 `origin/main` 是唯一集成基准，本地 `main` 和主工作目录只负责同步。每项开发任务使用独立分支和 worktree，通过目标为 `main` 的 PR 交付，合入由人决定。这是本仓库的开发约定，不改变产品内 Agent 的分支行为。

在主工作目录同步主分支并创建任务工作区（将 `my-task` 换成任务名；下面的 Git 命令适用于 PowerShell 和常见 Unix shell）：

```sh
git switch main
git fetch origin
git pull --ff-only origin main
git worktree add -b codex/my-task ../konden-worktrees/my-task origin/main
cd ../konden-worktrees/my-task
```

客户端已提供独立 worktree 时直接使用它；确认任务分支从最新 `origin/main` 创建即可。同一任务继续使用原 worktree，新任务另建。后续的依赖安装、修改、运行、验证和提交均在任务目录进行；并行实例使用不同的数据目录和端口，不共用可写的运行状态。

验证后只暂存本任务文件，再提交、推送并创建 PR（需要已登录的 GitHub CLI）：

```sh
git add <本次修改的文件>
git commit -m "描述本次修改"
git push -u origin codex/my-task
gh pr create --base main --head codex/my-task --fill
```

任务需要同步主分支时，在任务目录执行 `git fetch origin`、`git merge origin/main`；解决冲突后重新验证并推送，不擅自强推改写已发布的历史。PR 合入后，再在主工作目录快进同步 `main`。确认任务 worktree 不再需要且没有待保留文件后，才用 `git worktree remove <任务目录>` 清理，不使用强制删除，也不清理其他任务。

仓库约定不能阻止远程直推。要强制所有人通过 PR 合入，需要在 GitHub 为 `main` 启用分支保护或规则集，限制绕过规则，并禁止强制推送和删除。

## 开发环境由你选择

可以使用自己管理的 Python、Node.js、IDE 和虚拟环境，不要求使用准备脚本创建的 `konden-env`。Python 版本见 `.python-version`；依赖安装使用 `requirements.lock` 和 `web/package-lock.json`。CI 验证使用 Node.js 24。

开发不需要原生编译工具链。用户工作区内其他项目的工具链由用户自行管理。

下面的 `python`、`npm` 均指你自己选择的开发环境。在仓库根目录执行：

```sh
python -m pip install --require-hashes -r requirements.lock
npm --prefix web ci
python web_chat.py --dev
```

该入口使用当前 Python 环境，支持后端和前端热重载。模型配置与独立数据目录见[运行指南](运行指南.md#其他入口与数据位置)。

## 测试

日常反馈以默认测试为主，真实进程测试单独运行：

```sh
python -m pytest                 # 架构契约与进程内语义
python -m pytest -m process      # 真实进程、shell 与 MCP 传输
python -m pytest --all           # 默认测试 + 进程测试
npm --prefix web test
npm --prefix web run build
```

平台限定的跳过不表示通过。真实模型测试需要配置可用连接并显式设置 `KONDEN_RUN_LIVE_TESTS=1`，随后运行 `python -m pytest tests/live`；这些测试会调用实际模型服务。

提交前使用与 CI 共用的入口：

```sh
python scripts/ci.py               # 当前源码的快速检查：default、Web 和 smoke
python scripts/ci.py --clean       # 已提交 HEAD 的快速检查：临时 checkout + 独立虚拟环境
python scripts/ci.py python        # 只验证 default（先跑 ruff 的 pyflakes 规则）
python scripts/ci.py web           # 只验证 Web
python scripts/ci.py smoke         # 启动、Worker、进程隔离与恢复的关键进程检查
python scripts/ci.py process       # 准备应用命令行工具后，验证完整 process 层
python scripts/ci.py python web process  # 当前平台的完整合入检查
```

无参数入口运行 default、Web 与 smoke，便于本地快速反馈；完整合入检查还须运行 process，不代表另一个平台也已通过。`--clean` 不含未提交修改，也不携带前端构建结果，支持上述目标和 process 的分组、worker 参数。process 按分组准备应用工具；integration 还准备 Chrome 与浏览器 MCP，首次运行需要下载；smoke 不安装这些工具。启动测试自行准备临时应用环境，不依赖个人 `konden-env`。

验证入口清除继承的 `KONDEN_*`、pytest 注入设置及 Python 路径覆盖，统一使用 UTF-8，并关闭第三方 pytest 插件自动加载；process 并行时显式加载锁定的 xdist。这样本机额外安装的插件不能改变测试是否可以收集、运行。日常 pytest 和显式 live 测试仍保留原来的使用方式。

`requirements.txt` 表达直接依赖范围，`requirements.lock` 锁定含平台条件的完整依赖与哈希。升级依赖时使用 uv 重新生成并提交锁文件，再运行验证：

```sh
uv pip compile requirements.txt --universal --python-version 3.13 --generate-hashes --upgrade --output-file requirements.lock
```

## 文件行为与开发边界

所有会话的文件工具与命令直接作用于任务根真实目录，不提供系统内的文件回退，见[执行环境](架构/能力/执行环境.md)。Python 入口在 `konden/filesystem/`（工作区登记、路径解析与文本读写）与 `konden/execution/`（命令与持续进程）。

历史实验与讨论记录从[文档索引](README.md)查阅，不作为当前使用或构建步骤。

## CI

合入检查由 [CI](../.github/workflows/ci.yml) 执行，触发范围是推送到 `main`、目标为 `main` 的 PR，或手动触发。同一 ref 上有新运行时，会取消旧运行。PR 与主分支执行相同的完整检查，纯文档改动也不例外。

完整进程测试与 Python、Web 检查一起纳入 `CI` 汇总，任何一项失败、取消或跳过都不能得到成功的合入检查。进程测试保留失败状态和报告，没有自动重试、`continue-on-error` 或合入后才执行的附加必需验证。

所有 job 都调用 `scripts/ci.py`，与本地共用入口、锁文件和测试命令。具体矩阵、worker 数及 smoke 选择以代码为准；完整 process 已包含 smoke 用例，不再重复执行。

### 流程

```text
CI
  Python（各支持平台）   ruff + default
  Web                      前端测试 + 类型检查 + 生产构建
  Process（各支持平台 × 语义分组）
                         → CI（全部通过才成功）
```

测试分层（见[架构总览](架构/总览.md#测试分层)）在 CI 里的对应关系：

| 层 | CI 中的位置 |
|---|---|
| default | Python job，在各支持平台运行 |
| process | Process job，在各支持平台按语义分组运行完整场景 |
| live | 不进 CI |

GitHub 分支保护应要求 `CI` 汇总通过，并要求 PR 跟上最新主分支。workflow 文件不会自动配置远程门禁，修改时应核对实际分支保护。

### 关键取舍

- **合并前后验证范围一致。** 完整进程场景属于合入门禁，本地 smoke 仅提供快速反馈。普通契约不因已有完整 Host 场景而重复搬入进程层。
- **完整进程检查保留真实并发。** process 仍按 `tests/conftest.py` 中的语义分组执行，用 pytest-xdist 的 `worksteal` 并行，不以降低并发掩盖竞态。未匹配专门分组的用例进入 `integration`。
- **Windows 进程检查使用 runner 临时盘。** 保留 `TEMP`/`TMP` 指向 `RUNNER_TEMP` 的现有设置；测试不能依赖临时目录前缀长度。
- **测试报告。** Python 和进程检查上传 junit 报告，保留耗时和平台限定的跳过原因；启动环境缺失不作为跳过理由。Web 结果看日志。

### 偶发失败

偶发失败要查根因，不靠重跑掩盖，也不把超时调大或给单个组降并发。并发下出现的失败先按可能的产品缺陷排查。

先说明失败对应哪条产品行为，再判断应该修生产逻辑、简化测试替身、下移测试层次，还是删除重复覆盖。对于有价值的竞态回归，显式安排关键先后顺序，让错误实现稳定失败；重复通过不能证明问题消失。长期保留的测试必须有独立保护价值，不能只因为曾经写过就继续维护。

只在 runner 上出现的问题，可以在临时分支上修改 workflow，用 `workflow_dispatch` 手动触发，把单个用例在多台 runner 上循环运行，同时记录分阶段时间戳，再对比修改前后的耗时分布。查完后删除临时分支，原始日志留在本地 `.tools/`，不放进文档目录。

### 不做

- 不运行真实模型（live）、完整业务流程和性能基准，这些需要另外验证。
- 不为单个 process 组单独调整 worker 数或超时。
