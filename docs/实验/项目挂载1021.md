# 项目挂载实测（2026-10-21）

本篇保留「Bot 任务根留在个人目录、项目工作树作为挂载」这一取舍前的关键对照，不作为现行规则。现行设计见 [Coding Bot · 项目归属与执行目录](../架构/CodingBot/总览.md#项目归属与执行目录)。

## 问题与条件

当时关联项目的 Bot 把任务根切换为自己的 worktree，并写进系统提示。要支持对话中途挂载和一位 Bot 挂多个项目，任务根就不能跟着项目走。风险在于：任务根留在个人目录时，Bot 会不会用相对路径把代码写进个人目录，而不是写进项目工作树。

每组在隔离数据根中新建一位关联小项目的 Bot，使用本机 deepseek-flash 配置，经 Web 接口驱动并开启自动放行。小项目含一个已知 bug 和测试。连续两轮：

1. 修 bug、跑测试、提交并落地。
2. 新增一个函数和测试，提交并落地，再在个人目录写一条笔记。

对照组为当时的 main（任务根就是 worktree）。实验组任务根留在个人目录，worktree 作为额外的可写目录，挂载提示告诉模型工作树路径、写文件用其下的路径、命令设 cwd。每组两次。

## 关键对照

| 指标 | 对照 1 | 对照 2 | 挂载 1 | 挂载 2 |
|---|---|---|---|---|
| 两轮都正确落地到集成分支 | 是 | 是 | 是 | 是 |
| 代码写进个人目录 | 3 个临时脚本 | 0 | 0 | 0 |
| 工作树留下未提交文件 | 无 | `__pycache__/` | 无 | 无 |
| 笔记写在个人目录 | 是 | 是 | 是 | 是 |
| git、pytest 命令未设 cwd | 9 | 7 | 0 | 0 |
| 未成功的工具调用 | 0 | 0 | 0 | 0 |

## 结论与限制

挂载组两次运行里，代码文件全部用工作树下的路径修改，命令全部把 cwd 设为工作树，笔记正确落在个人目录；没有出现担心的写错目录。在这些样本中，任务根不动的做法至少不比切换任务根差。

只测了 deepseek-flash、一个很小的项目、每组两次。当时只挂一个项目且在创建时关联，挂载提示出现在对话开头；挂多个项目、中途挂载时提示出现在长历史之后，未在本轮测到。驱动脚本和完整记录留在本机，未归档。

## 追加：多项目与中途挂载

落地后用同一配置测了一位不关联项目的 Bot，连续四轮：用户让它挂上已登记的 ledger 并修 bug；给一个未登记仓库的路径让它挂上并改 README；用户在 Web 上替它挂上 tools，再让它同时改 tools 和 ledger；最后让它解除 notes 并在个人目录写笔记。每轮等上一轮回复后再发。

最初两次暴露两个问题：模型不知道 ledger 已登记，去文件系统里搜路径；模型在同一步里同时调用两次挂载，或把解除和写笔记放在一起，而这两个工具当时被要求单独调用，违反时整轮运行失败。挂载说明改为先按项目名挂、找不到时结果列出已登记的名字；挂载与解除不再要求单独调用，解除在同一步有写入抢先导致 Git 拒绝移除时如实返回没有解除。

修改后两次运行四轮全部正确：三个项目的集成分支各得到正确的提交，解除后 notes 的工作树已移除，个人目录根下只有笔记，没有失败的工具调用。命令有的用 cwd 参数、有的先 cd 到工作树，效果相同。只测了 deepseek-flash，每组两次。
