# 命令环境分离实验

2026-10-07，在 Windows 本机验证产品环境与工作区命令环境的分离，以及模型对用户环境指令的延续。现行设计意图见[执行环境](../架构/Sandbox/执行环境.md)，这里仅记录实验与证据。

产品继续使用专用 Python 与产品进程环境。启动时先取得独立的命令环境，再补全产品环境；命令环境作为进程参数经 Host、Worker 与工具装配传入 Shell 执行器，不写入个人配置或会话日志。工作区保留启动 PATH 与项目变量，产品 CLI 管理继续刷新安装路径。

用户通过普通消息指定、修改或取消环境。助手提示词要求在每次命令中落实，Compact 保留要求与已验证执行方式，不增加环境配置表、设置工具或语言探测。

## 真实模型实验

使用 `deepseek/deepseek-v4-pro` 与真实 Host / Worker / Shell / Compact。实验创建两个位于工作区之外的 Python 虚拟环境，各自具有不同的探针依赖；产品 Python 中没有该依赖。通过修改产品环境中的 PATH 与标记，模拟产品环境调整，不修改命令执行或模型输出。

| 阶段 | 输入与独立验收 | 结果 |
| --- | --- | --- |
| 默认环境 | 启动 PATH 指向 launch-env；产品 PATH 随后加入自己的 Python；模型执行裸 `python probe.py launch.json` | 使用 launch-env，加载 launch 依赖；环境标记仍为 launch |
| 用户指定 | 用户要求本会话后续使用 selected-env，模型自行表达命令 | 使用 selected-env，加载 selected 依赖 |
| 上下文交接后 | 触发一次真实 Compact，随后仅要求再次执行，不重复环境信息 | 仍使用 selected-env 与 selected 依赖 |

产品环境标记保持 product，三次命令的启动标记均保持 launch；探针源码未修改。虚拟环境选择由命令表达，不形成隐式环境状态。

环境、独立结果、调用轨迹、回复和 Journal 均写入被忽略的 `tests/.live_workspace/`，没有复制个人凭据。此次原始证据在 `tests/.live_workspace/command-environment-20261006-200544/`；目录时间戳使用 UTC。实验结束后已删除一次性实验脚本，仓库保留本记录与守住执行边界的回归测试。

## 契约与回归

真实跨 Worker 测试验证：产品环境随后改变，命令仍保留启动 PATH、Conda 前缀与 Java 环境变量；命令执行不改写产品变量。Windows 工作区策略不读取注册表 PATH，产品管理策略继续刷新。Bash 注入环境与后续产品变化的分离在进程边界单测中验证。

本机 PowerShell 7 会在启动时给 PATH 增加自己的目录，独立启动也可复现；跨进程验收检查原始项目路径与顺序完整保留，执行器单测另行检查传入的 PATH 未被替换。

默认回归：690 passed、2 skipped、136 subtests passed；另有一个已存在的失败：`tests/llm/test_codec.py::LlmCodecTest::test_foreign_errors_preserve_type_name_and_traceback`，期望 ProviderBoom，但 Python 3.13 的 traceback 呈现 APIError。这次不修改该无关行为。

相关进程回归：65 passed、6 skipped。覆盖实际 Shell、Worker 启停、上下文交接与 CLI 管理；本次有一条 pytest 的 BytesIO BufferError 未捕获异常警告，测试结果通过，尚未定位该警告来源。`git diff --check` 通过。

这次实测证明所测模型能在环境变更和一次上下文交接后遵守要求，不构成模型永不偏离的保证。没有实测真实 Conda 激活、Java 构建或 POSIX Shell；它们的具体初始化由模型明确表达，执行器没有环境管理器适配分支。当前仍是本机执行，不提供操作系统级隔离。
