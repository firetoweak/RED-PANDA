# 内容回读实验（2026-10-10）

实验笔记，不作为长期默认值的依据。设计意图见[上下文投影](../架构/上下文/上下文投影.md)和 [Compact](../架构/上下文/Compact.md)。

## 要验证的流程

从模型实际任务出发：知道原文可以回读，定位需要的内容，取得足够证据，然后回答。分别观察已有关键词、只知道文档主题，以及交接后已没有原文引用的情况。

本次实现将正文读取统一为 `read_content`：省略关键词连续读，有关键词就返回命中附近原文；片段位置可用于扩读。没有引用时先用 `find_history` 定位历史消息，再读取返回的引用。历史检索产生的引用固定当次原文，不随后续消息改变。已读片段被省略后保留原引用及范围，避免为了回读上一页再生成一层引用。

模型可见说明只表达可读内容、参数单位、使用限制和下一步动作。交接提示不再附带内部来源结构；存储分块对模型透明。

## 方法与范围

基线固定为提交 `713aeb8d81aeb77c866b7cf72ad0cc9f94ea756b`，实验脚本加载该提交的投影与读取逻辑，与工作区实现比较。模型使用本机配置的 `deepseek/deepseek-flash`。每个场景、每个版本各跑一次，没有进行多模型或重复采样。

真实模型请求接入项目的消息投影和工具处理函数。普通场景模拟刚取得检索结果；交接场景通过实际窗口切换去掉早期消息，再要求核对证据。模型后续工具循环由实验脚本驱动，不是完整生产 Runtime 的端到端性能测试。

资料为合成的配置检索结果或运行文档。目标位于原文约 60% 处，保留文件路径和行号。答案必须同时满足：数值正确、来源文件正确、行号正确、目标证据确实出现在模型可见消息或工具返回中。仅在回答中猜中数值不算成功。

| 场景 | 原文字符数 | 目标 |
| --- | ---: | --- |
| medium | 18,686 | 处于新旧外置阈值之间，核对已知配置项 |
| known | 58,126 | 已有明确关键词，定位配置项 |
| browse | 58,098 | 只有文档主题，从目录寻找相关章节 |
| compact | 58,126 | 交接后仅知道检索过，需要找回历史证据 |

本次试验参数：外置阈值从 16,000 改为 32,000 字符，预览从 1,200 改为 2,000；原 `read_artifact` 每次最多 3,000 字符，新正文读取默认 12,000、最多 32,000。底层按 8,192 个 Unicode 字符分块，读取位置与模型工具的字符单位一致。

## 观察结果

调用次数只统计本轮查证的工具调用，不包括先前获取资料的调用。输入 token 为所有模型请求的累计值，包含重复传入的上下文；返回字符数为工具结果 JSON 的累计字符数。

| 场景 | 基线调用 → 当前调用 | 基线累计输入 → 当前累计输入 token | 基线正确 → 当前正确 |
| --- | ---: | ---: | --- |
| medium | 7 → 2 | 45,165 → 22,347 | 是 → 是 |
| known | 8 → 1 | 36,022 → 4,165 | 否 → 是 |
| browse | 12 → 3 | 69,673 → 8,681 | 是 → 是 |
| compact | 12 → 6 | 59,931 → 20,051 | 否 → 是 |

| 场景 | 基线返回 → 当前返回字符数 | 基线耗时 → 当前耗时（秒） |
| --- | ---: | ---: |
| medium | 20,818 → 2,614 | 7.33 → 4.16 |
| known | 23,377 → 1,534 | 8.80 → 2.33 |
| browse | 29,589 → 5,399 | 27.31 → 3.10 |
| compact | 24,128 → 39,538 | 19.46 → 4.59 |

已知关键词场景可一次拿到目标证据；未知命名仍能沿文档线索定位。交接场景取得证据需要更多步骤，而且当前成功过程返回的总字符多于基线失败过程，不能宣称每种情况下都节省返回量。

medium 的当前结果完整保留在上下文中，但模型仍调用了 `find_history` 和 `read_content`。这说明降低外置频率不能保证模型直接使用长上下文中的证据；增加可定位能力仍有价值。这次样本不足以判断阈值和分页大小是否最优。

早期探索样本曾把目标插在一行中间，模型质疑资料格式，已排除该轮结果。上表只使用修正为完整行之后的样本。

原始请求、工具返回、模型回答和汇总保存在本机忽略目录：

- `tests/.live_workspace/content-reading-20261010-v2/`：known、browse、compact。
- `tests/.live_workspace/content-reading-20261010-medium/`：medium。


## 小范围磁盘读取

同一份 5,800,000 字符的 ASCII 原文，先完成保存，再在靠近末尾的不同位置读取 20 页，每页 12,000 字符，检查结果相同。计时和 `tracemalloc` 只覆盖读取阶段。

| 实现 | 20 页读取耗时（秒） | Python 分配峰值（字节） |
| --- | ---: | ---: |
| 基线整份 JSON 加载后切片 | 0.2945 | 17,722,954 |
| 当前按块读取 | 0.0532 | 47,293 |

该结果只说明本次小范围读取避免了整份正文分配；不代表进程 RSS、冷缓存性能、写入速度或关键词搜索耗时。原始汇总在 `content-reading-20261010-v2/performance.json`。

## 边界与验证

单元验证覆盖字面关键词跨块匹配、Unicode 字符坐标、续查与扩读、正文总量上限、原工具提示保留、回读片段省略后保留原引用、损坏数据原样暴露，以及固定历史引用和交接读取范围。

日常测试通过 728 项，跳过 7 项，另有 119 项默认未选中的测试。独立运行 Compact 进程组曾出现 9 项通过、1 项在 Windows 临时目录清理时因 `journal.sqlite` 占用失败；失败项在不同运行间变化，并伴随仍运行进程被关闭的异常。此处记录为尚未解决的进程收尾问题，未据此修改生产进程生命周期，也不算全部验证通过。

另外单独启用进程测试标记，验证交接中的历史检索接正文回读、冻结前缀的附件读取，两项均通过；附件用例出现一次 `BytesIO` 析构的 `BufferError` 警告，不能据此推断整个进程组已经稳定。

存储格式改为 SQLite 分块，未保留旧 JSON 文件读取路径，也未迁移现有数据。因此旧持久化引用不能直接由新实现回读；本次未修改用户已有会话数据。真正启用新实现时需明确这项不兼容边界。

回读只覆盖工具实际返回的原文；上游工具已经截断或省略的内容无法恢复。本次未引入自动语义摘要、语义检索或后台替模型决定哪些片段重要。
