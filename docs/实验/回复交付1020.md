# 回复交付实验（2026-10-20）

本篇保留当时强制使用 `message_user` 回答人的关键对照，不作为现行规则。后续已改为普通回复直接给人看，决定与代价见 [Coding Bot · 交互与响应](../架构/CodingBot/交互与响应.md#普通回复给人协作消息显式发送)。

## 问题与条件

当时给人的回答必须调用 `message_user`，结尾文字只显示为折叠的工作记录。真实应用验证中，deepseek-flash 在人的 16 次直接提问里仅 3 次调用了它；明确要求调用时 3/3 会用。没调用的 Agent 往往在之后的问答中延续纯文字作答。

本地复现使用真实 Host、隔离数据根、临时项目与本机 deepseek-flash 配置。每组新建四个长期 Agent，依次提问，统计是否调用回答工具。对照说明分别提醒「回答人必须用工具」及「刚才的纯文字人没有看到」。

## 关键对照

| 场景 | 当时的处理 | 调用回答工具的次数 |
|---|---|---|
| 直接问四个问题，无引导 | 原规则 | 12/16；另一轮 16/16 |
| 先要求只回复 PING_OK，再问四个问题 | 原规则 | 9/20、10/20 |
| 同上 | 追加两条可观察行为说明 | 20/20、20/20 |
| 先积累五轮纯文字回答，再问四个新问题 | 说明放在 system 角色 | 8/16；原先不用的仍不用 |
| 同一批 Agent 继续 | 说明改放 user 角色 | 12/16；仍有一个完全不用 |

## 结论与限制

在这些样本中，说明能改善冷启动，却不能稳定纠正已积累的纯文字回答习惯。模型曾在未调用回答工具时声称问题已经答过，表明它可能将自己的普通回复当成人已看到的回答。这支持检查协议形态与实际可见性是否一致，不能据此归因于所有模型或推断发生频率。

只测了 deepseek-flash 和人直接提问，每组样本小、波动明显；同事私信、群或例行任务开始的工作是否正确汇报未测。追加说明的试验改动未合入，一次性脚本留在本机。这些数据不证明后续普通回复方案已经通过验证；现行验证范围以代码、测试及验证地图为准。
